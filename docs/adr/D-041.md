# D-041: GI-only holds do not block the gates of a non-GI batch

**Date:** 2026-10-31  
**Status:** Accepted (Architect-Gate ruling 2026-10-31b §2 on P03 review P3-4; implemented by B16 and P04)

## Context

B09's grading-approval, final-packing and publish gates refuse on every active hold flag returned by
`run_gate_checks`, whatever `batches.gi_label_requested` says (`hold_reasons`). The pilot raises holds with two codes
only: `plot_outside_gi_region` (plot) and `yield_over_ceiling` above the hold margin (lot). Both sources say what
these holds are for: FR29 "a batch with any out-of-boundary component lot is blocked from being labeled/published as
GI-certified (it can still be traced as a normal, non-GI batch)"; FR68 / Dataflow Stage 7 "more than 30 % above:
held out of the GI-labelled batch until reviewed". P03's non-GI switch lets the admin tick such lots, and B09 then
locks them in a batch that can never be published.

## Decision

1. `GI_ONLY_HOLD_CODES = {plot_outside_gi_region, yield_over_ceiling}` beside `hold_reasons` in
   `lots_batches/service.py`. In a batch with `gi_label_requested = false`, holds with these codes do not block
   approve grading, final packing or publish. They stay open flags, and each approval row records them in
   `blocked_reasons` as approved-over, next to the warns.
2. Every other hold code, today's batch/reading/event holds and any future one, still blocks every batch (fail
   closed: a new hold blocks until someone adds it to the list on purpose).
3. A GI-requested batch is unchanged: every hold blocks (the admin asked for the badge, and FR70 wants a review).
4. A non-GI batch skips the GI re-check, as `_gi_check` already does: `gi_verified = false`, no
   `gi_block_reasons`, no badge on the page.

## Advantages

- FR29's "can still be traced as a normal, non-GI batch" becomes possible; P03's switch tells the truth.
- The hold is not lost: it stays open and is recorded on each approval.
- Fail-closed for holds nobody has classified.

## Compromises

- A hard-coded list of two codes; a new GI-only hold rule must be added to it (a unit test ties the list to the
  rule modules' `CODES`).
- A `yield_over_ceiling` lot (possible over-declaration) can reach a public non-GI page while its review is
  still open; the quantity warnings stay visible to the admin, and the page makes no GI claim.

## Revisit when

- Holds get a per-rule "scope" (GI vs commercial) in the rule bundle: move the list there.

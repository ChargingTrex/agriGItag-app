# D-019: GI region derived from open administrative boundaries with recorded provenance

**Date:** 2026-10-29  
**Status:** Accepted

## Context

The GI Registry publishes boundaries only as prose and map drawings (Application 883, Certificate 693, GI Journal 200).

## Decision

**Amendment 2026-10-29 (after B03).** The Datameet / Census-2011 sub-district file named below does not exist for Tamil Nadu taluks (Datameet has Census-2011 districts only and its village layer skips Tamil Nadu; the open Census-2011 taluk files found are non-commercial or restricted). Source is now **geoBoundaries** ADM3 (taluks) and ADM2 (district) for India, ODbL-1.0, LGD-derived, pinned to commit 9469f09 in `infra/scripts/gi_boundary/README.md`. ODbL requires attribution on the public map and share-alike for the derived boundary database: the derived `gi_region_v*.geojson` files are published under ODbL with attribution in the file properties and on the public page's map link. GADM stays a non-commercial cross-check only.


Region v0 = Virudhunagar district outline; v1 = dissolved union of the taluks named in the journal, built by `infra/scripts/gi_boundary/build_virudhunagar.py` from the Datameet / Census 2011 sub-district layer (open licence). GADM 4.1 only as a cross-check because its licence forbids commercial use. Every version stores `source_ref`, `licence`, `confidence: district_derived`, `taluks[]`.

## Advantages

- Reproducible and legally usable
- Close to the legal definition
- Replaceable by an official file without schema change

## Compromises
- ODbL share-alike applies to the derived region polygons (acceptable: they are meant to be public) and attribution text must appear wherever the boundary is shown

- Taluk boundaries changed after 2011
- The taluk list must be confirmed from the journal (TODO)
- Still an approximation, so the tolerance buffer and near-edge review stay on

## Revisit when

When an official or surveyed boundary file is obtained.

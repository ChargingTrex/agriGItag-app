# D-029: The offline outbox is per user on a shared phone

**Date:** 2026-10-31  
**Status:** Accepted (M06 review P2-4)

## Context

Farmer phones are often shared within a family (User Flows §Who uses what). B02's session model refuses a sign-in on a device that is active for another user (`device_in_use`), so the first user must sign out. Sign-out must not delete unsent entries (CLAUDE.md §6: nothing a farmer records is lost), but it must not let the next user's session send them either.

## Decision

Every outbox row and entry carries the user id that created it. Sign-out keeps the rows. The sync engine (M02) sends only rows belonging to the signed-in user; the cloud indicator counts only that user's rows. When the earlier user signs in again on the same phone, their waiting rows resume. Rows older than 30 days with no owner sign-in are surfaced to the field officer, never deleted silently.

## Advantages

- No data loss on shared phones
- No entry is ever sent under the wrong identity (the server also checks `entered_by` from the token)
- Simple rule to test: filter by user id

## Compromises

- Stranded rows can sit on a phone indefinitely if the owner never returns; the officer-facing reminder handles the pilot case
- One more column on Outbox/Entries (M02 schema v2)

## Revisit when

- If the pilot shows many stranded rows, add an officer "send on behalf" path with assist-mode attribution

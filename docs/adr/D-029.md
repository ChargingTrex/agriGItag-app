# D-029: The offline outbox is per user on a shared phone

**Date:** 2026-10-31  
**Status:** Accepted (M06 review P2-4)

## Context

Farmer phones are often shared within a family (User Flows §Who uses what). B02's session model refuses a sign-in on a device that is active for another user (`device_in_use`), so the first user must sign out. Sign-out must not delete unsent entries (CLAUDE.md §6: nothing a farmer records is lost), but it must not let the next user's session send them either.

## Decision

Every outbox row and entry carries the user id that created it. Sign-out keeps the rows. The sync engine (M02) sends only rows belonging to the signed-in user; the cloud indicator counts only that user's rows. When the earlier user signs in again on the same phone, their waiting rows resume. Rows older than 30 days with no owner sign-in are surfaced to the field officer, never deleted silently. On a user switch (M13) the phone also forgets the pull cursor, the reference bundles and the previous user's pulled lots, plots, tasks and flags, and the new user's pull refills their own. It keeps a lot or plot that an unconfirmed entry names, a lot the phone made `ready_for_sale` while its packing stands (no pull gives that state back), and the farmers M09 registered offline.

## Advantages

- No data loss on shared phones
- No entry is ever sent under the wrong identity (the server also checks `entered_by` from the token)
- Simple rule to test: filter by user id

## Compromises

- Stranded rows can sit on a phone indefinitely if the owner never returns; the officer-facing reminder handles the pilot case
- One more column on Outbox/Entries (M02 schema v2)
- The rows kept on a user switch (lots and plots named by the previous user's unsent entries, and their ready lots) stay visible to the next user in Log, Sell, Money and the home task card until those screens are scoped by farmer; the previous user's local drying reminders are gone when they sign in again (TODO.md)

## Revisit when

- If the pilot shows many stranded rows, add an officer "send on behalf" path with assist-mode attribution

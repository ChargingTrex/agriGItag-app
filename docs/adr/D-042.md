# D-042: Per-entry assist context applies only to entries about one farmer's records

**Date:** 2026-10-31  
**Status:** Accepted (Architect-Gate ruling 2026-10-31b §3 on B15 review P3-1; implemented by B16)

## Context

D-032 lets each sync entry carry `assist_session_id`. B15 checks the session's farmer against the entry's farmer for
consent, plot and lot event versions. For `quality_reading`, `flag_resolution`, batch event versions and
`assist_session` entries, the session's farmer is written as `on_behalf_of_farmer_id` with no link to the record:
an officer resolving a flag on farmer B's lot while carrying a session for A gets an audit row "on behalf of A".
M10 puts the session id on every entry made while assisting, so a blanket rejection would turn good offline
entries into rejections.

## Decision

| Entry | `assist_session_id` |
|---|---|
| `consent`, `plot`, lot `event_version` | must be the entry's farmer, else `forbidden` (B15, unchanged) |
| `quality_reading` on a lot | must be the lot's farmer, else `forbidden` (new, in `quality.service.create_reading`) |
| `quality_reading` on a batch, batch `event_version` | `forbidden` (new): a batch belongs to many farmers |
| `farmer`, `flag_resolution`, `assist_session`, `lot_intake` | ignored: no session lookup, no assist fields (the officer's own task, as D-031 does for `farmer`) |

The two new `forbidden` checks sit in shared code (`create_reading`, `events._check_subject`), so the
`X-Assist-Session` header path gets them too.

## Advantages

- Audit rows never name a farmer the record does not belong to (CLAUDE.md §6 stays true, not just present).
- Field officers' drying-end readings taken while assisting are recorded on behalf of the right farmer.
- M10's rule "every assisted entry carries the session" causes no rejections for kinds that cannot be assisted.

## Compromises

- Silent ignore on four kinds: a phone bug that attaches the wrong session there goes unnoticed (low harm: the
  field only adds attribution).
- The REST `POST /v1/flags/{id}/resolve` with `X-Assist-Session` still records the header's farmer; no client
  sends that header there.

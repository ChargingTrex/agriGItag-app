# D-014: One Entries/event_versions table with typed JSON payloads, on phone and server

**Date:** 2026-10-29  
**Status:** Accepted

## Context

Eleven event types with per-crop schemas, all needing the same sync, undo, audit and evidence path.

## Decision

A single append-only table with `event_type` and a JSON payload validated by per-type Pydantic schemas (discriminated union in OpenAPI) and generated Dart models.

## Advantages

- One sync, undo, correction and audit path
- Per-crop schema changes rarely need migrations

## Compromises

- Weaker column-level typing on payload fields
- JSONB indexes needed for payload queries

## Revisit when

If a payload field becomes a hot query key (promote it to a column).

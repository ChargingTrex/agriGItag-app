# D-009: Celery on Redis for background jobs

**Date:** 2026-10-29  
**Status:** Accepted

## Context

Page builds, photo verification, rule checks and notifications must run off the request path.

## Decision

**Amendment 2026-10-31 (B04).** Tasks obtain a fresh NullPool engine per task run via `worker.run_db_task` and dispose it afterwards; `task_acks_late` and `task_reject_on_worker_lost` are on; there is no result backend; a logging filter masks task args/kwargs in Celery's received and failure records so OTP codes never reach logs.


Celery 5 with Redis broker. Tasks call the async service layer via `asyncio.run` with a fresh engine per worker process.

## Advantages

- Most widely used Python job system; documentation and hiring familiarity

## Compromises

- Heavier than ARQ or Dramatiq
- Event-loop care needed when mixing with async SQLAlchemy

## Revisit when

If job volume or async friction suggests ARQ.

# D-045: Public page W03: schematic SVG map with ~1 km dots, print-only QR from builder URLs, unavailable page as a static file

**Date:** 2026-10-31  
**Status:** Accepted (W03)

## Context

W03 adds a map thumbnail, OG tags, a print stylesheet and an "unavailable" page to the static public page
(D-007). Four choices were open:

1. The map. Map tiles or an embedded map mean a third-party request, a tile licence and a pin a buyer can zoom
   into. The record has no region outline; the real GI 883 outline (D-019, geoBoundaries, ODbL) is built by
   hand and is not in the repo or in the record.
2. The QR and the page URL. OG needs an absolute `og:url` and `og:image`; print needs the QR and the link. The
   record had neither. B10 knows `PUBLIC_BASE_URL` and writes `batches/<code>/qr.png`; the CDN rewrite of
   `/b/<code>` is still a TODO, so the renderer cannot derive the QR's address.
3. Print. A hidden `<img loading="lazy">` is still fetched by Chrome on screen (measured with headless Chrome),
   and the W02 Robot keyword treats every `<img>` as an evidence photo.
4. A page for codes with no live page: not yet published, withdrawn, unknown.

## Decision

1. **Inline SVG of a shipped, schematic district silhouette** (`agritrace_page/assets/district_outline.json`,
   17 points at 2 dp, CC0, hand-drawn from town positions and labelled "schematic" on the page). The renderer
   projects it onto a 120-unit grid (about 1.1 km per unit) and draws one whole-unit dot per distinct lot
   village from the 3 dp `map_point`. Lots outside the box get no dot.
2. **The builder sends `public_url` and `qr_url`** (optional, additive schema fields; `qr_url` may not contain
   quotes, brackets or a backslash). `og:url` = `public_url`; `og:image` = `qr_url`; `og:title` = crop names +
   GI number + batch code; `og:description` is a fixed bilingual label. No OG text comes from a lot.
3. **The QR is a print-only CSS background** (`print-color-adjust: exact`), so the screen view does not
   download it. A `beforeprint` handler opens every `<details>` timeline; print CSS keeps one photo per event,
   prints black on white and keeps lot cards whole.
4. **`render_unavailable(code, reason)`** returns a `noindex` page with no batch data. The builder writes it to
   `batches/<code>/index.html` for unpublished or withdrawn batches; ops build the generic CDN 404 page with
   `python -m agritrace_page unavailable unknown <dir>`.
5. The page default is `lang="en"`, because the untagged text is English-language data (codes, places, notes);
   every Tamil string is in a `lang="ta"` element and is shown first.

## Consequences

- ADV: no third-party request, tile licence or zoomable pin; the dot is coarser than the map link, so it
  cannot become a plot pin or boundary (CLAUDE.md §6). OG previews carry no farmer name, village or number.
  The screen view stays one request. A scanned code always lands on a readable page.
- COMPROMISE: the silhouette is schematic, not the GI 883 area, until the record carries a simplified official
  outline (then with the ODbL attribution). Until B10 sends `public_url`/`qr_url`, published pages have no
  `og:url`, `og:image`, printed QR or printed link. Browsers print the QR only if it loads during print
  layout (checked in headless Chrome only). A Tamil-script farmer name or village is tagged `en` until the
  builder sends a language per value.

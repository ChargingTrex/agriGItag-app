# D-054: the outbox is strict FIFO, and a missing-dependency rejection is retried once

**Date:** 2026-11-01  
**Status:** Accepted (WP-M14, audit waves 3–6 finding 1)

## Context

The server processes push entries in order and needs a farmer before its consent and plot, an assist session before
the entries captured in it, and version 1 of an event before its undo or correction (D-031, D-032, D-005). After a
failed push every row drew its own jittered backoff and `OutboxDao.nextBatch` sent only the rows that were due, so a
later row could go first, alone. The server rejected it (`not_found`, `assist_session_invalid`) and the phone parked
it as `needs_attention` for good.

## Decision

1. `OutboxDao.nextBatch` walks the owner's `waiting` and `sending` entry rows in `seq` order and stops at the first
   row that is `sending` or not yet due: a row in backoff, or still in flight in another isolate or left `sending` by
   a kill (until `resetStaleSending`), holds back every later row. `needs_attention` rows never block.
2. `_failed` draws one backoff for the whole failed batch (same 2-4-8 s jittered policy, 5 min cap, `Retry-After`).
3. A per-entry rejection with `not_found` or `assist_session_invalid` is retried once, like `stale_version` (D-005).
   A second rejection with the same code, and every other code, goes to `needs_attention`.

## Advantages

- No schema change and no dependency graph on the phone: queue order is creation order, which is dependency order.
- An older row still `sending` (other isolate, killed app) also holds the queue; the retry-once covers a dependency
  the server answered late. As a side benefit the two isolates stop pushing the same rows in parallel.

## Compromises

- One row in backoff delays every later row of that user until it is due: up to 5 min per attempt; an entry that
  fails with 5xx every time holds that user's queue until the server is fixed.
- After a kill mid-push, later rows wait until the next run after the 5 min `resetStaleSending` (save, resume,
  network change or the 15 min job).
- A dependency that is truly missing (another FPO's lot, a farmer the server rejected) waits one backoff longer
  before an officer sees it.
- Rows already parked as `needs_attention` by the old behaviour are not revived.

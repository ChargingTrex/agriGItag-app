# D-008: LocalStack locally as the S3 stand-in with versioning and object lock (amended 2026-10-29; originally MinIO)

**Date:** 2026-10-29  
**Status:** Accepted (amended)

## Context

Production uses S3 with Object Lock; local development needs the same API.

## Decision

**Amendment 2026-10-29.** MinIO Community Edition is archived and its Docker images were removed from Docker Hub and Quay in September 2026 (verified: `docker manifest inspect minio/minio` fails). Community forks are unverified builds. The stand-in is now **LocalStack** pinned to **`localstack/localstack:4.14.0`** (the last 4.x community release, 2026-02-26, Apache-2.0; `latest` from the 2026.x line requires an auth token and a LocalStack account, which every developer and CI runner would need). The pin is frozen on purpose: S3 on port 4566 with versioning, object lock and presigned URLs; buckets created by `infra/scripts/s3-init.sh`. The API reaches it at `S3_ENDPOINT`; phones and browsers use `S3_PUBLIC_ENDPOINT` for presigned URLs. Production remains real S3 with Object Lock.

Original text follows.


docker-compose runs MinIO; `minio-init.sh` creates `evidence` (versioning + object lock, governance mode, short retention in dev), `public-pages` and `id-docs` buckets.

## Advantages
- LocalStack emulates the AWS API surface the production code uses (same boto3 calls), so local tests exercise the real S3 semantics
- Permissive licence and an official, maintained image

- Same API locally and in production
- Immutability is testable on a laptop

## Compromises
- LocalStack's image is large (about 1 GB) and slower to start than MinIO was
- Object-lock behaviour in an emulator is still not AWS; production needs an infra review

- Object-lock semantics differ slightly from AWS
- Production still needs an infra review

## Revisit when
- If LocalStack 4.14.0 does not enforce signed headers or object lock under test (the B00 Verifier checks this), switch to SeaweedFS (Apache-2.0, S3 API with versioning and object lock); RustFS is the weaker option (1.0 only since 2026-09, recent object-lock CVE).
- Review the frozen pin each season: a frozen emulator drifts from AWS behaviour.

If local tests never exercise object lock, a lighter stand-in may do.

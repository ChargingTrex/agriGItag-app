# D-053: M13 release config: no deferred imports, Flutter's default shrinking, free space through a 3-line channel

**Date:** 2026-10-31  
**Status:** Accepted (WP-M13)

## Context

PLAN §13 D1 asks for a download under 30 MB (AAB per-ABI splits, resource shrinking, on-demand voice packs) with a
100 MB hard ceiling. §13 D2 asks for a cold start under 3 s on a 2 GB phone and names "deferred imports for the
officer/QC features". PLAN §7.2 M13 also asks for a "Phone is full" check below 100 MB free.

Facts checked in this repo and in the Flutter 3.38 tool:

- The Flutter Gradle plugin (`FlutterPlugin.kt`) already turns on `isMinifyEnabled` (R8) and `isShrinkResources` for
  release unless the build passes `--no-shrink`. Plugins ship their own consumer ProGuard rules. An Android App Bundle
  splits by ABI, density and language by default.
- Flutter puts a deferred Dart library in its own `.so` only when `deferred-components` is set in pubspec.yaml and the
  app uses Play Feature Delivery. Without that, every library is compiled into `libapp.so` and `loadLibrary()` returns
  at once. Dart AOT runs no library initialisers at start-up (top-level variables are lazy), so an imported but unused
  screen costs no start-up time.
- No package in pubspec.yaml reports free disk space.

## Decision

1. No Gradle size changes. Rely on Flutter's default R8 + resource shrinking and the AAB's default splits. A comment
   in `android/app/build.gradle.kts` says where they come from. `tool/size_check.sh` (M00) stays the CI gate: fail
   above 100 MiB, warn above 40 MiB, AAB per-device download checked against 30 MiB when bundletool is on PATH.
2. No `deferred as` imports in `app_router.dart`. The officer and QC screens stay plain imports. The cold start is
   checked on the Go AVD instead (Q01: `flutter run --profile --trace-startup`, `timeToFirstFrameMicros` < 3 000 000).
3. Free space comes from a method channel in `MainActivity.kt` (`StatFs(filesDir).availableBytes`). No plugin is
   added. The Dart side (`lib/core/capture/free_space.dart`) treats "no answer" as "unknown" and skips the check.

## Advantages

- Nothing is added to the build that it already does. The size number in the M13 report describes the shipped
  config.
- The router keeps synchronous routes. Async `loadLibrary()` would add a frame of delay to every officer and QC route
  and touch every widget test that opens one, for no gain without deferred components.
- No new dependency or LIBRARIES.md row for a value the platform gives in one call.

## Compromises

- PLAN §13 D2's wording ("deferred imports") is not followed to the letter. If the Go AVD trace shows a cold start of
  3 s or more, the fix is Play deferred components (a feature module per role) plus a lighter first frame. That
  changes how the app ships through Play, so it gets its own decision.
- iOS has no free-space handler yet, so the low-storage check never fires there (TODO.md). The pilot phones are
  Android (D-002).
- R8 runs with the plugins' own consumer rules only. A plugin with incomplete rules would fail at run time in
  release, not at build time. The Q01 release smoke run on the Go AVD covers this (camera, scanner, audio,
  WorkManager, notifications).

## Revisit

When the Go AVD cold start is 3 s or more, when the AAB per-device download is over 30 MiB, or when an iOS pilot
starts.

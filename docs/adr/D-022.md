# D-022: Portal and API served from one origin

**Date:** 2026-10-29  
**Status:** Accepted

## Context

The FPO admin portal (React) calls the API under `/v1`. P00's Vite config proxies `/v1` to the API in development and assumed the same origin in production; the review noted this choice had been filed under D-020 (API versioning), which is a different decision.

## Decision

In every environment the portal and the API are reachable on the same origin: the portal is served at `/` and the API at `/v1` behind one reverse proxy (Vite dev proxy locally, the ALB/CloudFront path routing in production). Browser auth therefore needs no CORS allowance, and B02 may issue an httpOnly, same-site refresh cookie for the web client instead of the sessionStorage shortcut.

## Advantages

- No CORS configuration or preflight cost
- Cookies can be httpOnly and same-site, closing the XSS token-theft path
- One TLS certificate and one hostname for operators and auditors

## Compromises

- Path-based routing must be configured in production infra (documented in infra/README.md when the deploy WP lands)
- Partner API consumers still use their own hostnames and credentials (out of pilot scope)

## Revisit when

- If the portal is ever hosted by a third party on another domain

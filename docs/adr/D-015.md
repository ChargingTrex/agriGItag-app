# D-015: Standards Profiles as versioned JSON interpreted by one generic grade engine

**Date:** 2026-10-29  
**Status:** Accepted

## Context

Grades must be computed from readings against a published standard, per crop, editable by the compliance team.

## Decision

`standards_profile_versions.rules` JSON lists parameters, limits per grade, plausibility ranges, source caps and lot gates. The engine assigns each parameter the best grade it meets and the batch the worst of those; visual readings cannot earn the top grade.

## Advantages

- Compliance edits without deployments
- Same JSON drives the phone preview
- One engine for AGMARK, ISO and custom profiles

## Compromises

- Non-tabular standards (coffee defect charts, tea sensory grades) need engine extensions
- Seed values marked `load_from_standard` must be replaced before go-live

## Revisit when

When a second grading scheme does not fit the parameter/limit model.

# D-026: Drift stores dates as ISO-8601 text with millisecond precision

**Date:** 2026-10-30  
**Status:** Accepted

## Context

Drift's default stores `DateTime` as whole seconds since the epoch. The sync metrics (plan §13 F1) measure save-to-acknowledgement in a "Sent ≤ 5 s" target, and the three clocks on every entry are compared with server timestamps; one-second resolution is too coarse and loses the timezone offset.

## Decision

`apps/mobile/build.yaml` configures Drift to store dates as ISO-8601 text with milliseconds (`store_date_time_values_as_text: true`). Drift compares such columns through `julianday()`.

## Advantages

- Millisecond precision for sync latency and clock-skew detection
- Offset preserved; readable in any SQLite tool

## Compromises

- Comparisons go through `julianday()`, slightly slower than integer compares (negligible at phone scale)
- Text is larger than an integer (a few bytes per timestamp)

## Revisit when

- If the on-device database grows past what a 2 GB phone handles comfortably (unlikely in the pilot)

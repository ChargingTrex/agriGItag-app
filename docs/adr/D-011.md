# D-011: Single presigned PUT for photos, no resumable upload in the pilot

**Date:** 2026-10-29  
**Status:** Accepted

## Context

Photos are compressed to about 300 KB on the phone.

## Decision

The API returns a presigned PUT URL per photo; the phone uploads directly with a SHA-256 header and retries the whole PUT on failure. The worker verifies checksum and EXIF afterwards.

Amended 2026-11-01 (B18, audit waves 3-6 #4): the PUT is now also signed with the declared `Content-Length` (at most 2 MiB), so storage refuses a body of any other size.

## Advantages

- API never proxies bytes
- Simple client logic
- Object lock + versioning give the immutable trail

## Compromises

- A dropped upload restarts the whole 300 KB
- The architecture doc's resumable-upload promise is deferred (TODO)

## Revisit when

If photo size grows or field failure rates show restarts hurt.

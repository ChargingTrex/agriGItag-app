# D-004: Modular monolith: one Python package, two containers (api, worker)

**Date:** 2026-10-29  
**Status:** Accepted

## Context

The architecture doc asks for a modular monolith a small team can run.

## Decision

One package `agritrace` with modules identity, registry, events, rules_flags, lots_batches, quality, storage_monitoring (stub), publishing, notifications, partner_api (stub), reporting. Module boundaries enforced by import-linter: a module may import another's `models.py` and the `service.py` names listed in `__all__`; never its router, schemas or tasks. Cross-module async work goes through task-name constants in `core/task_names.py`.

## Advantages

- Easy to run and debug
- Modules can be split out later without changing callers

## Compromises

- Boundaries are enforced by lint, not by process isolation
- A broken import contract is caught in CI, not at runtime

## Revisit when

When one module needs independent scaling or a separate team.

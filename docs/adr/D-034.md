# D-034: Public page publishing: allow-list precedence, WebP-only photo copies, cache policy, Pillow labels

**Date:** 2026-10-31  
**Status:** Accepted (B10)

## Context

B10 builds the static public batch page (D-007) from the database through W01's `PublicBatchRecord`
schema and `agritrace_page.render`. Four choices were not fixed by earlier decisions:

1. B13's field YAML marks some fields `partner` that the W01 schema requires on the page (`plot.declared_area`
   as farm area, `quality_reading` values in the grade block), and many optional page fields (farm quantities,
   inputs, seed varieties) are `partner` or `public` per tenant.
2. Evidence photos live in the private, object-locked `evidence` bucket. Presigned links (B07) expire after
   an hour; a page printed on a pack lives for a year. The original JPEG keeps the phone's exact EXIF GPS (M04).
3. Plan §13 E3 asks for long cache headers on assets and a CDN invalidation on publish.
4. The module map names `reportlab` for labels; Pillow is already installed (B06).

## Decision

1. **W01's schema is the page allow-list; tenant YAML can only hide what the schema makes optional.** Fields the
   PRD fixes on the page (farm area, lot quantity and share, village-level place, farming type, grade readings)
   are always sent. Optional fields (event quantities, input, seed variety, farmer name, farmer GI number,
   irrigation source) are sent only when `fieldconfig.public_fields(entity, fpo_code)` lists them. A required
   field that is empty fails the build as `public_record_invalid` with its path.
2. **Photos: only the WebP variants, copied into public-pages under a content-addressed name.** The build task
   copies `thumb` and `medium` to `public-pages/batches/<code>/evidence/<sha256[:16]>.<thumb|medium>.webp`
   (server-side S3 copy). The page never carries the raw evidence key (FPO and event ids) or the original JPEG;
   the schema's `jpeg_url` fallback points at the medium WebP.
3. **Cache policy.** `index.html` and `data.json`: `public, max-age=60`. Photo copies and `qr.png` (a pure
   function of the batch code): `public, max-age=31536000, immutable`. When `CLOUDFRONT_DISTRIBUTION_ID` is set,
   each build calls `CreateInvalidation` for `/b/<code>*`; locally it is unset and nothing is called.
   The bucket is versioned (D-008), so each rebuild adds object versions and the old build stays retrievable.
4. **Labels are drawn with Pillow and saved as PDF** (A4, 2 × 4 labels: QR, product, batch code, net kg, pack
   and best-before dates, FSSAI number), not with reportlab.

## Consequences

- ADV: the page keeps the PRD §12.1 shape for every tenant; no exact location leaves through photo EXIF; page
  links never expire; a rebuild reaches phones within 60 s even without a CDN; no new library for labels.
- COMPROMISE: a tenant cannot hide farm area or grade readings without a schema change; photo copies are
  re-written (new versions, same bytes) on every rebuild; browsers without WebP show no photo; the label is a
  raster PDF with the default font, so no Tamil text on it yet (TODO.md, B10).

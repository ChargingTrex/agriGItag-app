# D-044: Assist mode is a route scope over the farmer screens, guarded by the running session, with one app-level assist bar

**Date:** 2026-10-31  
**Status:** Accepted (M10)

## Context

UserFlows §Field officer flows: in assist mode "the screen switches to that farmer's home screen, with a coloured bar
across the top reading 'Logging for: [farmer name]' so it is never confused with the officer's own account", and the
officer logs "exactly as the farmer would". PLAN §7.2 M10: "assist bar on every screen". CLAUDE.md §6: assist mode is
recorded on every entry it creates. The M07 farmer screens hard-code `/home` and `/log` paths, which only the farmer
role may open (D-013), and D-032 makes every assisted entry carry the session id from the phone.

## Decision

1. The farmer home, its sub-screens and the event flow are mounted a second time under `/assist/:farmerId` (the same
   route builders, `homeRoutes()` / `logRoute()` in `app_router.dart`). M07 screens navigate through
   `farmerPath(ref, '/log/...')`, which adds the `/assist/<id>` prefix while an officer assists.
2. A route redirect on `/assist/:farmerId` lets the officer in only while `assistProvider` holds a session for that
   farmer; otherwise (typed URL, app restart) it goes to `/officer`. So no entry can be made under the scope
   without assist mode, and every entry made there gets `assistMode`, `assist_session_id` and `enteredRemotely`.
3. The assist bar is drawn once, in `MaterialApp.builder` above the navigator, whenever a session runs. It sits over
   every screen, sheet and dialog, including ones later work packages add, without per-screen code.
4. Back on the assisted farmer's home, or "End assist", ends the session (best-effort `POST /assist/end`, D-032) and
   returns to `/officer`.

## Advantages

- No second copy of the M07 screens. The farmer UI the officer sees is the farmer's UI.
- The "bar on every screen" acceptance holds by construction, not by discipline.
- The guard ties the `/assist` scope to a real session, so the CLAUDE.md §6 invariant cannot be bypassed by navigation.

## Compromises

- M07 screens depend on `farmerPath` (one call per navigation) and must keep using it.
- Routes exist twice in the tree (go_router needs one route object per place). `_parent()` redirects keep them
  path-agnostic.
- The session is in memory. An app restart drops assist mode on the phone and leaves the server session open
  (allowed by D-032).
- The bar takes the status-bar inset from the screens below it. Screens under the bar see no top padding.

## Revisit when

- Officers need assist mode to survive an app restart: persist the session in SyncState and restore it in
  `AssistNotifier.build`.

# D-052: The portal e2e chain plays the QC phone and runs in two modes (MSW in CI, the B12 seed live)

**Date:** 2026-10-31  
**Status:** Accepted (P07)

## Context

P07's acceptance chain is "login → approve → review flag → create batch → approve → publish → labels, green
< 10 min, twice without reseed" plus "0 serious axe violations". Grading approval needs a grade, and the
grade comes from the QC officer's readings on the phone: the portal has no screen for it. CI has no compose
stack (Docker is not used by the `portal` job), and the B12 seed batches every received lot into the
reference batch, so a live run cannot create a new batch.

## Decision

1. **Mock mode (default, CI):** Playwright starts `npm run dev:mock`. The MSW state is exposed to the page as
   `agritraceMock` (src/mocks/browser.ts, dev mock bundle only); before creating the batch the chain swaps
   `grades` for a map that grades any existing batch "Special", standing in for the QC phone (installed first
   because the portal caches a "never graded" answer for its 30 s staleTime). Every run opens a fresh page, so MSW starts from
   its seed: the second run needs no reseed.
2. **Live mode (`E2E_LIVE=1`, after `make up && make seed`):** Playwright starts `npm run dev` (proxy `/v1` to
   the api). The chain signs in as the seeded admin with the dev OTP (`OTP_DEV_CODE`), uploads a farmer with
   a new name and approves them, clears one more open flag, opens Ready lots (no creation: nothing is left
   to batch), and walks the reference batch `FGP8T4033HM7`. The QC grading is posted over the API as the
   seeded QC officer (moisture meter + one reading, grade "Standard", as B12's fixes path). Gates already
   passed are recognised from the page and skipped, so a second run without reseeding is green.
3. **axe:** axe-core (already a dev dependency) is injected from node_modules with `page.addScriptTag`; no
   `@axe-core/playwright` wrapper. Serious and critical violations fail (soft, so every screen is reported);
   moderate and minor are printed.

## Consequences

- **ADV:** one portal-only spec covers the whole admin chain in CI on every PR without Docker or a phone
  emulator, and the same spec runs on the seeded stack for the Verifier.
- **COMPROMISE:** the grading step itself is not driven through a UI here (mobile M-WPs and B12's e2e cover
  it); the mock exposes a test hook in the dev mock bundle; live mode does not create a batch (B12's e2e
  covers `create_batch` on the stack) and changes the demo data (one farmer and one cleared flag per run).

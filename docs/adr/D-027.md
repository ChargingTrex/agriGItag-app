# D-027: Tokens live in the platform keystore, not in SQLite

**Date:** 2026-10-30  
**Status:** Accepted

## Context

mobile-design.md §2 placed access and refresh tokens in the Drift `Session` table. Farmer phones are often shared within a family (User Flows §Who uses what), and a plain SQLite file is readable by anyone with a backup or a rooted device. B02's session model (D-024) rotates refresh tokens and revokes a device on reuse, which only helps if the token itself is hard to copy.

## Decision

Access, refresh and pin tokens are stored with `flutter_secure_storage` (iOS Keychain, Android Keystore-backed EncryptedSharedPreferences). The Drift `Session` row keeps only non-secret state (user id, role, FPO, device id, locale, preferences, pin_set).

## Advantages

- Tokens never sit in a plain file on a shared phone
- Reinstalling the app drops the tokens, which is the desired behaviour (sign in again with OTP)
- Drift schema and backups contain no secrets

## Compromises

- One more plugin and two platform-specific storage behaviours to test
- Secure storage is slower than SQLite (microseconds; irrelevant here) and unavailable in unit tests without a fake

## Revisit when

- If the platform plugin proves unreliable on Android Go devices (fallback: encrypted SQLite column with a Keystore-held key)

# D-050: The portal learns the public page origin from `VITE_PUBLIC_BASE_URL`; the preview iframe is sandboxed and reads the dev proxy in development

**Date:** 2026-10-31  
**Status:** Accepted (WP-P04)

## Context

After publishing, the batch page must show the public URL `/b/<code>`, the QR image and a preview of the page
(plan §7.3 P04, FR15, FR63). The API knows the public origin as `PUBLIC_BASE_URL` (B10: the QR encodes
`{PUBLIC_BASE_URL}/b/<code>`) but no endpoint returns it. Locally `/b/<code>` does not resolve: it needs the CDN rewrite to
`batches/<code>/index.html`, so B10 added the dev proxy `GET /v1/public/batches/{code}` (404 in production). The page is
static HTML with inline CSS and no script (W01).

## Decision

1. The portal reads the public origin from the build-time variable `VITE_PUBLIC_BASE_URL`; unset, it uses its own origin
   (`window.location.origin`). The URL shown is `{origin}/b/<code>`.
2. The preview iframe points at `/v1/public/batches/<code>` in development (`import.meta.env.DEV`; the Vite proxy forwards
   `/v1`, D-022) and at the public URL in production builds.
3. The iframe carries `sandbox=""` (no scripts, forms, popups or same-origin access) and a title; a new build number
   remounts it.
4. The QR PNG and the labels PDF need the bearer token, so they are fetched with the API client (QR as a `data:` URL,
   labels as a download through an object URL), never linked.

## Advantages

- No contract change; the preview works locally without a CDN.
- The sandbox costs nothing (the page has no script) and keeps a compromised page from touching the portal.

## Compromises

- `VITE_PUBLIC_BASE_URL` must match the API's `PUBLIC_BASE_URL` per environment; a mismatch shows a URL the QR does not
  encode. Upgrade: a `public_url` field on `BatchOut` or `PublishOut`.
- Production must allow framing the public origin (CSP `frame-src`) when it differs from the portal's.

## Alternatives rejected

- Hard-coding the public origin: breaks per environment.
- Linking `qr.png` / `labels.pdf` directly: the browser would send no bearer token (D-024 keeps it in memory).

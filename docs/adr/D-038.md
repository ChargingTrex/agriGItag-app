# D-038: Public scans are a body-less POST, rate-limited per IP with a fixed one-minute window in Valkey

**Date:** 2026-10-31  
**Status:** Accepted (B11)

## Context

`POST /v1/public/scans` is called without sign-in by the static public batch page (D-007), served from
the `public-pages` bucket / CDN, which is a different origin from the API (D-022). FR20 wants scan
counts; CLAUDE.md §6 forbids personal data on public paths. The acceptance line is "100 scans/min → 429".
`scan_events` has `batch_code`, `scanned_at`, `approx_location` and `user_agent_hash`; it has no IP column.

## Decision

1. The batch code travels as the query parameter `batch_code`; the request has no body. A static page can
   then call it with `navigator.sendBeacon(url)` (a "simple" cross-origin request: no CORS preflight and no
   CORS configuration on the API). Codes must be 12 Crockford base32 characters
   (`core.ids.CROCKFORD`, any case; else 422), stored upper-case. Codes no batch has are still counted, but
   only 10 per minute per address (a second budget `ratelimit:unknown:...`), so junk rows stay bounded
   (B11-r1 P3-3).
2. Stored per scan: batch code, server time, SHA-256 of the `User-Agent` header. The IP address is never
   stored; `approx_location` stays null (no GeoIP).
3. Rate limit: Valkey key `ratelimit:scans:<first 16 hex of SHA-256(ip)>:<unix minute>`, `INCR`, `EXPIRE 60`
   on the first hit; the 101st hit in a window → 429 `rate_limited` with `details.retry_after_s` (as the OTP
   limit, conventions.md). The window number is part of the key, so a missed `EXPIRE` can never block an
   address beyond its minute. No library: a few lines on redis-py, already a dependency.
4. Valkey unreachable → the scan is answered 204 and not stored (no limiter, no unbounded writes); one
   warning per process (B11-r1 P3-2).

## Advantages

- Works from any static page without CORS work; no personal data at rest.
- One Valkey round trip pair per scan; no new dependency.

## Compromises

- A fixed window allows up to 200 hits across a window boundary; acceptable for analytics counting.
- Scans during a Valkey outage are lost.
- The IP hash in Valkey is unsalted (an IPv4 hash can be brute-forced) but lives 60 s and never reaches the
  database.
- Behind the load balancer set `FORWARDED_ALLOW_IPS=<load balancer subnet>` (uvicorn ≥ 0.32 already trusts
  proxy headers from the allowed IPs; never `*`, a spoofed X-Forwarded-For would bypass the limit), or every scan
  shares the balancer's address and the limit becomes global (TODO.md).
- A query parameter on a POST is unusual; the OpenAPI description says why.

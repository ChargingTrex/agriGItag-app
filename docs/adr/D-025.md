# D-025: BM-03 "3G" means Lighthouse's built-in 3G preset

**Date:** 2026-10-30  
**Status:** Accepted

## Context

The plan's benchmark BM-03 says the public page must reach performance ≥ 0.90 and LCP ≤ 2 s "on simulated 3G". Lighthouse has no "Slow 3G" preset. With Chrome DevTools' Slow 3G numbers (400 ms RTT, 400 kbit/s) a 1 KB page containing one heading measures a median LCP of about 2006 ms on the reference laptop, so the 2 s limit would fail regardless of page content.

## Decision

BM-03 is measured with Lighthouse's built-in 3G preset (300 ms RTT, 700 kbit/s, simulated throttling, median of 3 runs) as configured in `apps/public-page/lighthouserc.3g.yml`; BM-16 uses the normal-4G profile from `qa/robot/profiles.yaml` (60 ms, 10 Mbit/s) with LCP ≤ 2.5 s. Thresholds: performance ≥ 0.90, total bytes ≤ 500 KB, LCP ≤ 2000 ms (3G) / ≤ 2500 ms (4G).

## Advantages

- A reproducible, documented preset instead of a vendor UI label
- The target still represents a weak rural connection and the page passes it with margin (LCP ≈ 1.6 s)

## Compromises

- A field "slow 3G" (400 kbit/s) link will load slower than the benchmark shows; the User Flows doc targets 4G as primary, so this is accepted
- Lighthouse scores vary by ±0.08 on slow machines; CI may need a retry rule

## Revisit when

- When field measurements from the pilot area are available (replace the profile numbers in `qa/robot/profiles.yaml`)

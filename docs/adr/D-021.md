# D-021: Valkey instead of Redis for the broker and cache

**Date:** 2026-10-29  
**Status:** Accepted

## Context

The plan and architecture doc name Redis for Celery's broker and caching. Redis images from 7.4 onward are
licensed RSAL/SSPL (not OSI open source); Redis 8 added AGPL. The project requires widely used, permissively
licensed open-source components (D-018 spirit), and production targets AWS ElastiCache, which now recommends
its Valkey offering.

## Decision

Run `valkey/valkey:8-alpine` locally and ElastiCache for Valkey in production. Keep the `REDIS_URL` setting
name, the `redis` Python client and Celery's redis transport, because Valkey speaks the same protocol.

## Advantages

- BSD-3 licence, Linux Foundation governance, widely deployed (AWS, Google, Oracle back it)
- Drop-in: no code or client change
- Matches the production managed service

## Compromises

- Younger project than Redis; Redis-only modules (RedisJSON, Search) are unavailable, which the pilot does not use
- Documentation and tutorials still say "Redis"; the variable name keeps that word on purpose

## Revisit when

- If a Redis-only module becomes necessary, or if Valkey diverges from the protocol the client expects

# D-001: Python/FastAPI backend instead of NestJS

**Date:** 2026-10-29  
**Status:** Accepted

## Context

The architecture document specified Node.js/NestJS. During planning the user chose Python.

## Decision

Backend is Python 3.12 with FastAPI, Pydantic v2, SQLAlchemy 2 (async), Alembic, GeoAlchemy2 and Celery on Redis. OpenAPI 3.1 is generated from the Pydantic models.

## Advantages

- User's preferred stack
- Pydantic models give a fully described OpenAPI document for free
- Largest hiring pool in India for backend work
- GeoAlchemy2 and shapely are mature for PostGIS work

## Compromises

- The portal no longer shares a language with the API; mitigated by the generated TypeScript client
- The architecture document must be read with this substitution in mind

## Revisit when

If the team becomes TypeScript-only, or if async SQLAlchemy + GeoAlchemy2 friction outweighs the benefits.

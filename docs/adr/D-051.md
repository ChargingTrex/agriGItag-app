# D-051: Portal CSV exports are written in the browser with a BOM and a formula guard; a lot's packed kg is the batch's packed kg × its share %

**Date:** 2026-10-31  
**Status:** Accepted (WP-P05)

## Context

P05 adds CSV downloads to the FPO admin portal (plan §7.3 P05, FR21, FR58): the batch's lots and shares, and the
dashboard farmer table. The audit trail CSV already comes from the API (B11 `GET /v1/batches/{id}/audit-export.csv`,
formula guard in `reporting.service.csv_cell`). The other two hold only data the portal has already loaded
(`BatchOut.shares`, `LotOut.code`, farmer names, `FarmerRow`), so no new route is needed. Farmer and village names are
often Tamil; Excel opens a UTF-8 CSV without a BOM as the system code page and shows garbage. The API stores packing
per batch (`BatchOut.packed`), not per lot, but the lots CSV must show packed kg per lot.

## Decision

1. The portal writes these CSVs itself (`features/exports/exportModel.ts`, ~15 lines, no library): RFC 4180 quoting,
   CRLF line ends, a UTF-8 BOM at the start.
2. Every cell starting with `=`, `+`, `-`, `@`, tab or CR gets a `'` prefix, the same rule as B11 `csv_cell`.
3. Every quantity is two columns, value and unit (`received`, `received_unit`), FR58.
4. A lot's packed kg is `batch packed kg × share % ÷ 100`, rounded to the gram (`packed_share`).
5. The farmers CSV writes only an allow-list of `FarmerRow` columns (the dashboard's), whatever else a row holds, so a
   phone, survey number or coordinate cannot reach the file (CLAUDE.md §6).

## Advantages

- Excel opens Tamil names correctly on a double-click; a malicious name stays text.
- No new route, no library, no server load for data the page already holds.
- The packed share answers "how much of the packed output came from this farmer" (FR60) without a schema change.

## Compromises

- The CSV rules exist twice (B11 Python, portal TypeScript); both are pinned by tests on all six triggers.
- A cell that really starts with `-` gains a `'` (none today: exported quantities are not negative).
- The packed share is derived, not recorded; share rounding can make the column sum differ from the packed kg by a few
  grams. Upgrade: per-lot packed kg from the API if packing is ever recorded per lot.

## Alternatives rejected

- papaparse or another CSV library: a dependency for 15 lines (Ponytail; D-047 made the same call for reading).
- New `lots.csv` / `farmers.csv` API routes: more contract and server code for data the portal already has.
- Leaving packed kg out of the lots CSV: the plan asks for it.

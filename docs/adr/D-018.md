# D-018: Library-first implementation with a dependency ledger

**Date:** 2026-10-29  
**Status:** Accepted

## Context

The user wants widely used open-source libraries used wherever they simplify the code, and documentation of which files use which library and why.

## Decision

**Amendment 2026-10-29.** MPL-2.0 is accepted for dependencies used unmodified as build-time tools or transitive runtime dependencies (examples: `lightningcss` in the Vite build, `certifi` and `pathspec` in the Python toolchain); MPL's file-level copyleft does not reach our code when the files are unmodified. MPL-2.0 libraries we would modify or vendor remain rejected. LGPL stays rejected for linked libraries (asyncpg and pg8000 are used instead of psycopg).


Workers prefer a mainstream library over new code. `docs/LIBRARIES.md` records library, version, licence, files that use it, purpose, why this one, alternative rejected. `infra/scripts/libraries-check.py` fails CI if a manifest dependency is missing from the ledger.

## Advantages

- Less code to maintain
- Documentation and hiring familiarity
- Future developers can see the why

## Compromises
- Rejecting LGPL rules out some good libraries (psycopg 3 is LGPL; the backend uses asyncpg, the QA layer pg8000)

- Larger supply-chain surface
- Licence review needed; copyleft or non-commercial licences rejected

## Revisit when

Never; keep the ledger.

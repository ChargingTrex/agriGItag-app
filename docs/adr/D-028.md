# D-028: OTP auto-read uses Android's SMS User Consent prompt, not the silent SMS Retriever

**Date:** 2026-10-31  
**Status:** Accepted (M06)

## Context

The User Flows doc says the app reads the sign-in code from the SMS so the farmer never types it. Android offers two APIs: the SMS Retriever (silent, but the SMS text must contain the app's signing hash, which B04's OTP template does not carry and which differs per build) and the SMS User Consent API (one "Allow" tap on a system prompt, no hash requirement). iOS has no comparable API; its autofill needs a system-keyboard text field, which the farmer rules forbid.

## Decision

Android: SMS User Consent prompt; the code auto-fills after the farmer taps "Allow"; typing on the keypad remains available. iOS: no auto-read; the farmer types the six digits on the large keypad. Pilot devices are Android.

## Advantages

- Works with any OTP template and any build signature
- One tap instead of six, and the prompt is a familiar system dialog
- No hash management per flavour

## Compromises

- One extra tap compared with the silent Retriever
- iOS farmers type the code

## Revisit when

- If a silent read is required, add the signing hash to the OTP template per flavour (B04) and switch to the Retriever

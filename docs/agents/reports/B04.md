## What was done

- **`notifications.send`** (`modules/notifications/tasks.py`) is registered under `task_names.NOTIFICATIONS_SEND`.
  It takes the B02 kwargs (`user_id`, `template_key`, `channel`, `lang`, `payload`) and calls `service.deliver`
  through `worker.run_db_task`.
- **`service.deliver`** reads the recipient (and so the phone) from `users`. It inserts a `queued` row and
  commits, renders the template in `lang` (English fallback), and calls the provider. It then commits `sent`
  (`provider_ref`, `sent_at`) or `failed`.
  - An unknown template, a missing variable or a provider refusal gives a `failed` row with
    `provider_ref = error:<reason>` and raises nothing.
  - An unknown user writes no row (the foreign key forbids one) and returns None.
  - The stored payload is redacted (`{"code": "***"}`). The console log line is rendered from the redacted
    payload, and the phone number is never logged.
- **Providers** (`providers.py`), with no SDK:
  - `SmsProvider` protocol;
  - `ConsoleProvider` (logs the redacted text, returns `console`);
  - `UnconfiguredProvider` (`TODO(provider)`, raises `ProviderRefused("provider_not_configured")`);
  - `select_provider`: `console` → console; `sms` → console only when `SMS_PROVIDER=console`; everything
    else → unconfigured.

  New settings `SMS_PROVIDER` and `SMS_SENDER_ID` are in `core/config.py` and `.env.example`, and compose
  `x-app-env` sets `SMS_PROVIDER: console`. With no code default, production fails closed: an SMS is never
  shown as `sent` when nothing was sent.
- **Templates** (`templates.py`) cover `otp`, `harvest_reminder`, `sale_received`, `grade_given`,
  `payment_made` and `flag_raised` (officer). Each has a `when` doc string (recipient, trigger, variables)
  and one en and one ta sentence with one action. Rendering is `str.format`. A mobile key convention
  (`notif` + the camelCased key) is noted in the header; the app has no such keys yet.
- **`GET /v1/notifications`** returns the caller's own rows, newest first, with keyset cursor
  (`id < cursor`, UUIDv7) and `limit` 1–200. The lean `NotificationOut` has id, template_key, channel, lang,
  payload (redacted), status and created_at. It returns 401 without a token. Every field has a description.
- **Celery hardening** (`worker/__init__.py`, two `DECISION D-009` blocks with ADV/COMPROMISE):
  - `task_acks_late=True` and `task_reject_on_worker_lost=True`;
  - no result backend and no `result_extended`;
  - `MaskTaskArguments`, a logging filter on `celery.app.trace` and `celery.worker.strategy`. It replaces
    `args`/`kwargs` with `<masked>` in the context mapping, which is also the `data` extra that JSON
    formatters print;
  - `run_db_task`: `asyncio.run` with a NullPool engine built and disposed per call. It works in the worker
    and in a test thread;
  - the existing `worker_process_init` cache reset is kept.
- **Tests:**
  - unit `test_notifications_templates.py` (10): ta/en, fallback, KeyError cases, redaction, every template
    documented;
  - unit `test_notifications_service.py` (7): provider selection; the OTP row `sent/console` with the code
    absent from the row and logs; unknown template → `failed` without raising; missing variable; the
    unconfigured SMS; an unknown user; the eager `tasks.send.apply` → `sent/console` row plus the
    acks_late / reject / no result_extended config; a raising task whose Celery failure record has
    `args`/`kwargs` masked;
  - integration `test_notifications.py` (5): both acceptance lines literally; OTP end to end
    (`POST /v1/auth/otp/request` → eager task → row `otp/sms/sent`, payload `***`); list paging and
    isolation; 401.
- `core/errors.py`: whitespace only (`ruff format`). This format failure was already on `decdcad` and stopped
  `make lint`.
- Tracking: CHANGELOG has one line. TODO now has 4 items ticked (the B02 contract, B02-r1 P3-11, the B00

<!-- Purpose: worker report for WP-B11. Serves: checkpoint-protocol step 2. Readers: BE Reviewer, Verifier, Orchestrator. -->

## Done

- **`GET /v1/dashboard/fpo/{id}`** (field officer, QC officer, FPO admin, viewer; another FPO's id → 404).
  Every section is SQL aggregates (9 queries), every amount a `Quantity`:
  - completeness: lots, complete lots, `%` (one decimal, null with no lots). A lot is complete when every
    type in its crop's `event_schema.mandatory` has a live event (not `undone`/`superseded`, the rules'
    `DEAD_EVENTS`). One SQL expression `lot_complete()` (D-037), reused by the farmer table.
  - stage tiles (land preparation, nursery, sowing, input application, harvest, drying, packing): done /
    in progress / not started per D-037 (furthest recorded stage while the lot is `open`/`drying` = in
    progress), one query.
  - active flags by severity, batches by status (every status present), Land Area Analytics (total, by
    block, by village: plots, declared, walked, declared-of-walked, GI-confirmed acres and share), Finished
    Goods (packed/published batches, total kg, newest 100 with packed = remaining kg and scans), scans
    (total, last 7 days), sync health (per network type, last 7 days: entries, save→ack p50/p95 ms, photo
    upload p50/p95 ms, failure rate = failures ÷ (failures + entries)).
  - filters `crop_id`, `district`, `block`, `village_id` (villages master via the farmer's village) narrow
    completeness, tiles and land area (place only). No phones, pins or boundaries anywhere.
- **`GET /v1/dashboard/fpo/{id}/farmers`**: per-farmer rows (village, block, plots, declared/walked acres,
  lots, complete lots), cursor pages, `?fields=` with tenant-disabled farmer fields hidden (D-017), reusing
  `registry.service.parse_fields` / `fpo_code`.
- **`GET /v1/audit-log`** (FPO admin): search by `actor_user_id`, `entity_type`, `entity_id`, `from`, `to`,
  newest first, cursor. Scoped by ownership of the described row (D-039); no device id or GPS in rows.
- **`GET /v1/batches/{id}/audit-export.csv`** (FPO admin, viewer): one row per version of every event of the
  batch and its component lots (`batch_shares`), with `entered_by` (user id), `entered_by_name`,
  `on_behalf_of_farmer_id`, `assist_session_id`, reason, `quantity` + `unit` columns (FR58) and the payload
  JSON. Cells starting with `= + - @` (tab, CR) get a `'` prefix (closes the B13 TODO).
- **`POST /v1/public/scans?batch_code=`** (no auth, no body so `sendBeacon` works cross-origin): stores code
  (upper-cased), time, SHA-256 of User-Agent; never the IP. Rate limit 100/min per IP: fixed window on
  Valkey (`INCR` + `EXPIRE`, key = IP hash + minute) → 429 `rate_limited` with `details.retry_after_s`
  (D-038). No library.
- **Stubs**: `GET /v1/partner/batches/{code}`, `POST /v1/partner/benefits`, `POST /v1/probes`,
  `POST /v1/probe-readings` → 501 `not_implemented_pilot`, planned behaviour in each OpenAPI description
  (backend-design.md §1 routes; the spec's inner `/partner/v1` dropped because everything is under `/v1`).
- Error codes: none new (`rate_limited`, `not_implemented_pilot` existed); docs/api/error-codes.md
  regenerated. No migration (head still 0004). No new library.
- Decisions D-037, D-038, D-039 (renumbered after M08/M11 took D-035/D-036) with ADR files.
- Merged main (B10, P03) into the branch; spec regenerated on top.

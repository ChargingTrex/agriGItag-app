## What was done

1. **Session persistence.**
   - `lib/core/db/daos/session_dao.dart` (+ `.g.dart`, registered in `database.dart`) has `read`, `save`,
     `setLocale` and `clear` over M01's Session row.
   - `lib/core/db/providers.dart` adds `appDatabaseProvider`, which calls `AppDatabase.open()` once and closes on
     dispose.
   - Tokens (access, refresh, access expiry) and the installation device id (UUID v4) live in
     `flutter_secure_storage`. iOS uses `first_unlock_this_device`: readable by background sync, never synced
     through iCloud.
   - The `DECISION D-027` comment is on `SessionDao.save`. The v1 schema still has NOT NULL `access_token` and
     `refresh_token` columns, so they are written `''`. A test asserts this.
   - `AndroidManifest.xml` gets `android:allowBackup="false"`, which the plugin requires: a restored backup cannot
     decrypt Keystore data.
2. **Screens** (`lib/features/auth/`):
   - `phone_screen.dart`: `+91` plus 10 digits, then "Get code".
   - `otp_screen.dart`: 6 digits, submits on the sixth.
     - The code is read from the SMS on Android through smart_auth's SMS User Consent API (`DECISION D-028`), behind
       a `smsCodeProvider` seam that tests replace.
     - "Send again" requests a new code.
     - `device_in_use` opens a bottom sheet: icon, "This phone is signed in as someone else. Sign out first." and a
       Sign out button. The button gives this install a new device id and retries the same code.
   - `pin_screen.dart`: 4 digits shown as dots.
     - `pin_set=false` asks for the PIN twice; a mismatch starts over.
     - `pin_invalid` shows the tries left; `pin_locked` shows the minutes left until `locked_until`.
     - A 401 (the 5-minute pin token expired) shows "Start again".
   - `auth_step.dart` is the shared layout, built from the farmer tokens:
     - prompt, one sentence with the red-triangle glyph, digit slots, a 3 x 4 keypad of 64 dp keys (no TextField),
       one FarmerButton, and the language switch in the app bar;
     - `authMessage()` maps every D-024 code, plus `network`, `portal_only` and `unknown`, to one sentence. No code
       is ever shown.
   - Role routing goes through the existing redirect: `/auth/otp` and `/auth/pin` are nested under `/auth`, and
     roles are mapped by wire name (`Role.qc` is now `qc_officer`, as the API says).
   - Accounts with only portal roles (fpo_admin, viewer, super_admin) are logged out again and told "This account
     works on the web portal".
3. **Session restore** (`SessionNotifier.restore`, awaited in `bootstrap.dart` before `runApp`; local reads only):
   - row + refresh token → the role's home immediately, offline too;
   - expired access token → background refresh: `refresh_reused`/401 signs out with "You were signed out. Please
     sign in again."; no signal keeps the session;
   - row without tokens → signed out and the row deleted;
   - tokens without a row (iOS Keychain outlives a reinstall) → tokens cleared, device id kept;
   - a keystore `PlatformException` → `deleteAll` and a signed-out start, instead of a crash at launch;
   - a new phone signing in with the same number is a normal sign-in. History pull is M02's: a hook comment is in
     `restore()`.
4. **Interceptor** (`lib/core/api/api_client.dart`):
   - Bearer goes only to operations whose generated `extra['secure']` names `AccessToken`. healthz, OTP, refresh
     and presigned PUTs get none. A request's own Authorization header (the pin token) is kept.
   - On a 401 for a request the interceptor authorised: if another call already rotated the token it retries with
     the current one; otherwise it calls `refreshAccessToken()` (single-flight) and retries once.
   - `X-Client` is never sent.
   - The `X-Device-Id` header is removed (`deviceId` constructor parameter dropped): the API does not read it, and
     the device id travels in the verify body.
   - `apiClientProvider` binds the client to the session.
5. **Sign-out.**
   - `SessionNotifier.signOut()` calls `POST /v1/auth/logout` (best effort), then clears the tokens and the Session
     row and keeps the device id. The outbox is not touched.
   - `/settings` (placeholder, allowed for every signed-in role, opened from a gear on the role placeholders)
     shows "Entries not sent yet: N. They stay on this phone; get signal to send them." from
     `outboxDao.pendingCount()`, then the Sign out button.
6. **Generated client.** `tool/gen_api.sh` regenerated `packages/agritrace_api` with the identity, registry and
   quality APIs. There are no manual edits; the second run leaves `git status --porcelain` empty (below).
7. **l10n.** 26 new keys in `app_ta.arb` and `app_en.arb`, each with an `@description`. `signIn` is now the app
   bar title of the sign-in steps.
8. **Lint.** `tool/no_textfield_lint.sh` now also scans `features/auth`, because farmers sign in there too.

DECISION comments: D-027 (session_dao.dart), D-028 (otp_screen.dart), D-024 (`refreshAccessToken`), D-013
(session.dart, rewritten COMPROMISE), D-003 (api_client.dart, unchanged).

## Risks

- A refresh answer lost in transit leaves the phone holding a rotated-out token. Its next refresh then looks like
  reuse and signs it out. This is inherent to D-024 and is stated in the D-024 code comment.
- Offline sign-out leaves the server's device signed in. The next user's `device_in_use` is resolved by a new
  device id, which leaves orphan signed-in device rows (their tokens are already deleted). The retry with the same
  code relies on `verify_otp` raising `device_in_use` before its commit, so the code is not consumed. I checked that
  in `service.py`, but not against a live server.
- The user id is read from the access token's `sub` claim (D-024 lists the claims), so the app depends on that
  claim staying.
- `bootstrap` now awaits the SQLite and keystore reads before the first frame. The cold-start effect on the Go
  AVD is not measured (Q01).
- The goldens are macOS-only, as M00's are.

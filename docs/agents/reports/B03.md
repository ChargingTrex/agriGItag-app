## What was done

- **`modules/registry/geo.py`**: all spatial SQL is here, written as explicit `text()` statements.
  - `locate_point(session, point, gi_tag_id) -> GeoResult{status, distance_m, region_version_id, buffer_m}`
    reads the latest `gi_region_versions` row that is in effect (`effective_from <= CURRENT_DATE`, highest
    `version_no`). `ST_Covers` → `inside`. Not covered but `ST_DWithin(geom, pt, tolerance_buffer_m)` →
    `near_edge`. Anything else → `outside`. `ST_Distance` gives the distance in metres. Raises
    `gi_region_missing` when the tag has no region in effect.
  - `event_within_plot(session, point, plot_id, radius_m, buffer_m)` checks the event point against the
    walked boundary plus buffer, or against radius plus buffer around the pin when there is no walked
    boundary (FR69).
  - `simplify_region(session, region_version_id, tolerance_m=50)` runs `ST_SimplifyPreserveTopology` on
    the geometry cast and returns GeoJSON with 6 decimal places.
  - `walked_area_acres(polygon)` computes the geodesic area on the WGS84 ellipsoid with pyproj `Geod`.
  - `parse_polygon` / `parse_multipolygon` validate input with shapely: type, `is_valid_reason`, WGS84
    ranges, and parse errors. Failures raise `invalid_geometry` (422).
- **`schemas.py`**: request and response models. Every field has `description=`, and so does every path
  and query parameter. `format_address()` joins the parts and drops any part that repeats one already
  shown, ignoring case (fixes "Tiruchuli, Tiruchuli"). `address_line` is a computed field on FPO,
  processor and farmer responses. GeoJSON input is typed with `PolygonGeoJSON` / `MultiPolygonGeoJSON`
  (Pydantic, no extra library).
- **`service.py`** (flushes but never commits; `__all__` = the names other modules may call) and
  **`router.py`**. 18 operations on 13 paths:
  - `GET/POST /v1/fpos`: a super-admin creates FPOs and sees all of them; everyone else sees only their own FPO.
  - `GET/POST /v1/processors`: the FPO's own processors plus shared ones; the FPO admin creates them.
  - `GET /v1/villages?district=&block=&q=&cursor=&limit=`: keyset pagination on (name_en, id).
  - `GET/POST /v1/farmers`, `GET/PATCH /v1/farmers/{id}`: scoped to the caller's tenant. Another FPO's
    farmer gives 404, never 403. A farmer caller sees only themself.
    - POST with a phone number creates or links a `users` row and a `farmer` membership, also when
      `no_smartphone` is set (F7).
    - A picked `village_id` fills in the address parts left empty.
  - `POST /v1/farmers/{id}/approve`: FPO admin only. Sets status `active` and records
    `approved_by` / `approved_at`; the audit listener writes the change. A farmer who is not pending
    gives 409 `farmer_not_pending`.
  - `POST /v1/plots`: idempotent on `client_id` (D-005).
    - Sending the same plot again returns 200 with the stored plot.
    - The same id with a different pin or size gives 409 `plot_locked`. An id owned by another FPO or
      farmer gives 409 `client_id_conflict`.
    - Stores the pin, its accuracy, the device, GPS and server times, and the declared area (`acre` or
      `cent`).
    - With a walked boundary it stores `walked_area_acres` and returns `area_gap_pct` /
      `area_gap_exceeds` (gap over 20 %).
    - Runs `locate_point` → `confirmed` / `near_edge` / `outside`. An unreviewed `map_pin` always gives
      `needs_review`.
    - Sets `location_method_label` (FR72).
    - Enqueues `rules.check_plot` by task name after commit; a broker failure is logged, not raised.
  - `GET /v1/plots/{id}`.
  - `POST /v1/plots/{id}/correct`: FPO admin only. No reason code gives 422 `reason_required`.
    - Writes a `plot_revisions` snapshot of every column (geography as WKT), bumps `revision_no`, and
      re-runs the region check.
    - Optional `review_method` / `review_outcome` set `reviewed_at` (FR70). A map pin that has been
      reviewed is then judged by the region check.
  - `GET /v1/crops`.
  - `GET /v1/gi-tags/{id}/region`: metadata of the version in effect plus the outline simplified at 50 m.
  - `POST /v1/gi-tags/{id}/region-versions`: a super-admin check against `users.is_super_admin` (an FPO
    admin gets 403). Validates the MultiPolygon and stores the buffer, taluks, source_ref, licence,
    confidence and `effective_from`. `version_no` = max + 1, starting at 0.
  - `GET/POST /v1/inputs`: the global list plus the FPO's own, FR56 categories. A global entry needs a
    super-admin.
  - `id_documents` / `producer_groups` have no endpoints; a TODO(B13) comment marks this.
- **`core/errors.py`**: added `client_id_conflict` (409), `plot_locked` (409), `reason_required` (422),
  `invalid_geometry` (422), `gi_region_missing` (404), `farmer_not_pending` (409) and
  `farmer_phone_taken` (409). Regenerated `docs/api/error-codes.md` (19 codes) and
  `packages/openapi/openapi.json`.
- **`infra/scripts/gi_boundary/`**: `build_virudhunagar.py`, `taluks.json` (Sattur, Aruppukottai,
  Tiruchuli with spelling aliases, `confirmed: false`) and `README.md`.
  - Builds `gi_region_v0.geojson` (district dissolve) and `gi_region_v1.geojson` (taluk union). Each
    carries `source_ref` (URL + file sha256 prefix + method), `licence`, `confidence: district_derived`,
    `taluks`, `taluks_confirmed`, `built_at` and `tolerance_buffer_m`.
  - Prints one JSON summary per version, ready to upload.
  - `--check-point LAT,LON --file F` reports inside or outside (exit code 0 or 3).
  - Downloads nothing itself.
- **Fixture**: `apps/api/agritrace/seed/fixtures/gi_region_fixture.geojson`, a hand-drawn octagon
  labelled `NON-OFFICIAL TEST FIXTURE` (`official: false`), 1 KB. Its east edge lies on the meridian

- **DECISION comments**: D-005 (`PlotIn.client_id`), D-017 (optional config-driven fields, `FarmerIn`),

## Round 2 (review B03-r1: PASS-PENDING-STACK, 0 P1 / 4 P2 / 12 P3)

### Fixed

- **P2-1 ODbL attribution.**
  - `build_virudhunagar.py` writes `attribution` into both outputs (default "Boundary data ©
    geoBoundaries contributors, ODbL-1.0; derived region shared under ODbL-1.0"; `--attribution`
    overrides it) and `share_alike` (true for an ODbL licence).
  - `POST /v1/gi-tags/{id}/region-versions` requires `attribution` and `share_alike`. **No column fits
    them** (`gi_region_versions` has `source_ref`, `licence`, `confidence`, `taluks`), so
    `region_source_ref()` stores them inside `source_ref` as
    `<source_ref>; attribution: <text>; share_alike: true|false`.
  - Tests: script output asserts both; a unit test checks `region_source_ref`; the integration test
    reads `source_ref` back.
- **P2-2 review outcome.**
  - `review_outcome` is now `accepted | rejected` in the schema (the column stays text). It must be
    sent together with `review_method` (422 otherwise); the reviewer's note goes in `reason_text`.
  - `location_status(check, pin_method, review_outcome)`:
    - `rejected` → `needs_review`, always
    - a map pin needs an `accepted` review
    - otherwise the region check decides
  - A correction that changes `pin` or `pin_method` without a review in the same request clears
    `reviewed_at`, `review_method` and `review_outcome`.
  - Tests: unit cases for the mapping and the validator. The integration test runs a rejected review
    (needs_review), then a re-pin (fields cleared, confirmed, revision 4).
- **P2-3 provenance required.** `taluks` is a required non-empty list. `confidence` is required and
  one of `official | district_derived | fixture`. The fixture file now says `confidence: fixture`.
  Unit test covers both.
- **P3 items done:**
  - A cursor whose id is not a UUID → 422 `validation_error` (checked inside `decode_cursor`).
  - A declared area under 0.01 acre after conversion → 422, so `area_gap` can no longer divide by zero.
  - Every router docstring has `\f` before `Args:`, so OpenAPI descriptions stop at the summary.
    `D301` is ignored for `agritrace/modules/*/router.py` with a comment in pyproject. The only
    operation description that still holds `Args:` is `/v1/healthz` (main.py, not B03).
  - The D-019 COMPROMISE line in `geo.py` now names geoBoundaries / LGD (ODbL-1.0). The simplify
    docstring now says "finer" (≈ 49.4 m).
  - New integration cases: `client_id_conflict` from the same FPO with another farmer and from
    another FPO, and a cross-FPO `GET /v1/plots/{id}` → 404.
  - `POST /v1/inputs` takes any role. A global entry needs a super-admin; an FPO entry needs the FPO
    admin or a super-admin. This removes the ordering trap. Unit test: field officer → 403.
  - `GiRegionVersion` now uses the `Audited` mixin (marker only, no migration), so every upload
    writes an `audit_log` row. The integration test counts it.

Date 2026-11-04. No new dependency, no new DECISION.

- **Where.** `apps/portal/src/features/members/FarmerPage.tsx`, `DevicesSection`: shown only when the caller is
  `fpo_admin` (same gate as the phone Reveal) and the farmer has an app login (`FarmerOut.user_id`). Lists
  `GET /v1/users/{id}/devices`: platform, app version, signed-in date, "active" or "signed out <date>". Each
  active row has "Revoke", which opens an MUI dialog with an optional reason; "Sign out device" calls
  `POST /v1/devices/{id}/revoke` (`DeviceRevokeIn.reason`, blank sent as null) and refetches the list. Errors use
  the existing `errorMessage` alert. The server writes the `device.revoke` audit row; the portal adds nothing.
- **Mock.** `src/mocks/handlers.ts`: `MOCK_FARMER_USER_ID` on farmer #10, `mockState.devices` (one active, one
  signed-out Android) and `mockState.revokes` (reasons received), both reset per test; handlers for the two
  routes (401 / 403 non-admin on another user / 404 unknown device; revoke sets `revoked_at`, 204).
- **Tests (`members.test.tsx`, +3):** admin sees an active and a signed-out device with one Revoke; revoke with
  "phone lost" reaches the route and the row shows signed out; a field officer sees no Devices section.
- **Skipped.** Staff devices: the portal has no staff page and the API has no user list, so there is no place
  that shows a staff user; operators revoke staff devices via the API (TODO.md P12 line). No audit row on the
  page itself: the Audit log screen already shows `device.revoke` rows.
- **r1 P3s applied:** reason cleared when a Revoke opens, focus moves to the Devices heading after a revoke,
  reason input capped at 500 characters (server `maxLength`).
- **Verify.** `npm run lint`, `npm run typecheck`, `npx vitest run src/features/members --no-file-parallelism`,
  `npm run gen:check` (mock mode only; live stack not used).

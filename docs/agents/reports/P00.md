## What was done

- **Project** `apps/portal`: Vite 8 + React 18.3 + TypeScript 5.9 strict (`noUncheckedIndexedAccess`,
  `verbatimModuleSyntax`), React Router 7, TanStack Query 5, MUI 9, react-hook-form + zod 4. Node 24, npm,
  `package-lock.json` committed, exact versions pinned.
- **Generated client (D-003)**: `npm run gen:api` runs `openapi-typescript` on
  `../../packages/openapi/openapi.json` into `src/api/generated/schema.d.ts` (its header says "auto-generated
  ... Do not make direct changes") and `scripts/gen-error-messages.ts` into
  `src/api/generated/error-messages.ts` (header: "GENERATED ... NEVER EDIT BY HAND"). `src/api/client.ts` is
  `openapi-fetch` typed by it, with bearer-token and 401 middleware and `unwrap()`. Location chosen:
  **`apps/portal/src/api/generated/`**, not `packages/client-ts/`, because the portal is the only TS consumer
  (README §Layout). `npm run gen:check` regenerates and fails on a diff, including untracked files.
- **App shell**: `AppLayout` (AppBar + permanent Drawer, `<nav aria-label="Main">`) with the 8 planned screens
  as placeholder routes (Dashboard P06, Members P01, Flags P02, Ready lots P03, Batches P04, Labels & exports
  P05, Master data uploads P08, Settings P06). Dashboard shows `GET /v1/healthz` through the generated client.
- **Auth**: `AuthProvider` (session in React context + sessionStorage, validated with zod, query cache cleared
  on sign-out), `RequireAuth` guard (redirects to `/login` with `state.from`), `LoginPage` (mobile number ->
  6-digit SMS code -> 4-digit PIN, one field per step, react-hook-form + zod). `/v1/auth/otp/request`,
  `/v1/auth/otp/verify`, `/v1/auth/pin/verify` use plain fetch with an assumed contract in
  `src/auth/authApi.ts`, mirrored in the MSW handlers, all marked `TODO(B02)`. Any 401 signs out.
- **Error envelope**: `src/api/errors.ts`: `toApiError(status, body)` parses `{"error": {code, message,
  details}}` with zod, `errorMessage(error)` maps `code` through the generated table (fallback text for
  unknown codes, a network message for a failed fetch), and `isRetryable` (network, 5xx, 429) drives the
  QueryClient retry policy (conventions.md).
- **Lean lists (plan §13 C4)**: `src/api/cursor.ts`: `useCursorList` (wraps `useInfiniteQuery` over
  `{items, next_cursor, has_more}`, passes `cursor`/`limit`/`signal`, flattens `items`) and
  `fieldsParam<T>()` (typed `?fields=` builder). Usage rules in `apps/portal/README.md` §Lean lists.
- **Theme**: `src/theme.ts`: primary green `#2e7d32` (green seed, white text contrast ≥ 4.5:1), Button,
  ListItemButton and IconButton min target 48 px (mobile spec "office roles minTarget 48").
- **MSW**: `src/mocks/handlers.ts`: healthz GET/HEAD typed with generated `components['schemas']`, so a spec
  change breaks typecheck; auth handlers hand-written (TODO(B02)). Used by Vitest (`msw/node`,
  `onUnhandledFrame: 'error'`) and `npm run dev:mock` (browser worker, only under `import.meta.env.DEV`;
  `public/` is not copied into `dist/`, and the build contains no mock code; checked by grep).
- **Tooling**: ESLint flat config (typescript-eslint `strictTypeChecked`, react-hooks, eslint-plugin-jsdoc
  `flat/recommended-typescript-error` plus `require-jsdoc` on declarations, methods, classes and
  variable-assigned arrows and functions, `require-param`, `require-returns`, `require-throws`,
  `require-description`) + Prettier. A probe file with undocumented functions produced 5 jsdoc errors (rules
  confirmed active). Vitest + RTL + jsdom. Playwright config (`PORTAL_URL`, default `http://localhost:5173`;
  Vite proxies `/v1` to `API_URL`, default `http://localhost:8000` = compose `api`) with one smoke spec,
  **not run**. `npx playwright install chromium` is a P07 step.
- **CI**: `.github/workflows/ci.yml` does not exist on this branch, so the job is in
  **`apps/portal/ci-job.yml`** (npm ci, gen:check, lint, typecheck, test, build, size report into the job
  summary with pipefail). The Orchestrator should paste it under `jobs:`.
- **Docs**: `apps/portal/README.md`, 33 rows in `docs/LIBRARIES.md` (every dependency and devDependency),
  CHANGELOG line. DECISION comments: D-003 (`src/api/client.ts`), D-018 (`eslint.config.js`,

  not linked into the shipped bundle, but D-018 reviewers should confirm it is acceptable.

  `portal` service yet.

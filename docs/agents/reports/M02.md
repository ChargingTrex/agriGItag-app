# WP-M02 — Sync engine: worker report

Branch `worktree-agent-a5d835db7b6392398` (from main `eddf6b3`). Not merged.

## What was done

- **One `SyncService`** (`lib/core/sync/sync_service.dart`) with plain functions per phase. One run at a time: a
  request that arrives during a run causes exactly one more run, so nothing is lost. A run reads the signed-in user
  from the Session row and does nothing when nobody is signed in. Order: push → pull → photos (skipped when Wi-Fi-only
  is on and the phone is not on Wi-Fi) → bundles. A phase that throws is logged and the next phase still runs.
  - Pull now runs **before** photos. B07 reports `photo_pending` in the pull, so those photos are re-requested in the
    same run. mobile-design §3 lists pull after photos; the reason is documented at the call site.
- **Triggers.** Each automatic trigger first runs the probe (any HTTP answer to `HEAD /v1/healthz` within 3 s means
  reachable):
  - app open and resume (`AppLifecycleListener`);
  - 500 ms after a save (debounced). This is driven by Drift outbox **inserts**, so the feature screens need no call;
  - a connectivity change (`connectivity_plus`);
  - the earliest backoff ending (a foreground timer);
  - a WorkManager / BGAppRefresh periodic task every 15 min (`background_scheduler.dart`).

  `sendNow()` runs at once without the probe.
- **Push** (`outbox_processor.dart`):
  - Entries go oldest first, in batches of at most 50, trimmed to 256 KB measured on the real encoded envelope.
    `nextBatch` only measures payloads. A single oversized entry still goes out, so it gets its 413 instead of
    blocking the queue.
  - The envelope carries `device_id`, `app_version`, `device_time` and `metrics[]`.
  - Entry kinds: `event_version` is built from the columns plus the payload. An undo is sent as an `undo` version
    with the original's type and payload. The keys `occurred_on`, `occurred_end_on`, `batch_id` and `reason_text`
    are lifted out of `payloadJson` when present (a convention for M07). The other kinds (`plot`, `consent`,
    `quality_reading`, `flag_resolution`) send the payload as `data`.
  - Per-entry results:
    - `accepted` / `duplicate` → confirmed, with `serverReceivedAt` set to `server_time`; upload URLs are stored.
      A photo missing from a duplicate's `photo_uploads` is already in storage, so its row goes to `sent` and the
      next confirm settles it.
    - `rejected` → `markRejected`: needs_attention with the error code, never retried.
    - `stale_version` → retried once (DECISION D-005 comment: overlapping foreground and background pushes). A second
      `stale_version` is rejected.
- **Retry policy** (`retry.dart`):
  - Only network errors, 5xx and 429 are retried, with a backoff of 2, 4, 8 … s, ×0.8–1.2 jitter, capped at 5 min.
    `Retry-After` and `error.details.retry_after_s` are honoured.
  - 401 and 403 wait without marking the entry (M06 refreshes or ends the session).
  - Any other 4xx makes every entry of the batch needs_attention.
  - Timeouts are M06's `ApiClient` (10 s connect, 30 s send/receive).
- **Photos** (`photo_uploader.dart`):
  - Media whose URL is missing or expires within 1 min are first re-requested by re-pushing their entries; the server
    answers `duplicate` with fresh URLs.
  - Then one presigned PUT per file. Content-Type and `x-amz-checksum-sha256` are rebuilt exactly as B06 signs them.
    The PUT uses a bare dio, so no Authorization header is sent.
  - Parallelism: 3 PUTs when the last measured PUT ran at ≥ 1000 kbit/s, else 1. The speed is kept in SyncState
    `upload_kbps`.
  - A failed PUT is retried whole. A storage 403 drops the URL so a fresh one is requested. A missing local file
    becomes needs_attention `file_missing`.
  - Then `POST /v1/sync/photos/confirm` (50 per call):
    - `received` → done, object key = URL path, outbox confirmed, **full-size file deleted, thumbnail kept**;
    - `missing` → back to pending without URL.
- **Pull** (`pull_service.dart`, against B07 `d933a64`):
  - Each page is applied in one transaction together with its cursor.
  - `lot` and `flag` are upserted. The flag's farmer comes from the local lot, plot or entry.
  - `event` with status `undone` marks local confirmed versions undone.
  - `photo_pending` reopens the photo: pending, no URL, outbox due now.
  - `intake` and `notification` are ignored (no local table).
  - A record that cannot be read is skipped, so the cursor is never blocked.
  - A refused cursor (422) is dropped, so the next pull starts over.
  - Decimals arriving as strings are handled.
- **Bundles** (`bundle_fetcher.dart`, against B07):
  - One `GET /v1/sync/reference?since=plots:41,crops:7,…` lists every held part (first run: no `since`). A 304
    changes nothing. Returned parts are stored as sent, because the server compares by "version differs".
  - A missing `gi_region` is not an error.
  - DECISION D-016: plots come from the `plots` bundle part. The M01 Plots table is upserted from the same payload in
    the same transaction. Plots are never deleted, and the phone-only survey number is never overwritten.
- **D-029 per-user outbox.** Schema v2 adds `Outbox.ownerUserId`. The migration rebuilds Outbox and fills the owner
  from the entry, or for a media row from its entry. What filters by owner:
  - `nextBatch`, `pendingUploads`, `awaitingConfirm` and `nextDue`;
  - `pendingCount()` counts only the signed-in user's rows, via a subquery on the Session row, so it re-emits on
    sign-in and sign-out;
  - the new `strandedCount()` counts the other users' rows, for M10.
  - **Deviation:** I did not add `ownerUserId` on **Entries**. The existing `Entries.enteredByUserId` is the owner by
    definition, and the append-only trigger already covers it; a copy would need an Entries rebuild and a trigger
    change. This is recorded as a DECISION D-029 comment on the column.
- **Metrics (F1)** (`metrics.dart`):
  - A row is written at the acknowledgement: saved_at = `createdAt`, acked_at, failures = earlier attempts, network
    type.
  - Photo upload ms is added after confirm. If the acknowledgement row has already been shipped, a second row is
    written instead.
  - Unshipped rows go in the next push and are marked shipped after a 200.
- **Clock skew.** `clock_skew_ms` is stored when |device − `server_time`| > 10 min, and 0 otherwise.
- **Kill-safety.** `resetAfterKill()` (on start and in the background task) runs `resetStaleSending` and turns
  `uploading` media back to `pending`.
- **Enum wire names** (`enum_wire_names.dart`): `wireName` / `fromWire` (camelCase ↔ snake_case), plus the wire enums
  `SyncKind` and `ChangeKind`. The test checks them against `openapi.json`.
- **Providers** (`lib/core/providers/sync_providers.dart`): `syncServiceProvider`, `syncOverrides` (overrides M05's
  `pendingSendCountProvider`) and `strandedCountProvider`.
- **Platform**:
  - iOS `Info.plist`: `BGTaskSchedulerPermittedIdentifiers = in.agritrace.sync`, `UIBackgroundModes = fetch`.
  - Android needs nothing (the plugins merge their permissions).
- **DECISION D-003 comment** in outbox_processor: sync calls post JSON maps through the shared dio instead of the
  generated built_value models. `test/sync/contract_test.dart` pins every key and enum value against the committed
  spec.

## Risks

- Real-network timing (BM-11/12) is not measured: that is Q01's. The 30 s visibility lag of B07 pulls means changes
  made just before a run show up on the next run.
- `connectivity_plus` brings `nm` (MPL-2.0, Linux-only, unmodified), accepted under the D-018 amendment. I did not
  verify that it is absent from the APK by building.
- `workmanager_android` merges POST_NOTIFICATIONS and FOREGROUND_SERVICE(_SHORT_SERVICE) into the manifest.
- Foreground and background isolates can push the same rows at the same time. The server deduplicates, and
  `stale_version` is retried once.

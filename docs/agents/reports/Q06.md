## How the tests work

- **Keywords** (`qa/robot/lib/agritrace_keywords.py`, a new API section). `Login As` signs in with the dev OTP plus the
  office PIN, then caches and refreshes sessions in `qa/robot/results/.api-sessions.json` (the folder is git-ignored).
  This matters because the API allows 10 OTPs per phone per 24 h. `Call API` calls the live API with an expected
  status. The fixtures follow the Verifiers' live procedures:
  - `QA World`: a QA farmer with a random `+9197…` phone and an address, a calibrated meter, and a rainfed plot with
    land record `QA-SURVEY-77/3B`.
  - Builders: `New Plot` (1 acre, pins on a grid inside the fixture region), `New Lot`, `Moisture`, `Event`, `Push`,
    `Received Lot`, `Receive`, `New Batch`, `Packing`, `Start Assist`, `New Consent`.
  - Waits: `Wait For Flag`, `Wait For Build`, `Drain Pull`.
  - Docker: `Compose` runs one-off api containers and `exec` in the worker and s3 containers. `S3 Get`, `S3 Versions`
    and `S3 Put` use awslocal in the s3 container. `Decode QR` uses zxing-cpp.
  - HTTP goes through `requests`, the package robotframework-requests already installs. No httpx in the QA venv.
- **DB** (DatabaseLibrary + pg8000) is used only for what the API does not expose:
  - row counts the acceptance lines name (one `event_versions` row, `page_builds`, `notifications`, `evidence_photos`
    status);
  - the B03 near-edge point, computed with the Verifier's PostGIS query;
  - the B07 flag insert, as the Verifier and the integration test did;
  - a second FPO with its own admin (`Second FPO Admin`). The seed has one FPO and no super-admin, and no API adds
    staff. With it, "cross-FPO → 404" and "soil type hidden for that FPO only" are tested over HTTP as a real
    second-tenant admin.
- **B13 config lines** start throw-away containers from the stack's image with `${COMPOSE} run --no-deps -v <scratch
  config>:/app/config:ro api`, the same approach as B13's live check:
  - one with `id_document_capture: true`, published on `FLAG_ON_PORT` (8098). Its endpoint answers 422
    `validation_error`, so the route is exposed; the flag-off API answers 404 `feature_disabled`;
  - one with `enabled: maybe`, which exits 3 with `ConfigInvalid: /app/config/tenants/…: fields.plot.soil_type.enabled`
    and `Application startup failed`.
- **Tags**: every test keeps its `WP-Bxx` and `FR-n` tags, and `not-ready` is removed only from tests that pass. Test
  names stayed the same except one. "Standards Bundle Part Holds Only Lot Gates Yield Plausible And Limits" became
  "… Carries The Full Profile Rules Per Active Version", because that is the B07 acceptance line after the M03
  decision (docs/agents/acceptance/B07.md).

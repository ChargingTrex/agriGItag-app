## What was done

- **Auth on the final B02 contract** (`src/auth/*`):
  - `authApi.ts` now uses the generated `openapi-fetch` client (no hand-typed shapes or zod).
  - Every auth call sends `X-Client: web`. Verify sends `device_id` (a UUID kept in localStorage) and `platform: "web"`.
  - The `kind` discriminator picks the next step: `session` signs in, `pin_required` goes to the PIN step with `pin_token` as the Bearer.
  - When `pin_set: false` the user chooses a PIN, types it twice, and it is checked on the client.
  - `otp/request` expects 204.
  - `refreshSession()` sends `{}` and the cookie comes along on the same origin. It shares one in-flight promise, because two refreshes at once count as reuse.
  - Sign-out calls `POST /v1/auth/logout`.
  - `AuthProvider` keeps the `SessionOut` in React state only (`DECISION D-024` at the storage point; `DECISION D-022` at the transport). sessionStorage is gone.
  - On mount it restores the session through the refresh cookie, and `RequireAuth`/`LoginPage` show a progress bar meanwhile. It refreshes 60 s before `expires_in` runs out.
  - Any API 401 signs out.
  - Error text comes from the generated `ERROR_MESSAGES` plus details: `pin_invalid` "N attempts left", `pin_locked` "You can try again at HH:MM" (from `locked_until`), `rate_limited` "Try again in N seconds".
  - Note: the contract names `details.locked_until`. The brief's "retry_after" exists only on `rate_limited` (`retry_after_s`).
- **Members** (`src/features/members/`):
  - `MembersPage`: a "Waiting for approval" table (`?status=pending`) with an Approve button per row (48 px theme targets, `aria-label="Approve <name>"`). Approving invalidates every `['farmers']` query, so the farmer leaves the pending list and shows Active in the roster without a reload.
  - "All members" roster: `useCursorList` with "Load more", a server-side status filter, status chips, and lean columns (code, name, village/address, status). The search box filters loaded rows only (`shortcut:`, because there is no server `q`/`village_id`).
  - `FarmerPage`: profile, status chip, GI status (authorised-user no. or "Not registered"), assist-mode note, approve when pending. A plots note explains that "Add another plot" is mobile-only and that the per-farmer list waits for an API.
  - `PlotPage`: location_status chip, method label, declared vs walked area with units, gap % with a >20 % warning, and the review outcome.
  - `PlotMap` is loaded with `React.lazy`:
    - MapLibre GL 6.16 shows an OSM raster style. The source `bounds` and the map's `maxBounds` are the GI region bbox padded by 0.1°, so tile requests and the browser cache stay in the FPO area (D3).
    - The pin is a marker; the GI outline comes from `GET /v1/gi-tags/{id}/region`.
    - The satellite toggle is OFF by default. Its source (EOX S2 cloudless 2016, CC BY 4.0) is added only on the first click.
    - The worker URL is set from a Vite `?url` import, because MapLibre otherwise looks for it next to its renamed chunk and would break in the build.
    - `DECISION D-018` comment with ADV/COMPROMISE.
  - `ProcessorsPage` (gap analysis): list (`GET /v1/processors`, a plain array) and a minimal create form (react-hook-form + zod: name, kind, FSSAI, GI no.).
  - Routes: `/members`, `/members/:farmerId`, `/members/plots/:plotId`, `/processors`. Nav: "Processors" added after Members.
- **Mocks** (`src/mocks/handlers.ts`):
  - Identity handlers follow the spec: 204 otp/request, `pin_required` with `pin_set` true/false, pin/verify with `pin_invalid`/`pin_locked`, refresh/logout driven by a `mockState.signedIn` "cookie".
  - Registry handlers: farmers with cursor paging (57 seed farmers), detail, approve (`farmer_not_pending`), plot, crops, GI region, processors.
  - All bodies are typed with the generated `components`. `resetMockData()` runs after each test.

- **Playwright** in mock mode: with `PORTAL_URL` unset, `playwright.config.ts` starts `npm run dev:mock` on 5174. `e2e/members.spec.ts` covers login → members → approve (0 navigations), plus a plot page check: the MapLibre canvas renders in real Chromium, no `tiles.maps.eox.at` request is made before the toggle, and one is made after it.

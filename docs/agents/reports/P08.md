## What was done

- **Template route exists** (`GET /v1/imports/{kind}/template.csv`, B13), so the portal downloads the server's
  template (single source of truth) instead of building one client-side. It is fetched with `parseAs: 'text'`
  and offered as a `data:` link (`download="<kind>-template.csv"`; no object URL to revoke).
- **B13's dry run returns no parsed rows** (only `accepted` and `rejected: [{row, code, field}]`), so the
  preview parses the file in the browser. `features/imports/csvFile.ts`:
  - `parseCsv`: a ~30-line reader that numbers rows by the line they end on, like Python `csv` `line_num`
    (`DECISION D-047`, new ADR). Pinned by a test against numbers printed by Python for the same text.
  - `readCsvFile`: reads the bytes once, SHA-256 with SubtleCrypto, decodes UTF-8 (BOM dropped).
  - `maskPhone`: `XXXXXX` + the last 4, same as registry `mask_phone` (`phone_masked`).
- **`MasterDataPage.tsx`** (`/uploads`, replaces the placeholder): Farmers / Villages / Inputs tabs. Per tab:
  1. template button and column legend (column, en label, Required/Optional from `/v1/config/fields`);
  2. plain `<input type="file">` with a visible label; picking a file reads, hashes and dry-runs it (`dry_run=true`);
  3. preview: every row (row number, each column, status), rejected rows tinted red with the code, its
     message and the column outlined; phone-type columns from the config (and any `phone`/`mobile` column)
     masked; counts; client-side pages of 100 rows (`TablePagination`);
  4. "Import N rows" is enabled only for a successful dry run with accepted rows. It re-reads the picked file,
     re-hashes it, refuses with "The file changed after it was checked…" if the hash differs, and otherwise
     sends the same bytes with `dry_run=false`. The commit report replaces the preview statuses; after a
     farmers import a link to Members (new farmers wait for approval). `[kind]` queries are invalidated.
  - Errors: `errorMessage` text plus the server's `details.file` hint (e.g. "save the CSV as UTF-8").
  - Villages tab only for a super-admin (round 2); the server's `forbidden` message stays as a fallback.
- **Mocks** (`handlers.ts`): `GET /v1/config/fields` (farmer/village/input subset of apps/api/config),
  `GET /v1/imports/:kind/template.csv` (same filter as `imports.template_columns`), `POST /v1/imports/:kind`
  (simplified rules: missing required → `field_required`, malformed phone → `import_row_invalid`; villages need
  `mockState.superAdmin`; a farmers commit adds pending farmers; every call recorded in `mockState.imports`).
- **Tests** (`imports.test.tsx`, 9 cases): template + legend + axe; 2 bad rows → red rows, masked phone, counts,
  axe, confirm with the same bytes and `dry_run=false`, only valid farmers created, Members link; changed file
  refused; villages 403 message; villages as super-admin; server file hint; 250-row paging; CSV reader vs
  Python line numbers; mask.
  - Test-env note: Node's fetch wraps each multipart part in the global `File`, and jsdom's File cannot stream
    Node bytes, so the request body never ends. The test file swaps in Node's `File` around each test
    (comment in the file). Browsers are unaffected; the MSW handler checks the part with `typeof` instead of
    `instanceof Blob` for the same reason.
- No new library. LIBRARIES rows of react-router, TanStack Query, MUI, openapi-fetch, axe-core and user-event
  list the new files.

## Risks

- SubtleCrypto exists only on HTTPS or localhost; on a plain-HTTP staging host the file check fails with an error.
- Exotic CSVs (bare `\r` line ends, a quote inside an unquoted cell) may display differently from the server's
  reading; the server's verdict and counts are still what is shown and enforced (D-047 compromise).
- On this machine (load average 300–500 from other agents) the first render of a page sometimes exceeds the 5 s
  `findBy` wait; failures seen were timeouts in several suites (members, flags, batches, imports), not assertions.

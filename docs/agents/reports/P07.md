## Finished state (2026-11-01)

**What was built**
- `apps/portal/e2e/chain.spec.ts`: the chain, declared twice (`chain run 1`, `chain run 2`) in one serial
  session. Steps: dev-OTP login → upload a one-row farmers CSV and approve that farmer → Flags → clear the hold
  "Yield above the ceiling" (live mode: the first open flag) → Processors → Ready lots, tick the 3 reference
  lots → Create batch → Batches → batch page: approve grading, final packing, publish (wait for the build
  link) → labels download (`labels-<code>.pdf`). Each run has `test.setTimeout(10 min)` and asserts it took
  `< 600 000 ms`. axe runs on every screen the chain opens.
- `apps/portal/e2e/axe.spec.ts`: mock mode only. The login page plus all 14 routes of `AppRoutes.tsx` (the batch
  detail page is covered by the chain in 3 states).
- `apps/portal/e2e/support.ts`: `signIn` (handles a first-time PIN choice), `openNav`, `goInApp` (pushState, so
  the MSW state survives) and `expectNoSeriousAxe` (injects `axe-core/axe.min.js`, waits for finite CSS
  transitions, fails softly on serious or critical violations).
- Live mode (`E2E_LIVE=1`), **as changed by P10 (2026-11-02, after Verifier issues P07-1/P07-2)**: logs in as
  the seeded admin (+91 9000000001) through the form; the staff PIN is `E2E_STAFF_PIN` (default 1234; the
  shared stack uses 2468). Each run makes its own batch and never touches FGP8T4033HM7: the imported farmer
  gets a plot and a 20 kg lot over the API (admin token read from the portal's own requests), the QC officer
  (signed in once per Playwright worker) records the drying-end moisture and the intake, the run clears the
  intake's `yield_check_unavailable` flag, ticks the lot on Ready lots, creates the batch, the QC officer grades
  it over the API (B12's fixes path), and the gates are walked exactly (no "already passed" skips). `ok()`
  accepts the empty `204` of `otp/request`; the admin's second sign-in in a worker waits out the
  one-code-per-60 s limit. Command: `make up && make seed && cd apps/portal && E2E_STAFF_PIN=<pin> E2E_LIVE=1
  npx playwright test e2e/chain.spec.ts`.
- Config: `playwright.config.ts` adds live mode (`npm run dev` on 5173) and `E2E_BASE_URL` (replaces
  `PORTAL_URL`); `expect` 15 s, `actionTimeout` 30 s (20 s before review r1). `src/mocks/browser.ts` exposes `agritraceMock` (D-052).
  `tsconfig.node.json` adds lib `DOM` for `page.evaluate`.
- CI: the `portal` job runs `npx playwright install --with-deps chromium`, then `npm run e2e`; job timeout

## Skipped / risks

- ~~Live mode does not create a batch.~~ Fixed in P10: each live run adds one farmer, plot, lot, intake and
  batch (published) and clears that lot's flag; reseed to reset. Each live invocation costs the admin 2 OTPs
  and the QC officer 1 of the 10-per-day cap (`OTP_DAILY_CAP`).
- The QC phone step is simulated: in mock mode a `grades` Proxy in MSW state, in live mode API calls. The
  real phone → portal chain is Q02's.
- Robot `qa/robot/portal` is not wired to Playwright. There is no upload of the Playwright report in CI.
- `[WebServer] ECONNREFUSED` appears in mock runs. It comes from the published-page preview iframe
  (`/v1/public/...`), which goes past MSW to the dev proxy. It is harmless and does not fail the run.

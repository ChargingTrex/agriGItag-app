**Specs written**
- `apps/portal/e2e/chain.spec.ts`: the chain, declared twice (`chain run 1`, `chain run 2`) in one serial
  session. Steps: dev-OTP login → upload a one-row farmers CSV and approve that farmer → Flags → clear the hold
  "Yield above the ceiling" (live mode: the first open flag) → Processors → Ready lots, tick the 3 reference
  lots → Create batch → Batches → batch page: approve grading, final packing, publish (wait for the build
  link) → labels download (`labels-<code>.pdf`). Each run has `test.setTimeout(10 min)` and asserts it took
  `< 600 000 ms`. axe runs on every screen the chain opens.
- `apps/portal/e2e/axe.spec.ts`: mock mode only. The login page plus all 14 routes of `AppRoutes.tsx` (the batch
  detail page is covered by the chain in 3 states).
- `apps/portal/e2e/support.ts`: `signIn` (handles a first-time PIN choice), `openNav`, `goInApp`
  (pushState, so the MSW state survives) and `expectNoSeriousAxe`. That helper injects
  `axe-core/axe.min.js` with `addScriptTag`, waits for finite CSS transitions to end, and fails softly on
  serious or critical violations.
- Live mode (`E2E_LIVE=1`): the chain logs in as the seeded admin (+91 9000000001), and the QC grading is
  posted over the API as the seeded QC officer, following B12's fixes path. Batch creation is skipped because
  the seed batches every lot. Gates already passed are skipped, so a second run without reseeding works.
  Verifier command: `make up && make seed && cd apps/portal && E2E_LIVE=1 npm run e2e`.
- Config: `playwright.config.ts` adds live mode (starts `npm run dev` on 5173) and `E2E_BASE_URL`, which
  replaces `PORTAL_URL`. It also sets `expect` 15 s and `actionTimeout` 20 s.
- `src/mocks/browser.ts` exposes `agritraceMock` (D-052). `tsconfig.node.json` adds lib `DOM` for
  `page.evaluate`.
- CI: the `portal` job runs `npx playwright install --with-deps chromium` and then `npm run e2e`. The job
  timeout goes from 15 to 25 min.

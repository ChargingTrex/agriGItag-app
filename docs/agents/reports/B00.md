## What was done

- **apps/api package `agritrace`** (Python 3.12 pinned by `requires-python` and `.python-version`, locked with uv):
  - `main.py`: app factory, OpenAPI 3.1 metadata and one tag per module, Brotli middleware with gzip
    fallback, error-envelope handlers, `/v1` router (D-020), auto-mounting of `modules/*/router.py`
    (so parallel WPs never edit main.py), `GET /v1/healthz` running real `SELECT 1`, Redis `PING` and S3

    when any check fails.

    `ENV=prod`), `db` (async engine, sessionmaker, `get_session`, `Base` with a naming convention),
    `ids` (`uuid7`, `lot_code`, `batch_code`, `superlot_code`), `errors` (`AppError` with auto-registry

    `internal_error`, which the envelope handlers need), `schemas` (Quantity, SignedQuantity, GeoPoint,
    ThreeClocks, ClientRef, Page[T], ErrorEnvelope), `task_names`, `storage` (presigned PUT bound to the
    SHA-256 via `ChecksumSHA256`, head, get_stream, put_public), `time` (`utcnow`, `clock_skew`), and
    `audit` (placeholder).
  - `worker/__init__.py`: Celery on `REDIS_URL`, autodiscovers `agritrace.modules.*.tasks`,
    `worker_process_init` hook that drops the inherited engine (D-009).
  - 11 empty module packages with headers and `__all__ = []`.
  - `export_openapi.py`, `alembic.ini`, `alembic/env.py` (async engine, `Base.metadata`, GeoAlchemy2
    alembic hooks, `search_path=public`), `alembic/script.py.mako`, `Dockerfile` (python:3.12-slim, uv,
    non-root uid 10001), `.dockerignore`, `.env.example`.
  - Tooling in `pyproject.toml`: ruff (pydocstyle google plus D417), mypy strict with the pydantic plugin,
    interrogate at 100 % (private, magic and nested functions included), and two import-linter
    contracts for D-004 (an independence contract between modules that ignores only `-> *.models` and
    `-> *.service`, and "core never imports modules").
- **Tests:** `tests/conftest.py` starts session-scoped testcontainers for PostGIS, Redis and MinIO,
  creates the buckets, injects env vars, provides an httpx AsyncClient over the app and turns on eager
  Celery. Unit tests: ids, errors, schemas/time/config (19 tests). Integration tests (`integration`
  marker): healthz all ok, healthz independent failure, presigned PUT that checks the SHA-256.
- **infra:** `docker-compose.yml` (db, redis, minio, minio-init, mosquitto, api, worker; named volumes;

### P2 fixes

1. **Fail-closed secrets.**
   - `JWT_SECRET` has no code default (required), and `OTP_DEV_CODE` defaults to `None`, so the bypass
     is off. `ENV` still defaults to `dev`.
   - The prod guard now requires `JWT_SECRET` of at least 32 bytes and rejects any `OTP_DEV_CODE`.
   - Dev values live only in `.env.example`, compose and conftest.
   - `gen-error-codes.py` sets a placeholder `JWT_SECRET` before importing the package. It imports
     `agritrace.worker`, which reads the settings, and no secret is used.
   - Tests: `test_secrets_fail_closed` (missing secret means no start; OTP is off by default) and
     `test_prod_guard` (31 bytes rejected, OTP set rejected, 32 bytes accepted, dev allows both).
2. **healthz error text.** Each failing check returns `error: <ExceptionClass>` (for example
   `error: TimeoutError`). The full text is logged at WARNING by `agritrace.main`. A test checks that the
   body says `error: ConnectionError` and that the host:port appears only in the log.
3. **HEAD is cheap.**
   - `HEAD /v1/healthz` is a separate handler, `reachable()`, that returns 200 without running any probe.
     Its docstring explains why: it is the phones' probe, and a slow S3 must not stop entry pushes.
   - GET keeps all three checks. Operation ids are `healthz_v1_healthz_get` and
     `reachable_v1_healthz_head`.
   - A unit test checks that HEAD stays 200 with S3 down and that no probe runs.
4. **boto3 client.** It uses `Config(connect_timeout=3, read_timeout=10, retries={"max_attempts": 2,
   "mode": "standard"})`, and the healthz S3 probe uses that same client.
   - botocore stores this as `total_max_attempts: 3` (2 retries after the first try). The code comment
     and the test say so.
   - Test: `test_client_has_bounded_timeouts`.
5. **import-linter wildcard.** The contract now uses `modules = ["agritrace.modules.*"]`. A temporary
   probe module `masters/service.py` importing `registry.schemas` was reported:
   `agritrace.modules.masters.service -> agritrace.modules.registry.schemas (l.1)` BROKEN. I removed
   the probe afterwards.
6. **Signature validation.** `S3_SKIP_SIGNATURE_VALIDATION: "0"` is set on the compose `s3` service and
   on the LocalStackContainer. `tests/integration/test_storage.py` now also asserts 403 for a PUT
   without `x-amz-checksum-sha256` and for a PUT with `Content-Type: image/png`. Integration
   `test_healthz` asserts HEAD 200 and `"error: ConnectionError"`. These run under the Verifier.

### P3 taken

  registered code `payload_too_large` (413), so error-codes.md now lists 12 codes. conventions.md

## Round 4 (micro-patch; review B00-r2 new findings)

1. **P2-1: settings are validated at boot.** `create_app()` installs a lifespan
   (`_validate_config_at_boot`) that calls `get_settings()` before serving. A missing `JWT_SECRET`, a
   prod secret under 32 bytes, or a prod OTP code now raises `ValidationError`, and uvicorn exits instead
   of serving. `export_openapi` and in-process tests do not enter the lifespan, so they need no secret.
   The README claim "the API does not start without it" is now true.
   - Test: `test_startup_refuses_missing_jwt_secret` runs in an empty cwd without `JWT_SECRET`. It
     enters the lifespan and expects `ValidationError`, then enters again with the secret set and
     succeeds.
2. **P3-1: empty OTP.** A `field_validator` turns `OTP_DEV_CODE=""` into `None`.
   - Test: `test_empty_otp_is_off_and_secrets_stay_hidden` checks that `""` becomes None and that prod
     accepts `""`.
3. **P3-2: secrets hidden in errors.** `hide_input_in_errors=True` is set on `SettingsConfigDict`. The
   same test checks that a rejected short prod secret does not appear in the error text.
4. **P3-3: `Allow` on 405.** On a 405, `Allow` is now derived, not hard-coded. It unions the partially
   matched route's methods (`scope["route"]`) with the methods in the app's OpenAPI path item for that
   path template.
   - Why: FastAPI 0.162 nests included routers (`_IncludedRouter`), so `app.routes` is not flat, and
     walking the private nesting would be fragile.
   - `/v1/healthz` now answers `Allow: GET, HEAD` (test `test_wrong_method_lists_get_and_head`). The
     existing `/num/{n}` 405 test still gets `GET`.
5. **P3-4: changelog and ledger.** The CHANGELOG line now starts with `WP-B00 —`. The hatchling row's
   purpose names both wheels (`agritrace_page` and the `agritrace` API package).

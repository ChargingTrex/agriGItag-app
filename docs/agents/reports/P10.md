## C. P07-2 live mode

1. `ok()` reads `r.text()` and parses JSON only when the body is not empty (the `204` of `otp/request`).
2. The OTP limit. The QC officer signs in over the API **once per Playwright worker** (`liveQc`, cached together
   with its moisture meter). The admin still signs in through the real form in both runs. `support.ts`
   `signIn` waits out the one-code-per-60 s limit before the second "Send code" in a worker (live only). The
   admin's API calls reuse the portal's own bearer token, read from its requests, so they need no extra OTP.
3. Live mode creates its own batch and **never touches FGP8T4033HM7** (the constant is gone). Per run:
   the CSV-imported farmer is approved in the UI. Then over the API: the admin sets the farmer's village address
   and adds a plot inside the GI region (`rainfed`) and a chilli lot; the QC officer records a 10.5 % drying-end
   moisture and a 20 kg intake (the intake runs the ready gate). The run reviews the flag that intake raised
   (`yield_check_unavailable`) in the UI, ticks the lot on Ready lots, picks the processor, creates the batch in
   the UI, and the QC officer grades it over the API. The page is then reloaded, because the batch page cached
   "not graded" for 30 s. Grading approval, final packing, publish and labels are done in the UI.
   The public page needs a village-level place and `farming_type`, and a name-only CSV row has neither.
   That is why the run sets the address and the farming type.
4. Staff PIN: `E2E_STAFF_PIN` (default 1234; mock always 1234). Documented in `playwright.config.ts` and
   `support.ts`. No `.env.example` was added: Playwright does not load one, and the portal has none.

**Field config (D-017).** `FieldRules` reads FieldConfig rows `farmer` and `plot` (enabled fields → required) and
`features` (`boundary_walk`) once when the wizard opens. A step whose fields are all disabled is skipped
(`OnboardingDraft.applies`); a required field blocks Next or the save buttons (`canLeave`); disabled fields are dropped
from the payloads. No config pulled yet → every field enabled, only the YAML `core` fields (name, pin, declared size)
block.

**Save (crop step).** First plot of a farmer: `farmerCreatorProvider` calls `POST /v1/farmers` through the generated
client; with no signal (DioException without response) the farmer gets a UUIDv7 and an Entries row of type `farmer`
carrying the `FarmerIn` JSON (`TODO(M02)`, documented in code and TODO.md). Then one Drift transaction writes the
local Farmers row (`status: pending`, `hasSmartphone`, language, photo path, phone in `json`), the `farmer` entry
(offline only), the `consent` entry (`ConsentIn` fields: farmer_id, consent_type `data_collection`, consent_version
`v1-<lang>`, recording_ref = the bundled clip, given_at; witness and device come from the token on the server) and the
`plot` entry (`PlotIn` without `client_id`: the entry id is the plot id; pin + accuracy, device/GPS time, declared area,
land record, closed walked Polygon, farming type, irrigation source, soil, gi_tag_id). Each goes through
`EntriesDao.save`, so each has its outbox row. All entries have `assistMode = true` (CLAUDE.md §6), location columns on
the plot entry, and `undoDeadline = createdAt` (registrations are corrected by the admin, not undone).

**Other changes.** `tool/no_textfield_lint.sh` now also checks `features/onboarding_farmer` and allows only
`officer_text_entry.dart` by path (verified: a probe `TextField` in that folder fails the lint). `DigitKeys` in
auth_step.dart is public and wraps each key in `MergeSemantics`: the sweep found the delete key's label sat on a
separate node from its tap action (an M06 latent a11y bug). 53 new ARB keys (ta + en, described). 13 placeholder clips
per language (copies of the 0.4 s tone) listed in `prompts.json` `clips` and `placeholders`. 8 placeholder WebP picture
cards (96 px, 252 B – 1.4 KB) under assets/images/{water,practice,crops}.

## Skipped or not checked

- **SMS code at step 1.** Not done: the API sends no SMS to a number without an account, and `otp/verify` on the
  officer's phone would replace the officer's session (D-024). The number is proved at step 9 when the farmer signs in
  on their own phone with the code. Needs an officer-scoped phone-check route (TODO.md, M09 → B02/B03).
- Real recordings (consent v1, 60-second tour, step prompts) and real photographs for the cards: placeholders only.
- Device GPS, camera and the boundary walk on real phones (Q01); every fix is kept on the walk, no accuracy filter.
- Farmer photo upload (`photo_key`): no route issues an upload URL; the photo stays in the camera cache (shortcut).
- Village picker (FR53): not among the 9 binding steps; `Farmers.village` is written empty.
- Deep link handling for the QR (scheme registration, PhoneScreen prefill), M08; "Add farmer" button on the officer
  home, M10. The route works when pushed.
- `flutter clean` was run at the end; no device build, no APK size check (assets added: ~40 KB of clips, ~6 KB of
  pictures, qr_flutter is pure Dart).

## Risks

- Offline farmers depend on M02 handling the `farmer` entry type (POST /v1/farmers first, then substitute the server
  id in the consent/plot push bodies). Until then those three entries cannot sync. A `client_id` on `FarmerIn` would
  remove the mapping (TODO.md).
- The draft is in memory: an app kill mid-wizard loses it (nothing half-saved, so no corrupt data).
- The phone's area is spherical (≈0.3 % from the server's ellipsoid); only the server value is stored and flagged.

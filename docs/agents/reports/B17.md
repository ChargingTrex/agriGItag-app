## What was done, and why

1. **B12 seed, GI hold that never cleared** (`apps/api/agritrace/seed/demo.py`). The seeded `Lot(...)` now sets
   `gi_eligible=True`, the same start as `lots_batches.service.create_lot` (eligible until a hold flag says
   otherwise). Before, the model default `False` with `gi_hold_reason=None` was a state `rules_flags.apply_hold`
   never restores, so publish ended `gi_verified=false` with `lot_on_hold` x3. These are the only two `Lot(...)`
   writers in `agritrace/`. The e2e test needed no change; it now passes with `gi_verified` true.
2. **B13 stale head** (`tests/integration/test_config_imports.py`). The test takes the head from `alembic heads`
   and checks that `alembic current` shows it, so the next migration does not break it again. `alembic check`
   is unchanged.
3. **B14 stale audit expectation** (`tests/integration/test_registry_b14.py`). The `farmer.reject` row is expected
   as `{reason_code, reason_text, devices_revoked: 0, membership_removed: False}`. These fields are intended:
   `registry.service._end_farmer_access` returns them and the reject docstring lists them (352b61c). The test
   farmer has no phone, so it has no account and the values are 0/False.
4. **B00-2 env leak** (`tests/conftest.py`). Restoring the variables when the session ends would not have been
   enough. `stack` is session-scoped, so its teardown runs after the unit tests that follow it. So:
   - `stack` records the old values of the variables it sets in `BEFORE_STACK`.
   - A new autouse fixture, `_without_stack_env`, uses `monkeypatch` to put those old values back for each test
     whose fixture closure does not include `stack`, for that test only.
   - `stack` also wraps itself in `mock.patch.dict(os.environ)`, so the variables are restored when the session
     ends.

   The cache clearing at setup is unchanged. In a unit-only run `BEFORE_STACK` is empty, so the new fixture does
   nothing.
5. **B00-1 retried CreateBucket** (`tests/conftest.py`). The three `create_bucket` calls are now one loop that
   ignores `BucketAlreadyOwnedByYou` and `BucketAlreadyExists`. This is the same "create unless it exists" rule
   as `infra/scripts/s3-init.sh`. Timeouts are not changed. `put_bucket_versioning` is idempotent and stays as it
   was. The non-evidence buckets now send `ObjectLockEnabledForBucket=False` explicitly; `test_storage.py`
   passes with this.

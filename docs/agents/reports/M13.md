## What was done

1. **Size.** Measured; no Gradle change was needed. The Flutter Gradle plugin already sets `isMinifyEnabled` and
   `isShrinkResources` for release (`FlutterPlugin.kt`), and an AAB splits per ABI/density/language by default. A
   comment in `android/app/build.gradle.kts` says so. The CI size step (`tool/size_check.sh`, fail > 100 MiB, warn
   > 40 MiB, AAB > 30 MiB when bundletool is on PATH) was already in `.github/workflows/ci.yml`; unchanged.
   bundletool 1.18.1 was run from the Gradle cache through a PATH shim (not committed).
2. **Cold start.** No `deferred as` imports (D-053): without Play deferred components Flutter keeps every library in
   `libapp.so` and `loadLibrary()` is a no-op, and Dart AOT globals are lazy, so the imports cost no start-up time.
   The decision is marked in `app_router.dart`.
3. **Low storage.** `MainActivity.kt` answers `in.agritrace/storage` `freeBytes` with `StatFs(filesDir).availableBytes`
   (no plugin, D-053). `lib/core/capture/free_space.dart`: `freeBytesProvider` (null when the platform cannot tell),
   `purgeIfLow` (< 100 MiB → `MediaDao.purgeConfirmed`, returns true) and `lowStorageAtStartProvider` (once per app
   start). The farmer home listens to it and opens the sheet; the camera step runs `purgeIfLow` after each photo.
   `MediaDao.purgeConfirmed` reuses M02's `purgeFullSize(keepThumb: false)` for every `done` (server-confirmed)
   photo only. The "Phone is full" sheet is now one function `showPhoneFull` (farmer_sheet.dart), also used by the
   camera step and the confirm screen (two copies deleted).
4. **Background sync proof.** `scheduleBackgroundSync` takes an optional `Workmanager` (tests pass a recording fake);
   the isolate body moved into `runBackgroundSync(input, overrides:)` so a test can run it.
5. **In-app update.** Not built: the API exposes no minimum app version (`/v1/healthz` and the bundle manifest carry
   none, checked). TODO line for the backend field plus the phone sheet.
6. **D-029 completion.** On a real user switch (previous `sync_user_id` set and different), `_forgetPulledRows`
   deletes Lots, Plots, Tasks and Flags in the same transaction that resets the cursor and bundles, except a lot or
   plot named by an entry that is not confirmed or undone. Farmers are kept: only M09's offline registration writes
   them and nothing pulls them back. M12 reminders reschedule from the emptied Tasks table by themselves.
   **M08 review item:** the lot pull keeps a local `ready_for_sale` only while a `packing` entry for the lot exists
   with status other than rejected/undone.
7. **Drift schema v3.** The Session token/PIN columns were written only as `''`/null to satisfy NOT NULL; dropped
   (`TableMigration(sessionTable)`, the signed-in row is copied). Dump `drift_schema_v3.json`, migration test v2 → v3;
   the v1 → v2 test now migrates through v3 (the app database always migrates to its current version).
8. **Crash hooks.** `_report` writes an `agritrace.crash` developer-log entry (plus the debug console line it had).
   Unawaited futures in bootstrap and in the sync engine's timers/listeners run in the root zone, so their errors
   reach `PlatformDispatcher.onError` → `_report` and the app keeps running; the background isolate's run is wrapped
   in try/catch (returns false). No new `catchError` was needed.

## How the tests work

- **One sign-in per run.** `Portal As Admin` (portal.robot) signs `+91 90000 00001` in through the real form: mobile,
  dev OTP, then "PIN", or on a fresh seed "Choose a 4-digit PIN" + "Type the PIN again" + "Save PIN and sign in".
  It keeps that page for the whole suite (`auto_closing_level=SUITE`). Every test calls it first, before its API
  fixtures, because `Login As` can wait out the 60 s code limit and the form cannot. If "Send code" is rate limited
  (a run right after another run), the keyword waits 61 s once. If the sign-in fails, later tests fail at once
  instead of spending more OTPs. A run spends 1 admin OTP in the UI, plus OTPs for `Login As` (admin, officer, QC)
  only when the cached API sessions are gone (`qa/robot/results/.api-sessions.json`).
- **Fixtures over the API**, from Q06's keywords plus two new ones in `agritrace_keywords.py`:
  - `Packed Lot`: lot, officer push of packing (and optional harvest), drying-end moisture, ready, intake. Ready lots
    previews shares from packed weight, so an API lot without a packing event shows "—".
  - `Grade Batch`: the QC officer grades, with or without one inline moisture reading.
  - `New Farmer`: gained `approve=False`.
  - Suite keywords: `Share Lots` (100/200/20 kg, made once), `Held Lot`, `Phone Reveals`, `Lot Should Be GI Eligible`,
    `Create Batch In The UI`, `Open Screen`.
- **Full page loads for Ready lots.** The portal caches lots and hold flags for 30 s (TanStack `staleTime`). A lot
  made seconds after an earlier visit is either missing or shown as tickable before its plot hold arrives (this
  failed my run 2). Each test therefore opens `/ready-lots` by URL. It never navigates before the previous page has
  shown API content, because of Q07-1.
- **Selectors:** Playwright role and label selectors through Browser (`role=button[name="…"]` is an exact name match;
  `internal:label=`). These are the ones the WEB Verifier used (docs/agents/qa/portal-live/scripts/portal-lines.spec.ts).
- **Self-test:** `qa/tests/test_scripts.py::test_portal_fixtures_send_the_right_bodies` checks that `Grade Batch`
  sends no reading unless given one and that `Packed Lot` pushes harvest before packing, with no stack.

## What was done

1. **D-040, QC intake by push.**
   - `IntakeIn.processor_id: UUID | None` (description "absent → the FPO's only own processor …"); `lot_id` and
     `IntakeOut.accepted_by_user_id` descriptions updated.
   - `create_intake` checks the role itself (`INTAKE_ROLES` = QC officer, FPO admin; else `forbidden`) and refuses
     a correction by anyone but an FPO admin (`forbidden`), before the resend lookup. Without `processor_id` it
     takes the one processor with `fpo_id` = caller's FPO (`LIMIT 2`); zero or several → `field_required`
     `{field: processor_id, entity: lot_intake}`. Shared processors are never picked by default. A first intake
     of an `open`/`drying` lot calls `mark_ready` as the last check (same transaction); its `moisture_gate_failed`
     refusal stands and nothing is written. `DECISION D-040` at the processor default and at the ready gate.
   - `create_intake_from_sync(session, user, data)` (in `__all__`) validates `IntakeIn` (422 `validation_error`
     with details, as `create_plot_from_sync`) and calls `create_intake`.
   - Push kind `lot_intake` → `events.service._push_lot_intake` (commits per entry; `accepted`/`duplicate`;
     `server_id` = intake id). `DECISION D-040` at the handler.
   - `POST /v1/intakes` dependency `require_role(QC_OFFICER, FPO_ADMIN)`; description, 403/409/422 docs and
     docstring updated.
   - `IntakePayload` documented as a timeline note that receives nothing (no behaviour change).
2. **D-041, GI-only holds.** `GI_ONLY_HOLD_CODES = frozenset({"plot_outside_gi_region", "yield_over_ceiling"})`
   with `DECISION D-041`; one predicate `_blocks(flag, gi_label_requested)` used by `hold_reasons(flags,
   gi_label_requested)` and `_approval` (records every active flag that did not block). `approve_grading`,
   `final_packing` and `publish` pass `batch.gi_label_requested`. `_gi_check` unchanged.
3. **D-042, assist per kind.** `_entry_caller`: `NO_ASSIST_KINDS` (`farmer`, `flag_resolution`, `assist_session`,
   `lot_intake`) drop the assist context without a session lookup (`DECISION D-042`). `quality.create_reading`:
   with `on_behalf_of_farmer_id`, a reading on another farmer's lot or any batch reading → `forbidden`
   (`DECISION D-042`; the header path gets it too). `events._check_subject`: a batch event in assist mode →
   `forbidden`. `SyncEntry.kind`, `data` and `assist_session_id` descriptions, the push route description and
   docs/api/conventions.md §Sync updated.
4. No migration, no new library, no new error code (49 codes; `forbidden`, `field_required`, `gate_not_met`,
   `not_found`, `validation_error`, `client_id_conflict` reused). OpenAPI and error-codes.md regenerated.

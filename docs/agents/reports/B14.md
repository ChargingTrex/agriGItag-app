## What was done (the five outputs, all additive inside `/v1`, D-020)

1. **Masked phone + audited reveal.** `FarmerOut.phone_masked` (`XXXXXX` + last 4 digits of
   `users.phone`, null without an account) on every farmer response: list (one outer join), get, create,
   update, approve, reject. `GET /v1/farmers/{id}/phone` → `FarmerPhoneOut {farmer_id, phone}`, FPO admin
   only (`require_role(FPO_ADMIN)`, so a field officer gets 403), same FPO else 404 (`_farmer_in_scope`).
   Every call writes an explicit `audit_log` row (`action=farmer.phone_reveal`, `entity_type=farmers`,
   actor/assist/device from the caller; the number is not logged). `DECISION D-017` comments in the
   schema and the route. `FarmerOut` is used by no other module, so the sync bundle and public pages do
   not get the phone (checked by grep).
2. **Reject.** `POST /v1/farmers/{id}/reject {reason_code, reason_text?}` (FPO admin). The
   `farmers.status` CHECK allows only `pending|active|suspended`, so a rejection sets **`suspended`**
   (no migration, no new enum value) and writes an `audit_log` row `farmer.reject` whose `diff` is the
   reason; the flush listener also writes the usual `update` row for the status change. A non-pending
   farmer → 409 `farmer_not_pending` (reused). `DECISION D-020` comment in `reject_farmer`.
3. **Farmer plots.** `GET /v1/farmers/{id}/plots` → `Page[PlotOut]`, keyset cursor on plot id (registry's
   own `encode_cursor`/`_page`), farmer scope as for `GET /v1/farmers/{id}`. `PlotOut.gi_tag_id` already
   existed (B13). **`crop_id` was not added:** crops point to GI tags (`crops.gi_tag_id`), so one GI tag
   can map to several crops and there is no unique plot → crop. The portal picks the region to draw from
   `gi_tag_id` (`GET /v1/gi-tags/{id}/region`), which is what it needs.
4. **Server-side filter/search + `?fields=`.** `GET /v1/farmers?village_id=&q=&fields=` with the existing
   cursor. `q`: case-insensitive contains over name, local name and code; 1–4 ASCII digits also match the
   phone's end (only the suffix `phone_masked` already shows, so a search cannot probe hidden digits).
   `fields`: whitelist = `FarmerOut` fields and computed fields minus fields the tenant's
   `fields/farmer.yaml` disables (`fieldconfig.fields_for`); unknown names → 422 `validation_error` with
   `details.allowed`. Trimmed pages are returned as a `JSONResponse` built with
   `model_dump(include={"items": {"__all__": keep}})`; the OpenAPI schema stays `Page[FarmerOut]` and the
   query description says items then carry only those keys (also in conventions.md).
5. **FPO bbox.** New `GET /v1/fpos/{id}` (own FPO; super-admin any; else 404) → `FpoOut` with
   `bbox: [min_lon, min_lat, max_lon, max_lat]`: `ST_Extent` of the FPO's plots (walked outline where
   there is one, else the pin, `::geometry` casts, `CAST(:fpo_id AS uuid)` for asyncpg), else `ST_Extent`
   of every GI tag's latest effective region version, else null. `bbox` is null on `GET /v1/fpos`. The SQL
   sits in `service.py`, not `geo.py`, because `geo.py` is outside the declared paths.

No new libraries, migrations or config. Round 1 added no error codes; round 2 adds `account_inactive` (see below).

## Risks

- A rejected farmer is `suspended` like a later suspension; only the audit action tells them apart. The
  rejection also does not touch the farmer's `users`/`memberships` rows (approve does not either), so a
  rejected farmer with a phone can still sign in to the farmer app. Decide in P02/B-next if that matters.
- The bbox fallback frames every GI tag's region, because `fpos` has no GI link (a `shortcut:` comment is
  in the code). With one plot the box has zero size and the portal must pad it.
- `request_id` is not copied to the explicit audit rows (same shortcut as B06).

**P2-R: a rejected farmer loses sign-in.** Identity edits were the declared exception for this round.
- `reject_farmer` → `_end_farmer_access`: deletes the farmer's `memberships` row for that FPO (role
  `farmer` only, so an office role is kept). The listener audits the `delete`. When the user has no
  membership left, `revoked_at` is set on all their open devices and the refresh hashes are cleared, the
  same as identity's sign-out. `current_user` reads the device row, so the next request gets 401
  (`device_revoked`), and refresh fails too. The `farmer.reject` audit diff now also has
  `membership_removed` and `devices_revoked`. The D-020 DECISION text and `Side effects:` are updated.
- `core/errors.py`: new `AccountInactiveError` (`account_inactive`, 403, `error.account_inactive`, fix:
  "Your FPO has not approved this account; contact the FPO office.").
- `identity.verify_otp`: the attempt now counts as matching when the code is right **and a `users` row
  exists**. Only after that check: if the user has no active account (no membership, or suspended), the
  challenge is spent and 403 `account_inactive` is returned. A wrong code still gets `otp_invalid`, and an
  unknown phone gets `otp_invalid` even with the right code. `DECISION D-024` comment.
- `identity.request_otp`: sends the SMS to any known `users` row looked up by phone (not via `_account`),
  so the answer can be reached. The response is still 204 for every phone.

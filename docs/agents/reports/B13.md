## What was done

- **YAML config (D-017)**, `apps/api/config/`:
  - `fields/` holds farmer, plot, lot, quality_reading, village, input, and `event_<type>` for all 11 event
    types. Each field has `name`, `type`, `required`, `enabled`, `visibility`, `label {en, ta}` and `stage`.
    Fields with `core: true` (NOT NULL in the database) cannot be disabled or made optional by a tenant.
    `extra: forbid` on farmer, plot, village and input; `extra: allow` on the others, because B06 owns
    the event payload shape.
  - `features.yaml` has all 9 flags. Each line says which module reads it. Only `id_document_capture`
    and `producer_groups` are wired; the rest are declared with a "not wired yet" comment.
  - `tenants/VIRUDHAI_SCFC_VINOBA_BHAVA_FPO.yaml` turns off `plot.soil_type`.
- **`core/fieldconfig.py`**: the schema is Pydantic models with `extra=forbid`, so any unknown key is an
  error. It provides:
  - `parse(dir)` and `load()` (cached);
  - `fields_for`, `features_for`, `required_fields` and `public_fields` (tenant overrides are ignored
    on purpose: a tenant can hide a field but never make it more public);
  - `validate_payload(entity, fpo_code, data)`: drops disabled fields, raises `field_required` (missing
    or blank) and `field_unknown` (only under `forbid`);
  - `bundle_part(fpo_code)` for B07, as bundle part `fields`, and `etag()`.
  - Tenant files are checked when loaded: the file name must equal `fpo_code`, entities, fields and
    feature keys must exist, and core fields cannot be relaxed.
  - **Start-up refusal:** `main._validate_config_at_boot` calls `fieldconfig.load()`. An invalid file
    raises `ConfigInvalid` with a message that starts with the file path and the failing key. The class
    has no `Error` suffix because the error-code generator treats every `raise *Error` as an HTTP code.
- **Endpoints**:
  - `GET /v1/config/fields?entity=` and `GET /v1/config/features` live in `modules/config/router.py`.
    The logic stays in core; the router sits in `modules/` only because routers are mounted by discovery.
    The tenant comes from the token (one FPO-code read). Responses carry a strong ETag, and a matching
    `If-None-Match` gets 304.
  - Hooks in `registry.create_farmer` and `create_plot` (`DECISION D-017` comment at each). The body is
    passed through `validate_payload` and re-validated, so a disabled field falls back to its schema
    default and a required one gives 422. For plots this runs after the resend check, so a stored plot is
    still returned if the config changed later.
- **Migration `0003_masters`** (revises `0002_identity_pin`): adds `plots.gi_tag_id`, a nullable foreign
  key to `gi_tags`, and nothing else. The docstring has the backfill SQL (not run). No index is needed.
  - `Plot.gi_tag_id` was added to the model so `alembic check` stays clean.
  - `create_plot` and `correct_plot` store the GI tag; an unknown id gives 422.
  - `_check_region` now gets the plot's stored GI tag. The single-GI fallback and its `shortcut:` comment
    remain for plots that have none.
  - `PlotOut.gi_tag_id` was added (additive change).
- **Bulk import**, `registry/imports.py`: one parser per kind sharing the `_run` row-report helper.
  - Every row runs inside a SAVEPOINT. A commit writes all valid rows in one transaction; a dry run takes
    the same path and then rolls back, so it also catches database-level conflicts.
  - Limits: 2 MB and 5,000 rows (`import_too_large`). Files must be UTF-8; a BOM is accepted.
  - Farmers go through `create_farmer`, so the same rules as onboarding apply. They pick a village with
    `village_lgd_code`.
  - Villages: super-admin only, keyed on `lgd_code`. Inputs: keyed on name + manufacturer
    (case-insensitive) and go through `create_input`. Re-runs report `import_row_exists`.
  - Templates are built from the tenant's enabled, CSV-capable fields.
  - Sample fixture: `seed/fixtures/villages_virudhunagar.csv`, with fake `SAMPLE000n` LGD codes and no
    PIN codes.
- **Flag-gated routes**: `POST /v1/farmers/{id}/id-documents` and `GET/POST /v1/producer-groups`. The gate
  is a route-level dependency that runs before the role check and the body, and answers 404
  `feature_disabled`.
  - An ID document needs the farmer's unrevoked `data_collection` consent. It writes an `id_documents`
    row and returns one presigned PUT into `S3_BUCKET_IDDOCS`.
  - To support that, `storage.presign_put` gained an optional `bucket=` argument (backward compatible).
- **Farmer code fix** (TODO.md B03 shortcut): `_new_farmer_code` draws a new code on a collision. Without
  this, a 5,000-row import would hit UNIQUE(fpo_id, code) about half the time.
- **Error codes** (6 new): `field_required` 422, `field_unknown` 422, `feature_disabled` 404,
  `import_too_large` 413, `import_row_invalid` 422, `import_row_exists` 409.
- **Libraries**: `pyyaml` (it was already transitive; now a direct dependency) and `python-multipart` are
  runtime dependencies; `types-pyyaml` is a dev dependency. No jsonschema.
- **Docker**: the Dockerfile now copies `config/`.
- **Docs**: `docs/api/conventions.md` §Config, `docs/LIBRARIES.md`, CHANGELOG, TODO.md (2 items closed,
  6 added).

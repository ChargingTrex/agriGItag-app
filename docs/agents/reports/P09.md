| Finding | What changed | Why | Test |
|---|---|---|---|
| 1 (P1) `device_in_use` locks staff out of a shared PC | `authApi.ts` `verifyOtp`: on `ApiError` `device_in_use` remove `DEVICE_ID_KEY` and verify once more with a fresh `deviceId()`; a second 409 is thrown as before | A browser closed without "Sign out" leaves the device row bound to staff A; a new id signs nobody out (B02 rule holds) and the 409 is raised before the OTP is spent | `auth.test.tsx` "retries once with a fresh device id…": MSW answers 409 to the first verify (`server.use(..., { once: true })`), the second carries a new id, which is stored, and the PIN step opens |
| 4 (P2) sign-out fails silently | `AuthProvider.tsx` `signOut`: waits for `logout`; on 401 trades the refresh cookie for a live token and logs out with it (cookie dead too: nothing to revoke, local clear); any other failure keeps the session and shows `Could not sign out. <errorMessage>` in an MUI `Snackbar` + `Alert` (rendered by the provider, so no layout change). Mock logout now returns 401 unless authorised | Clearing only local state left the cookie and device binding for the next person (reload = signed in as A) | `auth.test.tsx` "keeps the session and says so when sign-out fails…": network error → alert, Dashboard stays, mock still signed in; second click gets 401 → refresh → logout → sign-in page |
| 5 (P2) 5xx/429 on refresh signs out | `endIfRejected` signs out only on `ApiError` 401/403; anything else resets the single-flight marker so the next call or timer retries | A proxy 502 during a deploy sent users to /login and cost an OTP | `session.test.tsx` "keeps the session when the scheduled refresh gets a 503" |

Also: the 401-loop branch of `recover` now marks the token before `signOut`, because sign-out is no longer synchronous and concurrent 401s must still produce one logout.

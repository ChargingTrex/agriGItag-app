## 1. CSV import: database data errors are row rejections (P3-2)

- `registry/imports.py` `_run` (imports live in registry, not `modules/config`): a `DBAPIError` raised inside
  a row's SAVEPOINT that `core.errors.data_error` maps (SQLSTATE class 22: NUL, out of range) becomes
  `ImportRowError(row, code="validation_error", field=None)`; any other `DBAPIError` is re-raised (500,
  router rolls the file back). The savepoint has already rolled the row back, so semantics are unchanged:
  accepted rows are written, a rejected row leaves nothing.
- Test `tests/integration/test_config_imports.py::test_database_data_errors_are_row_rejections`: inputs CSV
  with a NUL in `name_en` (row 3) and `pack_size` 10^13 beyond NUMERIC(12,3) (row 4) between two good rows
  → 200, accepted 2, rejected rows 3 and 4 `validation_error`, 2 rows written. No integer column is
  CSV-importable, so the numeric overflow stands in for "int overflow" (both SQLSTATE 22003).

## 2. One audit helper (P3-5)

- `core/audit.py` `write_audit(session, caller, action, entity_type, entity_id, diff, gps=None)`: registry's
  `_audit` moved to core, keeping its `request_id` shortcut note. `CurrentUser` is a `TYPE_CHECKING`
  import (core.auth imports core.audit).
- Replaced all three hand-written `insert(AUDIT_LOG)` calls: registry `_audit` (deleted; `reveal_phone`,
  `reject_farmer`), events `_write_version` push audit, identity `revoke_device`. Same action names,
  entity types, actor/assist/device ids, diff and GPS. `_sign_out` writes no audit row. Grep of
  `AUDIT_LOG` / `AuditLog(` shows only the listener and the helper left.
- One difference: the push audit row's `at` is now `utcnow()` at insert time instead of the
  `server_received_at` value taken earlier in the same call (microseconds apart; nothing joins on it).

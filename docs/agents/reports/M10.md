## Skipped / not checked

- Flags: no voice-note reason, no photo or map on the flag detail (UserFlows "Clearing a flag" steps 1 and 3), and no optional note. "Fix it" corrects only the bag count (shortcut comment).
- "Fix it" needs the event on the officer's phone. Pulled events cannot become Entries yet (B07 pull gap in TODO).
- `POST /assist/end` is not queued offline (shortcut, D-032 allows it). Assist mode is in memory, so an app restart drops it (D-044 "Revisit when").
- Instruments are fetched by the moisture screen itself (moisture meters, one page), not by the sync pull. The moisture reading has no GPS and no meter photo.
- M02 hand-offs not taken: officer "retry needs_attention entry", 7-day unsent red triangle.
- Device checks (Go AVD assist flow, real GPS distance, Android predictive back on the PopScope) → Q01. All of these are TODO.md lines ("M10 follow-ups").

## Risks

- The phone's `enteredRemotely` is pin-radius only. On a big walked plot it can say "remote" where the server does not. It is a local preview; the server recomputes `entered_remotely` and the push does not send it.
- A correction copies the original's location but has no photo. If B08's photo rule fires on corrections, "Fix it" could raise a new flag. This was not checked against the backend.
- `/assist/end` sent right after an offline start answers 404 until the outbox pushes the `assist_session` entry, and the server session stays open.

## What was done

1. **Dependencies** (`pubspec.yaml`): `drift ^2.31.0`, `drift_flutter ^0.2.8`, `uuid ^4.6.0` (was transitive);
   dev `drift_dev ^2.31.0`, `build_runner ^2.15.1`. `path_provider` and `sqlite3_flutter_libs` are **not** declared:
   `drift_flutter` brings both and does the documents-directory lookup itself (ledger row says so).
   `flutter pub add` also wrote the CocoaPods hooks (`ios/Podfile`, `#include?` lines in `ios/Flutter/*.xcconfig`),
   which is what Flutter needs for the first plugin on iOS.
2. **Tables** (`lib/core/db/tables/`), exactly the 14 of §2: `session.dart` (SessionTable → SQL `session`, CHECK
   id = 1, `Role` enum reused from the router), `registry.dart` (Farmers, Plots, Lots), `entries.dart` (Entries,
   Media + `EntryStatus`, `LocationStatus`, `UploadStatus`), `outbox.dart` (Outbox + `OutboxKind`, `OutboxStatus`),
   `sync.dart` (RefBundles, SyncState, SyncMetrics), `field_work.dart` (Tasks, Flags, Instruments, FieldConfig).
   Indexes: `entries_lot_status`, `entries_root_version` (**unique**, so two corrections of the same version cannot
   both land), `outbox_status_next`, `media_entry`. `///` on every column with units. `DECISION D-014` on Entries,
   `DECISION D-005` on `Entries.entryId` and `Media.mediaId`. Status columns that the phone drives are Dart enums
   (`textEnum`, stored as the enum name, e.g. `needsAttention`); server-owned statuses stay text.
3. **Append-only guard** (`tables/append_only.drift`, included by the database): trigger `entries_facts_immutable`
   aborts any UPDATE of an entry's fact columns (everything except `status`, `server_received_at`), trigger
   `entries_no_delete` aborts DELETE. They mirror the server triggers of D-005 and are part of the schema dump.
4. **Database** (`database.dart`): `AppDatabase(executor)` for tests, `AppDatabase.open()` via `driftDatabase(name:
   'agritrace', shareAcrossIsolates: true)` so M02's WorkManager isolate shares one connection; `schemaVersion = 1`;
   `MigrationStrategy` with `onCreate: createAll`, a documented `onUpgrade` skeleton (throws for unknown steps),
   `beforeOpen` turning on `PRAGMA foreign_keys` (Media.entryId → Entries).
5. **DAOs** (`daos/`), only the listed operations, each with params/returns/throws/side effects:
   - `EntriesDao.save(entry, media)` – one Drift batch (atomic): entry forced to `saved`, media to `pending`, outbox
     rows entry priority 0 then media priority 1, idempotency key = client UUID, due at `createdAt`.
     `markSent`, `markConfirmed(id, serverReceivedAt)`, `markRejected(id, error)` move the entry **and** its outbox
     row together (rejected → outbox `needsAttention` + `lastError`, since Entries has no error column).
     `markConfirmed` keeps an `undone` entry undone but stores `serverReceivedAt`. `latestVersions(lotId)` = rows no
     other row supersedes, ordered by rootId (UUIDv7 = creation order). `undo(id, now:)` checks exists / not an undo
     / not undone or rejected / no newer version / `now < undoDeadline`, then writes an `undo` version (root, v+1,
     supersedes) with its outbox row and marks the original `undone`; throws `StateError` otherwise, writes nothing.
   - `OutboxDao.nextBatch(now:, limit = 50, maxBytes = 256 KB)` – waiting rows due ≤ now, `priority, seq` order,
     joined to their entry/media; size = UTF-8 bytes of payload or media bytes; stops before exceeding the cap but
     always returns the first row. `markSending(seqs, now)` (attempts + 1, start time kept in `nextAttemptAt`),
     `markWaiting(seq, backoff:, now:, error:)`, `markConfirmed(seqs)`, `markNeedsAttention(seq, error)`,
     `resetStaleSending(now:, olderThan = 5 min)` → count, `pendingCount()` → `Stream<int>` of status ≠ confirmed.
   - `MediaDao.pendingUploads(limit)` (pending/failed, not purged, entry has `serverReceivedAt`), `markUploaded(id,
     objectKey)`, `purgeFullSize(id, now:, keepThumb = true)` (refuses with `StateError` before upload; DB first,
     then deletes files).
   - `RefBundlesDao.upsert/get/versions`, `SyncStateDao.get/set`, `SyncMetricsDao.record/unshipped/markShipped`,
     `TasksDao.nextForFarmer` (Stream, earliest due), `FlagsDao.openForFarmer` (Stream), `FieldConfigDao.get`.
6. **DateTime storage**: `build.yaml` sets `store_date_time_values_as_text: true` (ISO-8601 with ms). Whole Unix
   seconds (Drift's default) are too coarse for the "Sent ≤ 5 s" metric and the three clocks. Drift compares text
   dates through `julianday()`; ordering in DAOs uses `column.julianday`. Explained in `build.yaml` and README.
7. **Schema dump**: `test/db/drift_schemas/drift_schema_v1.json` + `test/db/generated/` (drift_dev `schema dump` /
   `schema generate`), `tool/schema_dump.sh` regenerates all of it (build_runner, dump, helpers, `dart format`).
   `test/db/schema_test.dart` creates a fresh database from the current code and validates it against the dump of
   `schemaVersion` with `validateDropped: true`. **Checked that it bites**: with `entries_no_delete` removed from the
   dump helper the test failed with `Contains the following unexpected entries: entries_no_delete` (restored after).
   Without `validateDropped` it did not fail, hence the option.
8. **Tooling**: `analysis_options.yaml` excludes `test/db/generated/**` (drift_dev helpers trip `strict-raw-types`,
   which `ignore_for_file: type=lint` does not cover). Drift's `lib/**/*.g.dart` carry their own lint ignore and are
   formatted at 120 by `tool/schema_dump.sh` so CI's `dart format --set-exit-if-changed lib test` passes.
9. **Docs**: README "Offline store" section, `lib/core/db/README.md`, 6 ledger rows in `docs/LIBRARIES.md`, CHANGELOG
   line.

**Insert timing (host, in-memory, 500 separate `save` calls each with 1 photo, after a 20-save JIT warm-up):**
1518 ms, 1590 ms, 1629 ms in the three full runs above under load average ≈ 24. A standalone probe on the same
host gave 642–1009 ms warm and 1358–1960 ms cold (first run, JIT), and 452–842 ms when all 500 saves share one outer
transaction. Switching `save` from three awaited inserts to one Drift batch roughly halved the per-save cost.

media confirm; nextBatch order + due filter + limit; byte cap and first-row rule; backoff + needsAttention; kill-safety

## Decisions and deviations to review

- `undo` row: `entryType = 'undo'` (`undoEntryType`), same root, v + 1, empty payload `{}`, no location, author fields
  copied from the original (the server takes the author from the token anyway), `undoDeadline = now`.
- `latestVersions` returns the `undo` row for an undone event (literal "latest non-superseded"); callers hide it.
- `markSending` stores the attempt start in `nextAttemptAt` instead of adding a `sendingSince` column (§2 has none).
- `nextBatch` does not filter media by entry confirmation; `MediaDao.pendingUploads` does. M02 may want
  `nextBatch` to return entries only; that is a one-line `kind` filter when it decides.
- `entries_root_version` index is UNIQUE (stricter than §2's plain index) to refuse forked versions locally.
- No new DECISION numbers; the text-date choice is a `build.yaml` comment, not an ADR.

## Risks

- The 2 s host assertion has ~0.4 s headroom only when the machine is loaded like today; on a busy CI runner it
  could flake. Relax it or run the perf test alone if it does; the binding number is Q01's on the Go AVD.
- `Session` keeps `accessToken`/`refreshToken` in plain SQLite as §2 specifies; M06 should decide on the
  keystore (flutter_secure_storage) before release.
- build_runner's AOT build script fails on this host; `tool/schema_dump.sh` uses `--force-jit`. The Homebrew `dart`
  first on PATH cannot run build_runner for this Flutter package; the script resolves the Flutter SDK's `dart`.

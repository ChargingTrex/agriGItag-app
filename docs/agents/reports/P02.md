## What was done

- **Flags list** (`/flags`, `FlagsPage.tsx`):
  - Filters live in the URL. Status (default Open; "All statuses" sends nothing), severity and assigned role go to the server. Rule code and subject (`?subject=<ids>`) filter the loaded pages in the browser (`shortcut:`, because B08 has no such parameters).
  - Each row shows: a severity chip (glyph ■/▲/● + colour + word), the en label linking to the detail with the ta label under it (`lang="ta"`), the subject (plots and lots link to their pages), the raised date as "14 Feb", the assignee and the status.
  - Cursor paging uses the existing `useCursorList` with "Load more".
- **Flag detail** (`/flags/:id`, `FlagPage.tsx`):
  - `details` laid out per family:
    - yield: harvested kg, declared acre, computed kg/acre, ceiling, warn/hold margins;
    - quantity: the chain `harvested → packed → received → used` with units, plus the out-of-tolerance links;
    - practice: declared vs derived tags and the input categories;
    - location and the rest: key/value pairs, plus a "Review the plot on the map" link for plot flags.
  - Lot flags show the lot's GI state and evidence thumbnails. Only the presigned `thumb_url` opens `medium_url`; the original JPEG is never used.
  - Resolve form (react-hook-form + zod, native selects): outcome, coded reason (both required, with inline messages), note.
  - The role gate mirrors the API (`resolveBlock`, `DECISION D-006` comment): an officer sees a hold or escalated flag with the form disabled and the reason. Success invalidates every `['flags']` and `['lots']` query, so the list, the lot's GI state and the detail refresh without a reload.
  - A resolved flag shows its outcome, date, reason and note.
- **Lot page** (`/lots/:id`, `LotPage.tsx`): `LotHoldState` (On hold / GI eligible), the lot's flags table, a link to its open flags, and the evidence photos. `useLotHold(lotId)` is exported for P03.
- **Plot review** (`PlotReview.tsx`, rendered on the P01 plot page under the existing MapLibre map with the pin and GI outline; satellite stays off by default, D3):
  - Shown for every plot that is not `confirmed`, so map pin / needs_review / near_edge / outside.
  - Fields: outcome (approve / keep for review), method (land record / satellite / field visit), reason (required) and a note, plus an optional corrected pin (both coordinates or neither). It sends `POST /v1/plots/{id}/correct`.
  - FPO admin only: an officer sees the form disabled with the reason.
  - After saving: "Review saved.", the revision line updates ("Revision 2, last reviewed on …"), and plots and flags refetch.
  - A "Open flags on this plot" link.
- **Farmer page:** lists the farmer's plots from B14's `GET /v1/farmers/{id}/plots` (code + location chip) and links to "Open flags on these plots" (`/flags?subject=<plot ids>`). This replaces the P01 TODO.
- **Routes:** `/flags`, `/flags/:flagId`, `/lots/:lotId`; the Flags placeholder is gone.
- **Mocks** (`handlers.ts`, typed from the spec):
  - `GET /v1/flags` with status/severity/assignee/cursor, `GET /v1/flags/{id}`, and `POST …/resolve`, which returns `reason_required`, `flag_not_open` and `resolution_forbidden` the way the B08 router does;
  - `GET /v1/lots/{id}/events` with a photo variant, `GET /v1/farmers/{id}/plots`, and `POST /v1/plots/{id}/correct` (admin only, `reason_required`; an accepted review closes the plot's open flags as `rule_passed`, like `rules.check_plot`);
  - `mockState.roles` drives the session's roles;
  - six seed flags cover every family; a second, map-pin plot was added.
- **Test infra:**

  - `@vitest/coverage-v8` (dev) backs `npm test -- --coverage`, which prints a text report only.

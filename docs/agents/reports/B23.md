## 1. Absolute session lifetime

- `core/config.py`: `session_max_days` (`SESSION_MAX_DAYS`, default 30, `ge=1`). It is a security
  setting, not a D-017 field flag, so it is not in `config/*.yaml`.
- `core/errors.py`: `SessionExpiredError` (`session_expired`, 401, `error.session_expired`, fix "Sign in
  again with an OTP.").
- `identity/service.py` `refresh`: when the presented token is the device's **current** one (`ok`) and
  `signed_in_at` is older than `SESSION_MAX_DAYS`, or was never stamped (fail closed), the device is signed
  out (`_sign_out`, commit) and the answer is 401 `session_expired`. A guessed token (`invalid`) and a
  rotated-out one (`reused`) keep their earlier answers, so knowing a device id still cannot sign it out
  (B02-r1 R4a). `DECISION D-024` comment marks the choice.
- Clients: **no change needed.** The phone's `session.dart` `_doRefresh` ends the session locally on any
  401 from refresh (`_endLocally(sessionEnded: true)`). The portal's `AuthProvider.tsx` `endIfRejected`
  calls `signOut()` on any `ApiError` with status 401. Neither looks at the code.

## 2. Device revocation route

- `POST /v1/devices/{device_id}/revoke`, 204, optional body `DeviceRevokeIn {reason ≤ 500}`.
- `service.revoke_device`. Who may call it:
  - The device's own user, any role.
  - Otherwise the device's user needs a membership in the caller's FPO, or the answer is 404 (no existence
    leak across FPOs).
  - Inside the FPO, only `fpo_admin` may revoke; anyone else gets 403.
- It reuses identity's `_sign_out`, the helper logout and refresh-reuse use (registry's `_end_farmer_access`
  copies the same three assignments because D-004 keeps `_sign_out` private). It sets `revoked_at` only when
  the device is not already revoked.
- It writes an explicit `audit_log` row: `device.revoke`, entity `devices`, actor, assist ids, caller's
  device, diff `{user_id, reason}`. `Device` is not `Audited`, so the flush listener writes nothing.
- After a revoke, `refresh` with that device's token is 401 `unauthorized` (existing `revoked` path), and the
  next request with its access token is 401 (`_device_active`).
- ~~Skipped: `GET /v1/users/{id}/devices`.~~ Added in round 2 (review P2-1): without it nobody could learn
  a lost device's id.

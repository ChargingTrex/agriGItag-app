The two extra P3 fixes are sound:
- **P3-1, OTP key.** It is now `HMAC(JWT_SECRET, b"agritrace-otp-v1")`, so the OTP hashes and JWT
  signatures use different keys (domain separation). The only cost is that codes in flight at deploy
  time become invalid, and they expire within 5 minutes anyway.
- **P3-3, 30 s leeway.** It is applied in `jwt.decode`. Expiry is extended by at most 30 s, so the access
  token lives at most 15:30 and the pin token at most 5:30. `iat` may then be up to 30 s in the future.
  Both are acceptable, and D-024 records the leeway.

Migration 0002 has a single head (`0002_identity_pin`). It adds 5 columns, 3 on `users` and 2 on
`devices`, all nullable or with a constant default. The downgrade drops all 5, in reverse order. It
touches nothing else.

## New findings

No new P1 or P2.

### P3

- **P3-14. The `signed_in_at` check uses whole seconds and does not allow for clock skew.**
  - Whole seconds: a token issued in the same second as the next sign-in still passes. That covers a
    pre-logout access token, or a `pin_token` replayed right after its PIN succeeded. Exploiting this
    needs a token captured inside a 1 s window, plus the PIN in the `pin_token` case.
  - Clock skew: `signed_in_at` comes from the clock of the container that ran the sign-in, and the
    30 s `LEEWAY` does not apply to this comparison. If a refresh then runs on a container whose clock is
    behind, its new access token can fail with `device_revoked` until the clocks catch up.
  - Fix, if wanted: compare against `signed_in_at - LEEWAY` and stamp `signed_in_at` from the DB clock
    (`func.now()`). Most of this is an availability problem, so it can wait for the Verifier's
    multi-container run.
- **P3-15. The per-phone daily cap lets anyone block a victim's sign-in.** Sending 10 `otp/request` calls
  for a victim's number stops that person from signing in for up to 24 h. This is the usual trade-off
  for a per-phone limit. The D-024 "Revisit when" line already plans per-IP limits for SMS abuse; it
  should also cover this lock-out case.
- **P3-16. Wording.** The `/v1/auth/otp/verify` 200 description still says "`pin_required` for office
  roles". Super-admins get it too (R7). This is one word in OpenAPI.

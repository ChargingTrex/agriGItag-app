## What is right (checked, no action)

- **Theme** (`app_theme.dart`): `useMaterial3: true`, `ColorScheme.fromSeed(Colors.green)`, no dynamic colour
  (a comment explains why), `materialTapTargetSize.padded`, `FarmerTokens.farmer` registered.
- **FarmerTokens** are 56 / 64 / 16, and `copyWith`/`lerp` are correct. **Status glyphs** pair a shape with a
  colour (tick / open circle / triangle), and the contrast figures are stated.
- **Text scale**: `MediaQuery.withClampedTextScaling(1.0, 1.5)` in `MaterialApp.router.builder` covers every route.
- **FarmerButton**: it is full width (`Expanded`), its height comes from the tokens, it has an icon, and a ≤ 2-word
  assert covers Tamil whitespace too. The speaker slot is ≥ 56 dp square. `Semantics(label: playVoice)` comes from
  `AppLocalizations`, so it follows the current locale, and `MergeSemantics` keeps label and action on one node. A
  disabled speaker until M05 is a documented `shortcut:`.
- **Router**: one table plus one pure `redirectFor`. A prefix trap (`/homework`, `/qcx`) is tested. The farmer
  cannot reach `/officer`, `/qc` or `/assist/*`, and a field officer can open `/assist/:farmerId`. Because the
  redirect is top-level, it also covers an initial (cold) location. Query strings are ignored (`matchedLocation`).
- **l10n**: `app_ta.arb` is the template, `preferred-supported-locales: [ta]`, and the session starts in `ta`.
  `required-resource-attributes: true` makes a missing `@description` a build error, and all 8 keys have one in
  both files.
- **dio**: connect 10 s, receive/send 30 s, `X-Device-Id` in BaseOptions, `AuthInterceptor` reads the token per
  request. There is no `LogInterceptor` and nothing logs headers. The generator's own auth interceptors are
  disabled (`interceptors: const []`). The 503 test confirms the signed-out request has no Authorization header.
- **Config**: dart-defines only (`API_BASE_URL`), with no flavor plugin. Staging and prod fail fast without the URL.
- **pubspec hygiene**: 5 third-party dependencies, all used. `cupertino_icons` was removed. Riverpod without
  codegen is accepted per the D-013 COMPROMISE comment in `session.dart`.
- **minSdk 26** has a D-002 comment. iOS deployment target is 13.0 in all three configs. `CFBundleLocalizations` is ta/en.
- **CI job**: Flutter is pinned at 3.38.4, with Java 17, lint, format, `analyze --fatal-infos`, test, regen+diff
  (client and l10n) and size check.

### P2 (fix before merge or with the named WP; not blocking this verdict)

**P2-1: Goldens recorded on macOS will very likely fail on the Linux CI runner.** `test/goldens/*.png`,
`test/flutter_test_config.dart:16`, `ci-job.yml:8`.
- *What it does:* the four goldens were recorded on macOS. On macOS, Skia rasterises glyphs with CoreText; on
  ubuntu-latest it uses FreeType. The comparator accepts 0.5 % differing pixels, which is about 92 px of the
  328×56 image.
- *What goes wrong:* the Tamil label and the two Material icons have glyph edges whose anti-aliasing differs
  between the two rasterisers. My probe shows that a 4 dp icon change already moves 1.6–3 % of the pixels, so
  the cross-platform difference is likely of the same order, and above 0.5 %. The first CI run of the `mobile`
  job would then go red. The tempting quick fix, raising the tolerance, would blunt the 56/64 gate.
- *Fix:* record the goldens on Linux. Either run `flutter test --update-goldens` once in a Linux container
  with Flutter 3.38.4 (for example `ghcr.io/cirruslabs/flutter:3.38.4`) and commit the PNGs, or tag the golden
  tests `@Tags(['golden'])` and let macOS developers run `flutter test -x golden`. Do not raise the tolerance.
  The README line "Update goldens (macOS…)" changes with this.
- *If skipped:* CI is red on the first M00 run, or the tolerance is raised and the golden stops catching
  size regressions. The exact height asserts would still catch 56 → 52.

**P2-2: Main's `docs` CI job goes red when apps/mobile lands.** `.github/workflows/ci.yml` `docs` job (Q00),
`infra/scripts/doc-coverage.py`, `apps/mobile/l10n.yaml`. The branch base `9d3dea5` predates Q00's ci.yml, so
the worker could not see this. TODO.md line 38 assigns it to M00.
- *What it does:* `doc-coverage.py` (a) requires a header comment in the first 5 lines of every `.dart` file
  under `apps/`, and (b) runs `flutter analyze --fatal-infos` in apps/mobile. It *fails*, rather than skips,
  when Flutter is missing.
- *What goes wrong:* (a) gen-l10n writes `lib/core/l10n/gen/app_localizations.dart` starting with
  `import 'dart:async';`, so the headers row FAILs (output above). (b) The `docs` job installs no Flutter. Main
  CI turns red at merge.
- *Fix:*
  1. (M00 paths) Add `header: "// GENERATED by flutter gen-l10n from lib/core/l10n/app_ta.arb and app_en.arb (l10n.yaml). Do not edit; edit the ARB files."` to `l10n.yaml`, then regenerate and commit.
  2. (Orchestrator at merge, together with the ci-job.yml splice) In the `docs` job, before "Doc coverage of the
     apps", add `subosito/flutter-action@v2` (3.38.4, cache) and `flutter pub get` in `apps/mobile`, and remove
     the `TODO(M00/P00)` comment.
- *If skipped:* every PR after the merge fails the `docs` job, and the BM-10 doc-coverage gate stops meaning anything.

**P2-3: The release manifest has no INTERNET permission.** `android/app/src/main/AndroidManifest.xml`.
- *What it does:* the Flutter template declares `android.permission.INTERNET` only in the `debug` and `profile`
  manifests. The main manifest has none.
- *What goes wrong:* every release/prod build is denied sockets. M02 sync, M06 OTP and the healthz probe would
  work on the emulator in debug and fail in the APK the Verifier and the pilot phones install. M00 makes no
  runtime network call, so no acceptance line is broken today. That is why this is P2 and not P1.
- *Fix:* one line in the main manifest: `<uses-permission android:name="android.permission.INTERNET"/>`.
- *If skipped:* the failure first shows up in the first release-build smoke test (M02/M06 Verifier or M13),
  long after the cause.

### P3 (nice to have; fix when touching the file or in the named WP)

**P3-1: size_check.sh and the README still present the 15 MB line as the M00 gate, and say "MB" for MiB.**
`tool/size_check.sh:4,7,34`, `README.md` size row.
- *What it does:* the defaults are right (fail > 100, warn > 40), but the usage text says
  `MAX_MB=15 … the M00 skeleton gate`. The script divides by 1,048,576 and prints "MB".
- *What goes wrong:* this contradicts the Orchestrator decision (TODO.md line 71). 100 MiB is 104.9 MB, so the
  same ambiguity that stalled M00 will come back at the 100 MB ceiling.
- *Fix:* drop the `MAX_MB=15` usage line and the README mention, and print `MiB`, or divide by 10⁶ and say MB.
  Either is fine; state which in the D-002 comment.
- *If skipped:* a Verifier reruns with `MAX_MB=15` and fails on a unit.

**P3-2: The CI size step will not skip on GitHub, and the AAB target is printed but never checked.**
`tool/size_check.sh:16,36-45`, `ci-job.yml`.
- *What it does:* ubuntu-latest presets `ANDROID_HOME`, so every PR builds a release APK (Gradle, NDK, several
  minutes). With bundletool present, the AAB size is printed but not compared with 30 MB.
- *Fix:* add `timeout-minutes: 30` to the job. Consider running the size step only on `push` to main. Leave AAB
  enforcement to M13, but say so in the script header.
- *If skipped:* slower PRs. The 30 MB download target has no automatic check until M13.

**P3-3: The regenerate-and-diff check misses new files and depends on floating generator versions.**
`ci-job.yml:33`, `tool/gen_api.sh`.
- *What it does:* it runs `git diff --exit-code -- packages/agritrace_api lib/core/l10n/gen`. The generated
  package's `.gitignore` hides its `pubspec.lock`, and its dev dependency is `build_runner: any`.
- *What goes wrong:* `git diff` ignores untracked files, so a new generated model that is not committed only
  shows up if an index file also changes. CI also resolves the newest `built_value_generator` on every run, so
  a generator release can produce a spurious diff. The worker noted this risk.
- *Fix:* replace the diff with `test -z "$(git status --porcelain -- packages/agritrace_api lib/core/l10n/gen)"`.
  Optionally add `.gitignore` to `tool/openapi-generator-ignore` and commit `packages/agritrace_api/pubspec.lock`
  for byte-stable `*.g.dart`.
- *If skipped:* rare false greens or false reds on the D-003 drift check.

**P3-4: The no-TextField lint has gaps.** `tool/no_textfield_lint.sh:14,25`.
- *What it does:* it word-greps `TextField|TextFormField|CupertinoTextField` in 7 farmer feature folders.
- *What goes wrong:* the probe passed with `EditableText`, `SearchBar` and `CupertinoSearchTextField` (`-w`
  rejects the `Search…` prefix), and with a `TextField` in `lib/core/widgets/`, where M05's farmer widget kit
  will live. M05's acceptance ("no free TextField lint passes") relies on this script.
- *Fix:* extend the pattern to
  `TextField|TextFormField|CupertinoTextField|CupertinoSearchTextField|EditableText|SearchBar|SearchAnchor`,
  matched without `-w` (for example `grep -rnE '\b(Cupertino(Search)?TextField|TextFormField|TextField|EditableText|SearchBar|SearchAnchor)\b'`).
  Add `lib/core/widgets`, with an explicit allowlist if officer widgets ever need one.
- *If skipped:* a free-text box can reach a farmer screen through a shared widget without CI noticing.

**P3-5: Unrouted paths under an allowed prefix show go_router's English "Page Not Found" screen.**
`core/router/app_router.dart:44`.
- *What it does:* `/home/xyz` for a farmer, or `/assist` with no id for an officer, passes the prefix check,
  matches no route, and renders the default error page (English, small "Home" button). Unknown top-level paths
  correctly bounce home.
- *What goes wrong:* no shipped navigation reaches this today, and Android deep links are not enabled. It
  becomes reachable once M07/M10 add sub-routes or notification deep links.
- *Fix:* `onException: (context, state, router) => router.go(redirectFor(role.value, '/__none__')!)`, or an
  `errorBuilder` that redirects to the role's home. Add one row to `router_test.dart`.
- *If skipped:* a farmer could land on an English dead-end screen with a sub-56 dp button.

**P3-6: The gap between the action and the speaker is half the token.** `core/widgets/farmer_button.dart:66`.
- *What it does:* `SizedBox(width: tokens.gap / 2)` gives 8 dp. The spec token is 16, and the design rule asks
  for "wide gaps".
- *Fix:* use `tokens.gap` and re-record the goldens (after P2-1), or add a one-line why-comment for the half gap.
- *If skipped:* a thumb aimed at the edge of the speaker can trigger the action.

**P3-7: Two members have no `///` docs.** `core/theme/status_glyphs.dart:42-46` (`operator ==`, `hashCode`).
CLAUDE.md §5 says every function, public or private. `public_member_api_docs` exempts overrides, so the
analyzer is silent. *Fix:* one line each. *If skipped:* a hand-checked miss in the Documentation Standard.

**P3-8: The crash sink prints in release builds.** `bootstrap.dart:83-85`. `debugPrint` is not stripped in
release, so uncaught errors go to logcat. Today no token or header reaches it: `DioException.toString` carries
the URI, not the headers. *Fix:* guard with `kDebugMode`, or name the release behaviour in the existing
`shortcut:` so M13 replaces it. *If skipped:* low risk; anything sensitive put in an exception message later
lands in logcat.

**P3-9: The dio timeout semantics and the `healthz` throw contract need a note.** `core/api/api_client.dart:32,61-64`.
In dio 5, `receiveTimeout` is the maximum *gap between chunks*, not a total 30 s budget, so a slow-drip response
can exceed A6's "request 30 s". Separately, `response.data!` on a 200 with an empty body throws a `TypeError`,
not the documented `DioException`. *Fix:* say so in the doc comment. M02 can add a total deadline if the
benchmarks need one. *If skipped:* surprises in M02 retry classification.

**P3-10: Template TODOs remain in `android/app/build.gradle.kts:23,38-40`.** Release builds are signed with
the debug keys, and the "Specify your own unique Application ID" TODO is still there. *Fix:* turn them into
`// shortcut: debug signing until M13 release signing` so `/ponytail-debt` collects them. *If skipped:* the
debt is invisible in TODO.md.

**P3-11: The text-scale clamp has no test.** `app.dart:37-38`. *Fix:* one widget test that sets the
platform text scale to 2.0 and expects `MediaQuery.textScalerOf(context).scale(10) == 15`. Alternatively leave
it to M05's 1.5× goldens. *If skipped:* a later edit to `builder` could silently drop the clamp.

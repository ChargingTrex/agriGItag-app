## Findings

### P1

### P2

**P2-1. An "outside" plot can fall off its own map** (`PlotMap.tsx:79-98`)
- What this is: the map's camera (`maxBounds`) and the OSM source (`bounds`) are limited to the GI region's
  bbox plus 0.1° (about 11 km).
- Problem: the plot pin is not part of that box. Take a plot with `location_status: outside` whose pin is
  20 km beyond the region, or a pin taken at the farmer's house in another town. The camera is clamped, so
  the pin is off screen and no tiles load where it is. These are exactly the plots a reviewer opens from a
  flag (FR70; P02 links flagged plots to this page).
- Fix: widen the box with the pin before padding. `bbox` already walks nested arrays, so one line does it:
  `bbox({ coordinates: [region['coordinates'], [pin.lon, pin.lat]] }, AREA_PAD_DEG)`. Add one case to the
  existing `bbox` test.
- If we skip it: a reviewer cannot see the plots that most need review, and P02 inherits the bug.

**P2-2. Coming back to a sleeping laptop signs the user out** (`AuthProvider.tsx:66-87`, `api/client.ts:42`)
- What this is: the access token is refreshed by a `setTimeout` 60 s before it expires, and any API 401 signs out.
- Problem: a laptop sleeps for 20 minutes and the token expires. On wake, TanStack Query refetches stale
  queries when the window gets focus (`refetchOnWindowFocus` default, `staleTime` 30 s). Those refetches go
  out with the old token while the overdue timer's refresh is still in flight. One 401 is enough to sign
  out, so the user lands on the login page and loses any half-filled form. The refresh cookie (browser-session
  lifetime) was still valid. Chrome's throttling of hidden-tab timers (aligned to about 1 minute after 5
  minutes hidden) eats the 60 s margin the same way. A network blip during the proactive refresh also signs
  out, because `.then(setSession, signOut)` treats a `TypeError` like a 401.
- Fix: in `AuthProvider`, pass `createApiClient` an `onUnauthorized` that first tries the cookie:
  `refreshSession().then((s) => { setSession(s); void queryClient.invalidateQueries(); }, signOut)`.
  Single-flight already makes parallel 401s share one refresh. Sign out only when the refresh itself fails,
  so "401 → sign-out" still holds for a revoked device.
- If we skip it: office staff get signed out every time they come back from lunch, and they will ask for a
  "remember me" that D-024 forbids.

**P2-3. The single-flight refresh has no test** (`authApi.ts:103-108`)
- What this is: concurrent refresh callers share one request, because the API treats two refreshes of one
  token as reuse and signs the device out.
- Problem: this is security-relevant logic (CLAUDE.md §4: security leaves one small test). If someone drops
  the `??=` or the `finally`, every test stays green while real users get `refresh_reused`.
- Fix: one Vitest case. Count `/v1/auth/refresh` hits in an MSW handler, call
  `Promise.all([refreshSession(), refreshSession()])`, and expect 1 hit. Then call once more and expect 2,
  which proves the `finally` reset.
- If we skip it: a regression shows up only as random sign-outs in production.

### P3

- **P3-4. The PIN step has no way back** (`LoginPage.tsx`). The `pin_token` lives 300 s. After that, or after
  a wrong number, `verifyPin` answers `unauthorized` and the only way out is a page reload. Add a text
  button "Start again" (`setStep({ kind: 'phone' })`) under the PIN and confirm steps.
- **P3-5. MapLibre zoom buttons are 29 px** (`PlotMap.tsx` NavigationControl), under the 48 px office
  target. Pinch and wheel zoom still work. One `sx` rule fixes it:
  `'& .maplibregl-ctrl-group button': { width: 48, height: 48 }`.
- **P3-6. The Playwright plot spec hits real tile servers** (`members.spec.ts:43`). It loads
  tile.openstreetmap.org and tiles.maps.eox.at from CI, which goes against OSM's tile policy and depends on
  the network. Use `page.route(/tile\.openstreetmap\.org|tiles\.maps\.eox\.at/, (r) => r.abort())`; the
  `request` event still fires, so the satellite assertion keeps working. Optional: assert that no
  `PlotMap-*.js` loads on `/members`, which proves the "lazy" half of the test title.
- **P3-7. Parallel 401s send N logout calls** (`AuthProvider.signOut`). This is harmless, and P2-2's fix
  removes most cases.
- **P3-8. The proactive refresh timer is untested.** A fake-timer test (advance 841 s, expect one refresh)
  would pin the 60 s rule. It can go together with P2-3.
- **P3-9. Ledger wording.** The `@playwright/test` row still says "tests in P07; browsers installed only when
  P07 runs". P01 now ships a mock-mode spec and `webServer`. Update the row's "files" and "what for".

## Findings

### P1

**P1-1. A closed flag never comes back, so holds and GI eligibility can be wrong** (`modules/rules_flags/service.py` `store_flags`, the `existing` / `elif flag.status in ACTIVE` branch; `models.py` `dedupe_key unique=True`)
- `dedupe_key` is unique across every status, and `store_flags` only updates flags that are `open` or `escalated`. A flag that is `fixed` / `rule_passed` (closed by the system) or `cleared` (closed by a reviewer) matches the key, so nothing is inserted and nothing is updated.
- Case A (system close): a harvest correction 1,350 kg on 1 acre gives a hold, `gi_eligible=false`. A correction to 1,150 auto-closes it (`rule_passed`) and sets `gi_eligible=true`. A second correction back to 1,350 gives no flag, and `gi_eligible` stays **true**. A lot 35 % over the ceiling can then go into a GI batch.
- Case B (escalation after review): an officer clears the 1,250 kg warn as `looks_fine`. A later correction to 1,350 is still not a hold, and GI is not blocked.
- Case C (B09 gate): intake 100 vs packed 69 gives `quantity_mismatch`. A corrected intake auto-closes it. A second intake of 50 makes the chain wrong again, but nothing is raised, so B09's `run_gate_checks` intake gate passes.
- Fix (small, all in `store_flags`): for an existing flag with `resolution_reason_code == RULE_PASSED` (closed by the system, `resolved_by is None`), or one whose new severity ranks above the stored one, set it back to `open`: clear `resolved_*` and `resolution_*`, set severity, details, assignee and `raised_at`. Add one integration test covering 1,350 → 1,150 → 1,350 (hold back, `gi_eligible=false`) and a unit-level case for the reopen branch. Update the router description "the next rule check does not reopen a resolved flag" and the TODO line.

### P2

**P2-1. No test covers auto-close or the hold/eligibility sync.** `store_flags`' close and refresh branches and `_sync_lot_hold`'s prefix rule are only exercised indirectly by the integration "re-check no dup" test, and auto-close is not tested at all. This is the logic that sets GI eligibility. Add the test from P1-1, plus a case where `rule_passed` restores `gi_eligible`.

**P2-2. `_sync_lot_hold` overwrites a reason another module set** (`service.py` `_sync_lot_hold`). If B09 sets `gi_eligible=false, gi_hold_reason="gi_recheck_failed"` and a yield hold arrives later, the reason is replaced by `"flags: yield_over_ceiling"`. When an admin clears that hold, the prefix test passes and `gi_eligible` goes back to `true`, so B09's hold is lost. No module writes these columns today, but B09 is next. Fix: only take over the reason when it is empty or already starts with `HOLD_PREFIX`; otherwise leave `gi_hold_reason` alone and only force `gi_eligible=false`.

**P2-3. Practice-tag contradictions are assigned to the field officer** (`service.py` `assignee`). FR56 says contradictions are "flagged for the FPO Admin". Fix: `assignee(severity, rule_code)` returns `fpo_admin` for `practice_tag_contradiction` as well. This is a one-line change, and it can be removed once B13 makes it configurable.

**P2-4. `batch_quantity_unattributed` fires on normal grading loss** (`rules/quantity_reconciliation.py` `_batch`). For a received 320 kg batch graded to 290 kg (9 % sorting loss) with shares totalling 320, the rule warns. Every real batch with a loss above 5 % gets a warn. It does reproduce §5, and it is a warn, not a hold. Architect-Gate should rule before B09 decides whether warns block publish. Possible options: compare Σ shares with `total_received_kg` and flag missing shares, or keep the current check and record the 5 % output tolerance as a season-1 calibration item. The worker already lists this risk.

**P2-5. The §5 count `yield_check_unavailable ×2` does not match the rule or PRD §12.2.** All three reference lots lack a harvest quantity, so this rule gives ×3. Either the spec should say ×3 or B12 must give one lot a harvest quantity. The stand-in test covers only one lot, so it cannot catch this. It is not a B08 code defect. Route it to Architect-Gate / B12, and list it in TODO under the existing B12 line.

### P3

1. `FlagNotOpenError` docstring says "…or an escalated one is resolved again by an officer". That case raises `resolution_forbidden`. Fix the docstring.
2. `rules/yield_ceiling.py` re-implements `quality.grade_engine.yield_outcome`; D-004 allows importing only `quality.service`. Two copies of the boundary math must change together. Either expose `yield_outcome` through `quality.service`, or add a comment pointing at the twin.
3. A plot `hold` (`plot_outside_gi_region`) does not change lot `gi_eligible`; only `run_gate_checks` returns it. Make the B09 TODO line say explicitly that the gate must block on plot holds too, not only on `gi_eligible`.
4. FR70 "repeated off-plot events" as a plot review reason is not aggregated (each event is flagged on its own). Add a TODO line.
5. Auto-close also closes `escalated` flags without the admin who was asked. This is acceptable because the audit log has it; record it in the router description.
6. `plot_checks`: a map-pin plot with `review_outcome="rejected"` raises `plot_map_pin`, not `plot_needs_review` (the `elif`). Harmless, but the reviewer sees the less specific reason.

## Ponytail review (skill `ponytail:ponytail-review`, trimmed)

What this change does: it adds the server rule set (11 small pure modules), the tasks that run them after sync,
photo, plot and quality writes, and a flags table that is upserted by key, auto-closed and can be resolved over
HTTP and sync. It is the server-side authority for flags, holds and GI eligibility.

**Must fix**
1. **Closed flags never return** (`service.py` `store_flags`). Same as P1-1. Fix: reopen `rule_passed` closures and severity increases. If skipped: a lot over the yield ceiling can go into a GI batch, and B09 gates pass on recurring mismatches.

**Should fix**
2. **No test of auto-close and hold sync.** Same as P2-1. If skipped: the next change to `store_flags` can break GI eligibility without any test failing.
3. **Foreign hold reason overwritten** (`_sync_lot_hold`). Same as P2-2. If skipped: B09's GI hold can be lost when an admin clears a yield hold.
4. **Duplicated yield math** (`yield_ceiling.py` vs `quality/grade_engine.py:yield_outcome`). merge: re-export it through `quality.service`, about -8 lines.

**Nice to have**
5. `quantity_reconciliation._lot` builds `chain` in two statements; one dict literal is enough.

Assumed load: pilot, one FPO, a few hundred lots, checks in one worker. Per-lot queries in `_check_lot` are fine at that size.

Verdict: fix 1 first (then 2, 3).
Lean: -10 lines possible.

## Findings

### P1 (blocks merge)

**P1-1: ConfirmScaffold shows a 48 dp back button whenever it is pushed, and that is its only real use.**
`lib/core/widgets/confirm_scaffold.dart:69` (`AppBar(title: …, actions: …)`), `test/widget/kit_harness.dart:103` (samples pumped as `home`).
- *What it does:* `AppBar` sets `automaticallyImplyLeading` to true by default. Any route that can pop gets
  Material's `BackButton`, which has a 48×48 dp tap target (probe 3). The sweep pumps every sample as the
  app's `home`, where nothing can pop, so it never sees the button.
- *What goes wrong:* every routine event ends on this screen (choose → photo → **confirm**). The farmer sees a
  small icon-only control with no speaker, under 56 dp. That breaks UserFlows "Big targets" and the M05 line
  "every control ≥ 56 dp". The spec for this screen is "offers only a big tick or Retake". Retake already goes
  back, and so does the Android system back.
- *Fix (two small edits):*
  1. Add `automaticallyImplyLeading: false` to the `AppBar` in `confirm_scaffold.dart`.
  2. Make the sweep realistic. In `pumpKit`, push the child onto a route with a `navigatorKey`, instead of
     only using `home`. Alternatively, add one sweep case that pushes the `confirm_scaffold` sample. Then any
     future implied back arrow on a kit screen fails the 56 dp guideline.

  M07 note: every farmer screen that uses a plain `AppBar` will have the same problem. Consider fixing it once
  in the theme (`appBarTheme` + an `iconButtonTheme` min size of 56) when M07 builds screens. That is not
  needed for this WP.
- *If skipped:* the most used farmer screen ships a small control, and the sweep stays blind to route chrome.

### P2 (fix in round 2 unless the Orchestrator defers)

**P2-1: While GPS is still weak, the ring is already green, so "turns green" cannot be seen.** `gps_ring.dart:101`.
- *What it does:* a fix that is not good yet colours the ring `colorScheme.primary`. The seed is green, so that
  is 0xFF3B6939. A good fix colours it `done.color`, 0xFF2E7D32. The golden `gps_ring_ta_x1.5_360x640.png`
  shows the 35 m ring dark green.
- *What goes wrong:* UserFlows §Onboarding step 4 says "when it turns green, the pin saves". The officer and
  the farmer cannot see that change. The design rule's colour language ("orange circle = to do") is not used.
- *Fix:* `color: good ? tokens.done.color : tokens.todo.color`, then re-record the 8 gps_ring goldens. The
  tick, the my_location icon and the text still carry the shape.
- *If skipped:* farmers wait for a change of colour that never visibly comes.

**P2-2: BigStepper's value breaks across lines at 1.5× on a 360 dp phone.** `big_stepper.dart:143`.
- *What it does:* the value `Text` (displaySmall, 36 sp × 1.5 = 54 px) sits between two 64 dp buttons. That
  leaves 200 dp, which the worker's own D-002 COMPROMISE comment states.
  - "1,20,000" needs about 207 px even in Roboto: 6 × 0.559 em + 2 × 0.24 em. ICU does not break inside a
    number, so Flutter breaks it character by character.
  - The golden `big_stepper_ta_x1.5_360x640.png` shows the value on 3 lines.
- *What goes wrong:* this does not throw an overflow, so the sweep passes. But a farmer reads "1,20,0 / 00".
  Typical stepper values (bags, acres) are short, which is why this is P2 and not P1.
- *Fix:* `FittedBox(fit: BoxFit.scaleDown, child: Text(…))`, then re-record. For NumberPad's read-out, add
  `maxLines`/`FittedBox` the same way if the Verifier sees a wrap with real fonts.
- *If skipped:* large numbers are hard to read for exactly the users who use 1.5× text.

**P2-3: The branch no longer merges cleanly with main (M01 landed after the base).**
- *What it does:* `git merge-tree` reports conflicts in `CHANGELOG.md`, `apps/mobile/pubspec.yaml`
  (drift/uuid vs just_audio/url_launcher), `pubspec.lock` and `docs/LIBRARIES.md`. Main's ledger already has a
  `path_provider (transitive via drift_flutter)` row.
- *Fix:* in round 2, rebase or merge main and keep both dependency sets. Re-resolve the lock with
  `flutter pub get` rather than by hand. Rerun analyze and both test runs. Merge the path_provider mentions
  into one ledger row.
- *If skipped:* the Orchestrator resolves the lock by hand at merge, and the test counts above no longer
  describe what lands.

### P3 (fix when touching the file, or in the named WP)

**P3-1: An interrupted load is counted as a missing clip.** `voice_player.dart:49-55, 71-75`.
- *What it does:* just_audio 0.10.6 `_load` throws `PlayerInterruptedException('Loading interrupted')` when a
  second `setAsset` starts before the first finishes. `play()` catches it as an `Exception` and counts a miss.
- *What goes wrong:* example: a screen's prompt is autoplaying and an `ErrorSheet` opens at once with its own
  autoplay. The first bar then shows the crossed-out speaker and "No voice" and inflates `missingClips`. The
  M02 metric will then blame the recordings.
- *Fix:* in the provider closure, `try { await audio.setAsset(path); } on PlayerInterruptedException { return; }`.
- *If skipped:* a wrong icon now and then, and a noisy metric.

**P3-2: An empty officer number enables the call button, and the disabled state has no test.**
`call_officer_button.dart:37`.
- *What it does:* probe 3 shows `phone=""` gives enabled=true, so a tap launches a bare `tel:`.
- *Fix:* `phone == null || phone.isEmpty`, and add a two-line test that the button is disabled when null.
- *If skipped:* if M06/M07 maps a missing number to `''`, the button opens an empty dialer.

**P3-3: The ledger's transitive notes are incomplete.** `docs/LIBRARIES.md` "just_audio transitive" row.
- *What it does:* the lock adds packages the ledger does not name:
  - `jni`, `jni_flutter`, `jni_util` (path_provider_android). These add a native `.so` per ABI to the APK.
  - `objective_c`, `hooks`, `code_assets`, `record_use` (path_provider_foundation; native-assets build hooks
    on iOS).
  - The `path_provider_*` and `url_launcher_*` platform packages.
  - `plugin_platform_interface`, `platform`, `xdg_directories`.
  At the same time the row lists `uuid` and `crypto`, which were already in the base lock. All the licences
  are BSD or MIT, so nothing is rejected.
- *Fix:* add one row (or extend the row) for these packages, naming jni's native library and the iOS build
  hooks, and add a url_launcher transitive note. Ideally do this together with the P2-3 merge.
- *If skipped:* the D-018 ledger hides a native library that counts against the D-002 size budget.

**P3-4: The goldens show Latin text and every digit as test-font boxes.** `test/flutter_test_config.dart:27-30` (M00).
- *What it does:* only NotoSansTamil and MaterialIcons are loaded. So the 44 English goldens and every number
  (stepper, pad, accuracy, cloud count) are black boxes. The P2-2 wrap was visible but hard to judge.
- *Fix:* add `_loadFont('Roboto', '$sdkFonts/Roboto-Regular.ttf')`. The file is present in the SDK cache. Then
  re-record. This is the shared M00 config, so the Orchestrator may prefer to do it in Q01, when goldens are
  re-recorded on Linux.
- *If skipped:* number layout is checked only by the unit expectations, not by pixels.

**P3-5: The failed-playback branch has no test.** `voice_player.dart:51-53`.
- *What it does:* the `on Exception` fallback is what every iOS user hits, because iOS cannot decode `.ogg`.
- *Fix:* one test with a `ClipPlayer` that throws. Expect `false`, `missingClips == 1` and `volume_off`.

**P3-6: PictureCardGrid does not enforce the "speaker on every choice, ≤ 2 words" rule.** `picture_card_grid.dart:22,30-34`.
- *What it does:* `promptId` is optional, and there is no word-count assert like FarmerButton's.
- *Fix:* copy FarmerButton's assert for `label`. Keep `promptId` nullable only if a caller really needs a
  speaker-less card; otherwise make it required.

**P3-7: One private member's doc is incomplete.** `big_stepper.dart:101`.
- *What it does:* `_button` does not describe `[size]` and has no "throws nothing". CLAUDE.md §5.2 requires
  every function, private ones included, to document all its parameters.

**P3-8: The placeholder flag covers the whole manifest, not each clip.** `assets/prompts.json`.
- *What it does:* once real recordings arrive one by one, `"placeholder": true` cannot say which clips are
  still tones.
- *Fix:* when the first real clip lands, move the flag to a per-id list (for example `"placeholders": {...}`).
  Fine as it is today, because all 4 clips are tones.

**P3-9 (M07 handover): a double tap on the tick fires `onConfirm` twice.** `confirm_scaffold.dart:94`.
- *What it does:* FilledButton calls `onPressed` on every tap until the route pops.
- *What goes wrong:* a first-time user's double tap creates two entries, unless M07 makes the entry UUID
  before this screen (D-005 idempotency) or ignores the second call.
- *Fix:* one sentence in the `onConfirm` doc ("called on every tap; the caller must be idempotent"), and M07
  makes sure of it.

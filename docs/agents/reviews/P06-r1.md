## What this change does

It replaces the P00 placeholder at `/` with the FPO dashboard:
- crop → district → block → village native selects;
- completeness and public-scan tiles;
- seven stage tiles, each a CSS stacked bar with the counts in text;
- Land Area Analytics by block and by village, Finished Goods, and Sync health;
- a per-farmer table whose column choice is stored per FPO in localStorage and sent as `?fields=`, with cursor "Load more".

It adds `/audit`: a react-hook-form + zod search (actor UUID, entity type and id, an India-time date range with the end day included). Rows
show "14 Feb", the actor and the assisted farmer, the action, the entity, and the diff keys verbatim. A non-admin sees the server's 403 message.

It adds `/settings`, which is read-only: FPO name and code, FSSAI and GI numbers, a disabled opt-out switch with its effect in words, and the
feature-flags and fields tables ("Edited in git").

MSW handlers live in a new `mocks/dashboardHandlers.ts`, spread after `handlers`.

## Findings

### P2

**P2-1. The dashboard place filters drop most villages and blocks at pilot scale** (`apps/portal/src/features/dashboard/DashboardPage.tsx:144-150`)
- **What this is:** the district, block and village options come from one `GET /v1/villages?limit=200`. The village directory is global and ordered by name (`registry/router.py:220-248`).
- **Problem:** the `shortcut:` comment rests on "the pilot imports one district". One district is more than 200 villages: Virudhunagar's LGD list is about 600, and P08 is the tool that imports it. With 600 villages sorted by name, only names from the first third of the alphabet load. Any block whose villages all sort late (Tiruchuli, the pilot FPO's own block, Vembakottai, Watrap) is missing from the Block select, and so are its villages. Nothing on screen says the list is cut.
- **Fix (about 8 lines, no new endpoint):** page through the cursor in the `queryFn`, and keep a `shortcut:` note naming the new limit:
  ```ts
  // shortcut: loads the whole village directory (~600 rows for one district); add a places endpoint if a state-wide master is imported.
  queryFn: async ({ signal }) => {
    const items: Schemas['VillageOut'][] = [];
    let cursor: string | undefined;
    do {
      const page = await unwrap(api.GET('/v1/villages', { params: { query: { limit: 200, cursor } }, signal }));
      items.push(...page.items);
      cursor = page.has_more ? (page.next_cursor ?? undefined) : undefined;
    } while (cursor);
    return { items };
  },
  ```
  Add one test: MSW returns two pages, and a village that exists only on page 2 appears in the Village select. Update the TODO "P06 skipped" wording to match.
- **If we skip it:** an admin cannot filter to their own block, and the tiles and farmer table cannot be narrowed to villages the FPO actually serves.

**P2-2. Merging main breaks the Settings test: a duplicate `/v1/config/fields` mock** (`apps/portal/src/mocks/dashboardHandlers.ts:327-359`, `apps/portal/src/features/settings/settings.test.tsx:33-34`)
- **What this is:** P06 adds its own `GET /v1/config/fields` handler (farmer: name, phone; plot: declared_area) after `handlers`.
- **Problem:** P08 (now on main, `handlers.ts:789`, `MOCK_FIELDS`) added the same route with farmer, village and input entities. MSW uses the first match, which is main's, so the Settings table gets 19 rows. I reproduced this on a temporary merged tree: `expected … to have a length of 4 but got 20`.
- **Fix:** merge main into the branch. Delete P06's `/v1/config/fields` handler and its local `field()` helper, so main's `MOCK_FIELDS` serves both screens. In `settings.test.tsx`, import `MOCK_FIELDS` from `../../mocks/handlers` and assert `getAllByRole('row')` has length `1 + Object.values(MOCK_FIELDS).flat().length`, keeping the `Mobile number` assertion. While there, resolve the three text conflicts as listed in the table above and re-run `npm test`.
- **If we skip it:** main goes red on the merge commit.

### P3

**P3-1. The filter note over-promises on land area and the farmer table** (`DashboardPage.tsx:607-610`). B11 narrows land area by **place only** (plots carry no crop). In the farmer table, `crop_id` narrows only the lot counts, not the farmers. Today, picking a crop leaves land area unchanged while the note says it is narrowed. Fix the copy: "Crop narrows completeness, stage progress and the farmers' lot counts; places also narrow land area and the farmer list. Finished goods, scans and sync health are for the whole FPO."

**P3-2. "In progress" is hard to tell from "Done" by colour** (`DashboardPage.tsx:255`). `primary.light` (#58975b) against `primary.main` (#2e7d32) has a normal-vision ΔE of 9.8 (dataviz floor 15). The counts are in text, so no meaning is lost, but the legend and bars barely separate. Fix: `import { green } from '@mui/material/colors'` and use `green[300]` (#81c784, ΔE 24.3) for `in_progress`.

**P3-3. Audit dates have no time and no year** (`AuditLogPage.tsx:240`). "14 Mar" suits the farmer UI, but an audit trail spanning seasons repeats the same "14 Mar", and several changes on one day cannot be ordered by eye. Fix: show the IST time as well, and wrap it so the full value is in the DOM: `<time dateTime={row.at}>{new Date(row.at).toLocaleString('en-IN', { day: 'numeric', month: 'short', year: 'numeric', hour: '2-digit', minute: '2-digit', timeZone: 'Asia/Kolkata' })}</time>`. Then update the test's `'14 Mar'` assertion.

**P3-4. The reason hint checks only `reason_code`** (`AuditLogPage.tsx:112`). If B06 adds only `reason_text` to the diff, the row shows the text and also "Reason: not in the audit log yet". Fix: `!('reason_code' in diff || 'reason_text' in diff)`.

**P3-5. The column state is not re-read when the FPO changes** (`DashboardPage.tsx:489`, `:614`). `useState(() => readColumns(fpoId))` runs once. Today there is no in-app tenant switch (re-login remounts the page), so this is hardening only. Fix: `<FarmerTable key={fpoId} …/>`.

**P3-6. Ledger "What for" cell** (`docs/LIBRARIES.md:74`, axe-core). The caller column lists the P06 tests, but "What for" still names only the P02/P03 pages. Append "and P06 pages (dashboard, audit log, settings)".

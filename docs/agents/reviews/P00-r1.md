## What is right (checked, no action)

- **Auth guard.**
  - Direct URL: a signed-out visit to `/members` renders only the sign-in page (tested).
  - Back navigation after sign-out: `signOut` clears sessionStorage, calls `queryClient.clear()` and sets
    the session to null. Every protected history entry goes back through `RequireAuth`, which returns
    `<Navigate replace>` before any `Outlet` renders, so no protected content flashes and no cached data
    remains.
  - Any 401 from the generated client signs the user out (tested).
  - The `from` redirect comes from router state that only the app writes. `pushState` cannot cross origins,
    so there is no open redirect.
- **Tokens.**
  - No token is logged (no `console.*` in src or dist) and none goes into a URL. `postJson` and the
    middleware send it only as an `Authorization` header.
  - The pre-PIN token stays in React state and is never persisted. Only a full session, parsed by zod,
    reaches sessionStorage.
  - The stored session is re-validated with zod on load, and a malformed value is treated as signed out.
  - The sessionStorage shortcut is marked `// shortcut: ... upgrade to an httpOnly refresh cookie when B02
    defines the web token transport` (AuthProvider.tsx:33), so /ponytail-debt will collect it.
- **Error mapper.**
  - A non-envelope 5xx becomes `internal_error`, and a non-envelope 4xx becomes `unknown_error`, which
    shows the fallback text.
  - An unknown code falls back to the generic text, and a ZodError does too.
  - The retry rule is correct: network errors, 5xx and 429 retry; all other 4xx, ZodError and AbortError
    do not. It applies only to queries. Mutations keep TanStack's default of `retry: 0`, which matches
    conventions.md ("retries are safe for sync pushes").
- **Generated client.**
  - `createClient<paths>({ baseUrl: window.location.origin })`. The `/v1` prefix comes from the spec paths
    (D-020), not from a hand-kept base.
  - `schema.d.ts` carries openapi-typescript's "Do not make direct changes" header and is lint- and
    prettier-ignored.
  - `gen:check` runs in `ci-job.yml` before lint and catches hand edits (probe above).
  - The MSW healthz handler is typed with the generated `components['schemas']`, so a spec change breaks
    typecheck.
- **Cursor hook.**
  - It fetches exactly once per page (the test asserts the call list `[[undefined,1],['c2',1]]`).
  - The key `[...queryKey, { limit }]` is hashed by TanStack, so it is stable across renders.
  - The `signal` is passed through, and `has_more: false` or a null cursor stops paging.
  - `fieldsParam<T>` rejects field-name typos at compile time.
- **MSW only in dev.**
  - `startMocks` is gated on `import.meta.env.DEV`, so production code eliminates the dynamic import.
  - `copyPublicDir: false` keeps `mockServiceWorker.js` out of `dist/`.
  - `msw` is a devDependency.
  - The grep and the sourcemap both confirm zero mock code in the build.
- **Error-message generator.** It locates columns by header name, not position, and fails loudly on a
  format change. `error-codes.md` is itself generated (`gen-error-codes.py`), so the format is stable.
- **CI job.**
  - It runs `npm ci`, `gen:check`, lint, typecheck, test, build, and the size budget with `shell: bash`
    (pipefail), so the budget failure survives `tee`.
  - It runs on Node 24 with an npm cache keyed on the lockfile.
- **Tooling.**
  - TS strict with `noUncheckedIndexedAccess` and `verbatimModuleSyntax`.
  - `erasableSyntaxOnly` on the Node scripts, so plain `node` can run them.
  - Type-aware `strictTypeChecked` linting.
  - The single `eslint-disable` carries its reason.

### P2 (fix before merge or with the named WP; not blocking this verdict)

**P2-1: lightningcss (MPL-2.0) has no ledger row and no licence decision.** `docs/LIBRARIES.md`, D-018.
- *What it does:* Vite 8.3.5 depends hard on `lightningcss@1.33.0` (MPL-2.0) plus 11 platform binaries.
  The worker named it as a risk in the report ("needs a D-018 decision") but added no row.
- *What goes wrong:* D-018 says "copyleft or non-commercial licences rejected", and the ledger header lists
  only permissive licences. A later licence audit (Q00 `libraries-check.py`, or G1's "LIBRARIES.md check")
  will find an undocumented copyleft package in the portal toolchain with no recorded decision. B00-r1
  P3-11 raised the same question for `certifi`/`pathspec`, and it is still open.
- *Fix:*
  1. Append one row: `lightningcss | 1.33.0 | MPL-2.0 | transitive of vite 8.3.5 (build-time only; not in
     dist, verified by sourcemap) | CSS parsing/minification inside Vite | hard dependency of Vite 8, not
     replaceable without dropping Vite 8 | Vite 7 (older major; same dependency as an optional peer)`.
  2. Have the Architect-Gate amend D-018 to state that MPL-2.0 is acceptable for **unmodified** dependencies
     (build-time or transitive) and that it covers certifi, pathspec and lightningcss.
- *If skipped:* the G1 ledger check has an unexplained copyleft entry, and the next reviewer cannot tell
  whether it was accepted or missed.

**P2-2: The assumed auth contract hands out a refresh token before the PIN is checked.** `src/auth/authApi.ts:15-22`,
`src/mocks/handlers.ts:36-42`. This is a design point for B02 and the Architect-Gate. No P00 code change is
needed now.
- *What it does:* one `tokenResponseSchema` covers both steps. OTP verify for a PIN role returns
  `{access_token, refresh_token, role, fpo_id, pin_required: true}`, and the zod schema **requires**
  `refresh_token`, `role` and `fpo_id` in that response. The portal itself behaves correctly: it keeps only
  `access_token` in memory as the PIN credential and discards the rest.
- *What goes wrong:* if B02 adopts the shape literally, anyone who has the SMS code (SIM swap, shared phone,
  shoulder-surfing) receives a refresh token without the PIN. If the server does not scope that token, it
  can mint full sessions, and the PIN step is bypassed. The pre-PIN `access_token` also has the same name
  as a real access token, which invites the server to accept it on other routes.
- *Fix (B02):*
  - When the role needs a PIN, OTP verify returns only `{pin_required: true, pin_token, expires_in}`. The
    `pin_token` is short-lived (≤ 5 min), single-purpose and accepted **only** by `/v1/auth/pin/verify`.
  - No refresh token is issued until the PIN passes.
  - The full response is `{access_token, refresh_token, expires_in, role, fpo_id}`.
  - Register dedicated error codes (`otp_invalid`, `otp_expired`, `otp_locked`, `pin_invalid`,
    `pin_locked`) rather than 422 `validation_error`, and never 401 for a wrong code, because the client
    middleware treats 401 as "signed out".
  - Add `/v1/auth/refresh` and `/v1/auth/logout`.
  - In P00's follow-up, the portal changes `tokenResponseSchema` into a `z.discriminatedUnion('pin_required', …)`
    and changes the PIN step to send `pin_token`. This is about 10 lines and is already marked `TODO(B02)`.
- *If skipped:* a second factor that does not protect anything, on the admin accounts that approve
  batches and publish pages.

### P3 (nice to have; fix when touching the file or in the named WP)

**P3-1: Edge cases in the error-message lookup and table.** `src/api/errors.ts:67`, `scripts/gen-error-messages.ts:36-45`.
- `ERROR_MESSAGES[error.code]` is a lookup on a plain object, so a code such as `constructor` or `toString`
  returns `Object.prototype` functions instead of `undefined`.
- An empty "Meaning" cell produces `""`, which `??` does not catch, so the user sees a blank Alert.
- An escaped `\|` in a cell truncates the message to `Use A \` (neither generator escapes pipes).
- None of this happens with today's 12 codes. Fix with `(Object.hasOwn(ERROR_MESSAGES, code) && ERROR_MESSAGES[code]) || FALLBACK_MESSAGE`,
  and make the parser reject an empty message.

**P3-2: Every `TypeError` is treated as "network down".** `src/api/errors.ts:68,78`.
- A programming error inside a `queryFn` or `select` (for example, reading a property of undefined) is
  retried three times with backoff and then shown as "Cannot reach the server".
- Fix: in `unwrap` and `postJson`, catch the fetch rejection and rethrow a small `NetworkError` class, then
  key `errorMessage` and `isRetryable` on that class. Optional; TanStack's own default retries everything.

**P3-3: A 429 retry ignores `Retry-After`.**
- conventions.md and error-codes.md say "wait for the `Retry-After` interval". TanStack's default backoff
  is 1 s, 2 s and 4 s.
- Fix when a portal screen can actually hit a rate limit (B02's OTP resend is a plain `fetch`, not a
  query, so it is unaffected): carry `retryAfter` on `ApiError` and use it in `retryDelay`.

**P3-4: The 48 px targets do not cover Checkbox, Radio, Switch or clickable Chip.** `src/theme.ts`.
- Checkbox measures 42 px (9 px padding + 24 px icon). P03's "tick lots" and P06's column toggles will use
  checkboxes.
- Fix: `MuiCheckbox`/`MuiRadio: { styleOverrides: { root: { padding: 12 } } }` (12 + 24 + 12 = 48). Add it
  now or in P03.

**P3-5: The login cannot step back.** `src/auth/LoginPage.tsx:145-157`.
- After "Send code", a mistyped number leaves the user on the SMS-code step until the page is reloaded,
  and there is no "Resend code".
- Fix: a text button on the OTP step that calls `setStep({ kind: 'phone' })`; B02 adds resend.

**P3-6: The guard checks "signed in", not "office role".** `src/auth/RequireAuth.tsx`.
- A role that never needs a PIN (`pin_required: false`, for example a farmer) gets the portal shell. The
  server's FPO and role scoping (CLAUDE.md §6) protects the data, so this is UX, but the header cites FR14.
- Fix with B02's role list: redirect non-office roles to a "this portal is for FPO staff" page. Add a
  `TODO(B02)` in `RequireAuth.tsx` now so the gap is greppable.

  Fix (Orchestrator, since DECISIONS.md is outside P00's paths): file **D-022 "Portal served same-origin

## Judgments requested

  portal is the only TypeScript consumer and the output is types-only (`schema.d.ts` + `openapi-fetch`), so

  second TS consumer appears".

  `POST /v1/auth/otp/verify` → (`pin_required`) → `POST /v1/auth/pin/verify` with a bearer token, E.164
  phone, and the error envelope throughout. B02 should adopt it **with P2-2's changes**:
  - a single-purpose, short-lived `pin_token` instead of a full token set before the PIN;
  - a discriminated response;
  - `expires_in`;
  - dedicated error codes;
  - refresh and logout endpoints;
  - an httpOnly refresh cookie for the web.
- **React Router 7 / TS 5.9 pins: correct.**
  - React Router 8.x (npm latest 8.5.1) requires `react >=19.2.7`, so 7.x is the newest major that
    supports the stack's React 18.
  - The app uses declarative mode only (`BrowserRouter`/`Routes`), the minimal surface.
  - TS 5.9.3 is required by openapi-typescript 7.13 (`^5.x`), even though npm latest is 7.0.2. Revisit both
    pins when the stack moves to React 19 or openapi-typescript supports TS 6+. Fix only the ledger wording
    (P3-8).

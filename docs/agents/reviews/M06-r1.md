The security core is good. Tokens are kept only in the keystore. The interceptor sends the bearer only where the

token is never stored. These are the things a security review fails on, and none of them failed.

The P1s are a back button and a language switch that are smaller than 56 dp. M05-r1 failed on the same
back-button rule (its P1-1), so it is treated the same way here.

## ponytail-review (trimmed)

Scope: `git diff main...HEAD -- apps/mobile ':!apps/mobile/packages/agritrace_api'`. I also read the callers:
bootstrap, router, placeholders, M00 tests, B02 `service.py` (`_bind_device` order) and smart_auth 3.2.0's source.
Assumed load: one phone, one user at a time, with at most a few requests at once (M02 sync plus a screen call).

**What this change does:** It adds the sign-in flow: phone number, then SMS code (read on Android after an "Allow"
tap), then a PIN for officers. It stores the tokens in the phone's keystore, and an HTTP interceptor adds the
token and renews it after a 401. It restores the session when the app opens, and adds a sign-out button that keeps
unsent entries.

**Must fix**

1. **Pushed sign-in steps show a 48 dp back arrow** (`lib/features/auth/auth_step.dart:98`, the `AppBar(...)`).
   - **What this is:** The OTP and PIN steps are opened with `context.push`, so Material adds its own back button.
   - **Problem:** That button is 48 × 48 dp. The farmer rule is ≥ 56 dp. The probe fails the 56 dp guideline on
     `/auth/otp` and `/auth/pin`.
   - **Fix:** `automaticallyImplyLeading: false` on this AppBar (as M05 did in `ConfirmScaffold`). Android's system
     back still returns to the phone step. Add the 56 dp guideline to `auth_screens_test.dart` for the 3 steps.
   - **If we skip it:** Farmers miss a small target on the first screen they ever see. It is the same defect that
     failed M05-r1.
2. **Language switch is a 48 dp text link** (`auth_step.dart:100-104`).
   - **What this is:** The `TextButton` in the app bar switches Tamil and English on every sign-in step.
   - **Problem:** It is 48 dp tall, with no icon and no speaker slot. "Language first: switched with one button"
     is a farmer control, and M00's placeholder already uses a `FarmerButton(icon: Icons.translate, ...)` for it.
   - **Fix:** Use the same `FarmerButton` as M00, with the existing speaker `shortcut:`. If it stays in the app
     bar, it needs `TextButton.icon(icon: Icon(Icons.translate), …, style: TextButton.styleFrom(minimumSize:
     Size(0, tokens.minTarget)))`. Re-record the 8 goldens.
   - **If we skip it:** The first control a Tamil farmer needs is the hardest one to hit.

**Should fix**

3. **A refresh that lands after sign-out writes the tokens back** (`lib/core/router/session.dart`, `_doRefresh`).
   - **What this is:** `_doRefresh` reads `_refresh`, awaits the network, then `_storeTokens`.
   - **Problem:** Here is the case. An M02 sync call gets a 401 and starts a refresh. The user taps Sign out.
     Logout fails (signal drops) or succeeds first, so `_endLocally` clears everything. Then the refresh answer
     arrives, and `_storeTokens` puts the access and refresh tokens back into memory and secure storage, with the
     Session row already gone. Until the next app open, `accessToken` is non-null while signed out. The sync
     engine could then send the outbox with the previous user's token.
   - **Fix:** One line before `_storeTokens`: `if (_refresh != token) return null;` (`_endLocally` has set it to
     null). Add one test: start a refresh, sign out, complete the refresh, assert `storedValues()` holds only
     `device_id`.
   - **If we skip it:** It is a narrow timing window, but the result is a "sign-out leaving tokens" state.
4. **The custom keypad is not marked `shortcut:`** (`auth_step.dart:151`, `_DigitKeys`).
   - **What this is:** A private 3 × 4 keypad, used instead of M05's `NumberPad`.
   - **Problem:** The reason exists only in the report and in TODO.md. M05's pad drops a leading zero (`int.parse`
     at `number_pad.dart:66`, still there on main), groups digits Indian-style and cannot mask. TODO.md line 150
     says "two `shortcut:` marks in auth_step.dart", but auth_step.dart has one, for the prompt `Text`. The other
     is in otp_screen.dart, and the keypad has none, so `/ponytail-debt` will not list it.
   - **Fix:** `// shortcut: own keypad because M05 NumberPad drops a leading zero (PIN 0123), groups 10-digit
     phones and cannot mask a PIN; swap when NumberPad gets fixed-length + obscure modes.`
   - **If we skip it:** Two keypads drift apart with nothing in the code that says why.

**Nice to have** (see P3 below): `readAll()` instead of four keystore reads at cold start; the stale
`tables/session.dart` doc; reset `_busy` if `signOut` throws.

Verdict: fix 1, 2, 3 and 4 first. Lean: about 0 lines possible. The new code is already small; `_DigitKeys` is
~40 lines kept on purpose, and nothing found is dead.
Not checked: a real device or emulator (SMS consent sheet, Keystore behaviour), the live API.

## Findings

### P1 (blocks merge)

- **P1-1: 48 dp back button on the pushed OTP and PIN steps.** This is ponytail #1 above. The fix is
  `automaticallyImplyLeading: false` in `AuthStep`'s AppBar and a 56 dp guideline case in `auth_screens_test.dart`
  for `/auth`, `/auth/otp` and `/auth/pin` (pushed, Tamil, scale 1.0 and 1.5).
- **P1-2: 48 dp, text-only language switch on every sign-in step.** This is ponytail #2. The fix is the M00
  `FarmerButton(icon: Icons.translate, label: l10n.switchLanguage, onSpeak: null)` (with its `shortcut:`), or an
  icon + label app-bar button with `minimumSize` 56. Re-record the 8 goldens.

### P2

- **P2-1: The branch conflicts with main; M05 is now merged.** Merge main. The conflicts are in the ARBs, the gen
  l10n files, pubspec.yaml, LIBRARIES.md and CHANGELOG.md. M05's `VoicePromptBar` and `ErrorSheet` are now on main,
  so the conditions in the two `shortcut:` comments ("once it is merged", "is unmerged") have come true:
  - swap the prompt `Text` (`auth_step.dart:113`) for `VoicePromptBar`;
  - swap the device sheet body (`otp_screen.dart:113`) for `ErrorSheet`;
  - if either does not fit, re-word the shortcut with the real limit.

  Then rerun analyze, lint, tests and goldens.
- **P2-2: `_DigitKeys` lacks a `shortcut:` mark with the reason.** This is ponytail #4. The Orchestrator should also
  correct TODO.md line 150 ("two `shortcut:` marks in auth_step.dart").
- **P2-3: A refresh completing after sign-out writes the tokens back.** This is ponytail #3. Add the one-line guard
  in `_doRefresh` and one test.
- **P2-4 (Orchestrator, TODO.md): another user's unsent outbox after a shared-phone sign-out.** Sign-out keeps the
  outbox (correct: never delete unsent entries). The next user who signs in on that phone would have M02 push the
  previous user's entries under their own token. The worker proposed this TODO line ("M02: … decide what happens
  to another user's unsent outbox rows after a shared-phone sign-out"), but it is not in TODO.md. Add it under M02,
  noting that D2D transfer (see the allowBackup row) gives the same situation.

### P3

- **P3-1:** `lib/core/db/tables/session.dart:11,31,34` still says "M06 decides whether they move to the platform
  keystore" and "sent as `X-Device-Id`". The worker called this file out-of-path, but `apps/mobile/**` is
  declared. Fix the doc comments now; this is a comment-only change, plus the regenerated `database.g.dart` doc.
  The column drop waits for schema v2 (TODO line 150).
- **P3-2 (Orchestrator):** ADR D-027 says "access, refresh and pin tokens are stored" and that the Session row
  keeps `pin_set`. The code is stricter: the pin token is held only in memory and `pin_set` is not persisted. The
  ADR also names EncryptedSharedPreferences, which flutter_secure_storage 10+ no longer uses by default. Amend the
  ADR text.
- **P3-3 (Orchestrator):** The D-013 code comment's COMPROMISE ("plain Notifier without riverpod_annotation
  codegen") contradicts ADR D-013's "Codegen dependency". This dates from M00 and was carried forward. Align one of
  them.
- **P3-4:** Placeholders: the gear `IconButton` on `/home`, `/officer` and `/qc` and the `/settings` back button
  are 48 dp. These are placeholders that M07, M08, M10 and M11 replace, so they do not block. But `/settings` is
  the farmer's only way to sign out until M08, so the P1-1 fix could cover it for free.
- **P3-5:** `restore()` makes four sequential keystore reads before the first frame. `_storage.readAll()` is one
  platform call. The cold-start effect on the Go AVD is not measured (Q01).
- **P3-6:** `restore()` reads the Session row outside the `try`. A DB open failure makes `bootstrap` throw before
  `runApp`, which leaves a blank splash. This is acceptable (nothing works without the DB), but the doc says
  "throws nothing".
- **P3-7:** In the settings placeholder, `_busy` stays true if `signOut()` throws (for example a keystore
  `PlatformException` on delete), which leaves the button dead. Use `try/finally`.
- **P3-8:** The keypad delete key is icon-only (64 dp, `Semantics` label `authDelete`). It is accepted as the
  standard number-pad convention, the same as M05's `NumberPad`.

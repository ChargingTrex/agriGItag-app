## Findings

### P1 (blocks merge)

**P1-1. A self-intersecting walked boundary makes the server reject the whole plot.**
`onboarding_notifier.dart:262-281` (ring built from every fix), `boundary_step.dart:48-54` (no filter).
- The server's `registry/geo.py:_checked` refuses any polygon that is `not geom.is_valid` with
  `InvalidGeometryError`. `_push_plot` then returns `rejected` for the **entire** plot entry: pin, declared size,
  crop, all of it. M02 (f039ae4 `markRejected`) sets the entry to `rejected` and its outbox row to
  `needsAttention`. The payload is append-only, so the plot cannot be fixed and resent.
- Concrete case: the officer taps "Start walking" and stands still for 3 s, walks the field, stands still 3 s and
  taps "Stop". The GPS jitters 2-5 m while standing still, the path zig-zags across itself, and the ring is invalid.
  This is the normal way people walk. `boundary_walk: true` is the default in `config/features.yaml`.
- Offline, the officer finds out days later. The farmer then has no plot on the server.
- **Fix (small, in M09's paths):** in `boundary_area.dart` add `bool ringIsSimple(List<LonLat> ring)` (an O(n²)
  check that non-adjacent segments do not cross, about 15 lines; n is a few hundred). In `plotIn`, send
  `walked_boundary` only when `ringIsSimple(walked)`. In `boundary_step.dart`, when it is not simple, show one
  sentence ("The shape crosses itself. Walk again or tap Next.") in place of the areas. Add one test: a figure-8
  walk → no `walked_boundary` in the payload, and the pin and size are still there. Thinning out repeated or
  near-duplicate points is optional. The shortcut comment at `boundary_step.dart:47` should then say what is
  dropped.

### P2

**P2-1. The server refuses every consent entry from the wizard (403), online and offline.**
`onboarding_notifier.dart:469-484`, `consent_step.dart:5`.
- `identity/service.py:_check_writer` allows consent only from the farmer, or from an officer whose request
  carries `X-Assist-Session` for that farmer. The wizard never starts an assist session. M02 (f039ae4) never sends
  the header. One push batch carries one header, but a batch holds many farmers. So `_push_consent` answers
  `ForbiddenError` and the consent ends up `rejected`. UserFlows step 2 ("saved with time and the officer's name")
  and FR41 are then not met on the server.
- The code comment at `:478` and the report ("witness and device come from the token") are wrong: the witness is
  set only when `caller.assist_session_id` is set.
- M09 cannot fix this inside `apps/mobile` alone. **Fix for r2:** correct the two comments. Add a TODO.md line
  "M09 → B02/M02 (consent witness)". **Escalate to Architect-Gate** for one of two options: (a) B02 accepts
  `data_collection` consent from a field officer for a farmer in the officer's FPO and sets
  `witnessed_by_user_id = caller`, which is the smallest change; or (b) the push gets a per-entry assist session.
  Option (a) needs no mobile change.

**P2-2. The offline `farmer` entry will be rejected by M02 as it is now, and it takes its consent and plot down
with it.** `onboarding_notifier.dart:465-468`.
- M02 at f039ae4 (`outbox_processor.dart:61`) sends every entry type it does not know as `event_version`. The
  `farmer` entry gets rejected. The `consent` and `plot` entries that name the phone UUID then fail
  `_farmer_in_scope`. All three end in `needsAttention`, and nothing retries them.
- The TODO (M02 sends POST /v1/farmers first, then swaps the id) describes this correctly. It is enough for
  M09 **only if the Orchestrator makes it a merge condition for M02** (or B03 adds `client_id` to `FarmerIn`, plus a
  push kind `farmer`, before the pilot). Record that dependency in CHECKLIST/TODO for M02.
- Also add to the same TODO: a `DioException` with no response also covers a receive timeout **after** the server
  committed the farmer. The offline copy is then a duplicate (phone taken, or a second farmer with no phone).
  `client_id` on `FarmerIn` fixes both problems.

**P2-3. The officer is stuck at step 4 when location permission is refused or location is off.**
`location_step.dart:47-53`.
- `GpsFix.fixes()` returns an empty stream that completes when permission is denied or location services are
  off (`gps_fix.dart:108-113`). `_sub` stays non-null, so the ring stays on screen. After 60 s, "Save anyway" sets
  `_noFix` and shows "No location yet. Move to open sky." forever. Nothing starts the GPS again. The pin is core, so
  the officer cannot go on.
- **Fix:** add `onDone: () { if (mounted && _best == null) setState(() { _sub = null; _noFix = true; }); }` to the
  `listen` call. The "In field" button then comes back, so the officer can retry after turning location on. Show
  `_noFix` under that button too, and add an ARB sentence "Turn on location and tap again" (ta + en). One test: a
  fake GPS stream that closes → "In field" is visible again.

### P3

- **P3-1.** The handoff comes back after the *second* plot of a smartphone farmer. `applies(handoff)` ignores
  `plotsSaved` (`onboarding_notifier.dart:219`). Fix: `hasSmartphone == true && phone != null && plotsSaved <= 1`.
  Extend the "Another plot" test to cover the "Farmer's phone" path.
- **P3-2.** No test checks what the QR holds, and that is the SEC property. Add
  `expect(signInLink('+919876543210'), 'agritrace://auth?phone=%2B919876543210')`. In the flow test, also check
  `tester.widget<QrImageView>(find.byType(QrImageView))` against the same link.
- **P3-3.** UserFlows step 2 says "plays a short recorded message **in Tamil**". The clip plays in the UI locale
  (`consent_step.dart:50`), and the farmer's language is picked only at step 3. Either play `ta` always (the farmer
  can replay it in English) or record the choice as a decision. `consent_version` already records honestly what
  was played.
- **P3-4.** "I agree" can be tapped before the consent clip finishes. Optional: enable the button after the
  clip ends, once real recordings land. Note it in the M09 assets TODO line.
- **P3-5.** `recording_ref` (`onboarding_notifier.dart:479`) sends an app asset path. The server field is
  documented as an "Object key of the consent recording". `consent_version` already says which text was played.
  Delete the line, or reword the server description in B02.
- **P3-6.** `onboarding_wizard.dart:5` says "officer-only controls >= 48 dp". The code (`tokens.minTarget` 56)
  and the a11y test hold 56 dp. Fix the header.
- **P3-7.** "Murugan: 1 fields saved": use an ICU plural in `onboardSummary`, for example
  `{count, plural, =1{1 field saved} other{{count} fields saved}}` (Tamil reads fine already).
- **P3-8.** The consent text (`app_{ta,en}.arb:271`) lists name, photo, phone, location and farm photos. It does
  not list the survey/patta number or the walked boundary, which are also collected. Add them before the native
  Tamil review that TODO already asks for.
- **P3-9.** On a retry after a later failure, `farmerId` is kept, so the server farmer keeps the `no_smartphone`
  value from the first tap, even if the officer then taps the other button. Rare. Either lock the choice after the
  first tap, or call `PATCH /v1/farmers/{id}` with `no_smartphone`.

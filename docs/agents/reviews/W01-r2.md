### P3

1. **Rarer phone formats still pass:** `0091 98765 43210`, `(987) 654-3210`, `98765.43210`, and a zero-width space inside the number.
   - *Fix:* strip `[\s\-.()​-‍]` from the compact copy, and allow `00` before `91` in the prefix.
   - These are rare in field notes. W02's lint can add the same cases.
2. **`boundary polygon` lost its `\b` anchor (`(?i)polygon`), so it now false-positives on the weed genus *Polygonum*, and also on "polygonal".** This fails closed: a publish is refused, not leaked. A field officer naming that weed in a comment would block the batch page, with an error that makes no sense to them.
   - *Fix:* use `(?i)\bpolygon\b` for text and keep the unanchored form only for URLs, or anchor as `polygon(?!um)`.
3. **The number patterns now run on every non-URL string, including system ids:** `footer.generation`, lot codes and batch codes.
   - A synthetic `Gen 9785403678.1` is refused as a phone number. Today's epoch-based generation strings (`Gen 17…`) are safe until about 2033.
   - Any 10-digit numeric id starting with 6–9 would fail closed.
   - *Fix:* B10 should keep generation and code formats non-numeric or prefixed, as they are now. One line in the README is enough.
4. **The `boundary_map_url` pattern accepts any https host.** Round 1 suggested pinning it to the static GI asset path. Leave it until B07/B13 fixes that host, then tighten the pattern.
5. **`markupsafe>=3` has no upper bound**, while jinja2 and pydantic are capped `<4` and `<3`. This is a consistency nit.
6. **TODO.md is missing two P2-5 items** (Orchestrator):
   - B10 maps `ValidationError` from `render()` to a registered AppError, for example `public_page_privacy_violation` with status 422;
   - B06 records the variant width and height in `evidence_photos.variants`.
7. **LIBRARIES.md in the worktree** (Orchestrator fixes on merge):
   - the `markupsafe` row still says "installed with jinja2". It is now declared directly as `>=3`, and its "Used in" column should mention pyproject;
   - the `hatchling` row still says "latest (build-only)". Give a floor, for example `>=1.25`, and pin the same floor in `pyproject.toml` `[build-system] requires`.

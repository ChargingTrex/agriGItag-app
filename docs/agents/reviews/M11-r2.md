## The instrument mirror: no clobber between two mirrors

- **One mirror only.** `qcInstrumentFetcherProvider` reads every page of `GET /v1/instruments?active=true`. Rows without `calibration_due_on` are skipped, because the server refuses their readings. The kind is serialized to the wire name.
- **Writes happen only after every page arrived.** `qcInstrumentsProvider` then deletes the table and inserts the fetched rows in one transaction. A `DioException` on any page leaves the cache untouched.
- **M10's own fetch is gone.** M10's `moistureMetersProvider` now filters `qcInstrumentsProvider.future` to moisture meters. No second writer is left.
- **Clobber case checked.** In r1 the risk was that M10 writes only moisture meters and deletes them, while M11 writes all kinds. Now one writer replaces the whole table from one complete list, so neither screen can drop the other's rows.
- **Delete-inactive is kept, and is now stronger.** M10 deleted inactive moisture meters only. Now inactive instruments of every kind disappear. M10's test still passes.

## `lot_intake` (D-040) against the spec and B16

- **The save** (`intake_screen.dart:241-286`) writes, in one `saveQcEntries` transaction, the moisture `quality_reading` (when typed) and then the `lot_intake` entry. Its id is `_intakeId`, made once per screen.
  - Payload: `{lot_id, sale_date (local YYYY-MM-DD), received: {value, unit: kg}, price_per_kg?, intake_moisture_reading_id?}`.
  - No `processor_id` and no `client_id`.
  - `received` is always shown and required (`IntakeIn.received` is required), so `received!` is safe.
- **backend-design.md §3 line 121-126:** "`data` = `IntakeIn` without `client_id` (the entry's `client_id` is the intake id) … absent `processor_id` → the FPO's only own processor". Matches.
- **B16** (`agent-a4cadb1d9f2ca5ebd` @ 07dadf0, `lots_batches/schemas.py:90-115`): `lot_id`, `processor_id: UUID | None`, `sale_date: date`, `received: Kg` (Quantity with unit `kg`), `price_per_kg?`, `intake_moisture_reading_id?`. The handler is `_push_lot_intake` (`events/service.py:846`). `lot_intake` is in `NO_ASSIST_KINDS`, which matches D-042. Field names match one for one.
- **Push.** `SyncKind.lotIntake`, with wire name `lot_intake`, maps through the existing non-event path of `entryToWire`. It is not an event type, because `eventTypes` still has `intake`, so the name `lot_intake` avoids the event mapping exactly as D-040 §1 says. The outbox order is stable, so the reading is processed before the intake that names it.
- **No `intake` event any more.** `grep` over `lib/` finds `'intake'` only in `eventTypes` (server enum parity) and as the reading stage. Nothing on the phone read the old `intake` entries.
- **Tests.**
  - `qc_flow_test`: saved types are exactly `{quality_reading, lot_intake}`. The payload is checked against `IntakeIn` in openapi.json, with `processor_id` excused until B16. The wire kinds are `[quality_reading, lot_intake]`, `client_id` is the intake id, and `data` equals the payload.

## Findings

### P2

**P2-1 (r2): an unverified lot's weight check trusts the forgeable QR `packedKg`**
(`apps/mobile/lib/features/qc_intake/intake_screen.dart:189-199` `_weightCheck`)

- Case: a farmer's phone shows a QR with `packedKg` edited to match whatever the bags will weigh, with the checksum recomputed (D-035: unkeyed SHA-256). The lot is not on the QC phone. The officer types 230 and sees the green "accepted" tick. The same card says the weight is "not checked".
- UserFlows §Selling: "A green tick means accepted". The server's `quantity_mismatch` flag catches it later, so no data is lost. But the phone shows a verdict it has no basis for.
- **Fix (micro-patch):**
  - Change the guard to `if (received == null || packedKg <= 0 || widget.lot.unverified) return null;`.
  - Add one `qc_screens_test` assertion: on an unverified card, typing a weight shows neither the tick nor the orange line.
  - Optionally say "Weight is checked after sync" in the existing `qcLotUnverified` line. No new key is needed.

- **P3-1 Stale report line.** `docs/agents/reports/M11.md:27` still says Save writes "`intake` (`received`, `price_per_kg`, `moisture_reading_id`)". Change it to the `lot_intake` payload.

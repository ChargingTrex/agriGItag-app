## Findings

### P2

**P2-1. The audit-log viewer returns coordinates, boundaries, survey refs and EXIF GPS, but says it does not**
(`apps/api/agritrace/modules/reporting/service.py:754`; claims at `reporting/router.py:158-159`,
`reporting/schemas.py:169`, `docs/adr/D-039.md:19`)
- **What this is:** `GET /v1/audit-log` returns `audit_log.diff` as stored.
- **Problem:** Each `plots` create or update diff holds `pin` as `"POINT(lon lat)"` (the registry writes
  `WKTElement`), `walked_boundary` as `POLYGON(...)` and `land_record_ref` (survey/patta number). Each
  `event_versions` row written by `events/service.py:517-538` holds `photos[].exif_gps {lat, lon}`. The route
  description ("device ids and GPS are not listed"), the `AuditRow` docstring and D-039 all promise the opposite,
  and the generated clients and P06 will rely on that promise. The P06 audit search would then show exact farm
  locations and survey numbers in a free-text log screen.
- **Fix:** In `audit_rows`, scrub location and land-record keys before building `AuditRow`. Keep the key and
  replace the value, so an admin still sees *that* it changed:
  ```python
  HIDDEN_KEYS = frozenset({"pin", "walked_boundary", "land_record_ref", "exif_gps", "started_gps", "gps", "boundary"})
  def _scrub(v: Any) -> Any:  # docstring per §5
      if isinstance(v, dict):
          return {k: "[hidden]" if k in HIDDEN_KEYS else _scrub(x) for k, x in v.items()}
      return [_scrub(x) for x in v] if isinstance(v, list) else v
  ```
  Then use `AuditRow(..., diff=_scrub(r.diff))` (or `model_validate` followed by `model_copy`). In
  `test_audit_log_search_is_fpo_scoped`, assert that the seeded plot's audit row has `diff["pin"] == "[hidden]"`.
  Change the three texts to "location, boundary and land-record values read `[hidden]`". About 10 lines and 1 assert.
  *Alternative*, if the Orchestrator wants admins to see locations in the log: keep the behaviour, correct the
  three texts, and add a D-039 compromise line. Either way, the contract must say what the route returns.
- **If we skip it:** The published contract makes a false privacy claim, and exact coordinates spread into a
  searchable screen and into whatever the portal exports from it.

## Correctness notes (checked, no finding)

- **Live versions only:** completeness and tiles filter `Event.status NOT IN ('undone', 'superseded')`
  (`DEAD_EVENTS`, the rules' set). Corrections add versions to the same event, so a corrected event stays live
  once. `draft` and `locked` count as live, the same as in the rules.
- **Tiles** follow D-037: P06 order, `bool_or` per stage, `max(stage_no)` furthest, `count(*) FILTER`.
  done + in_progress + not_started = lots. Farm events always hang off a lot (`events.one_subject` check), so
  `lot_id` correlation covers land preparation and sowing.
- **Crop `event_schema`:** a missing `mandatory` makes the lot complete (documented). A non-array `mandatory`
  would make Postgres raise. B13 validates the shape, so no finding.
- **Land area:** acres, with unit `acre` on every amount. GI share = confirmed declared ÷ declared, `%`, null at 0.
  Only place filters apply (plots carry no crop), as documented.
- **Sync health:** `percentile_cont(0.5 / 0.95) WITHIN GROUP` in SQL, `saved_at >= now − 7 d`, grouped and
  ordered by `network_type`, ms rounded with unit. Failure rate = failures ÷ (failures + entries).
  `Membership (user_id, fpo_id)` is unique, so the join cannot double rows.
- **Filters:** completeness, tiles and the farmer table take crop and place; land area takes place only. Flags,
  batches, finished goods, scans and sync health are FPO-wide. This is stated in the route description, the
  `Dashboard` docstring, D-037 §4 and TODO.
- **Pagination:** `Page[T]`, limit + 1 look-ahead, `id`-keyed cursor (UUIDv7), `limit` 1–200. Matches conventions.md.
- **Finished goods** cap of 100 rows is marked `shortcut:` (`service.py:76`) and has a TODO line.

### P3

**P3-1. Tamil-script free text is tagged `lang="en"`.** `templates/batch.html.j2:25` (`e.comment`), `:124`
(`lot.review_note`), `:113` and `:115` (farmer name, place). The page default became `lang="en"` (`:37`). Names
and places are proper names, which WCAG 3.1.2 (Language of Parts) exempts, so they are fine. But a farmer or
officer comment typed in Tamil is not a proper name: a screen reader reads it with the English voice. The
`_assert_tamil_is_tagged` test passes only because the fixture's comments are English.
Fix (about 4 lines, no schema change): in `render.py` add a filter
`def lang(v): return Markup('<span lang="ta">{}</span>').format(v) if _TAMIL.search(v) else v`
(with `_TAMIL = re.compile("[஀-௿]")`), register it in `_ENV.filters` (`render.py:237`), and apply
`|lang` at `batch.html.j2:25` and `:124`; add one Tamil comment to a test record. Or keep it in TODO (already
named there, TODO.md:247) until the record carries a language per value.

**P3-2. Stale TODO line for the sort fix.** `TODO.md:278` ("B10 → W01: `PublicBatchRecord` re-sorts timelines
by (date, instance_no) ...") is still open although W03 fixed it in `schema.py:244,262`.
Fix: tick it: `- [x] ... (W03: `_by_date` sorts by (date, stage order, instance_no), same order as B10 `STAGE_ORDER`)`.

**P3-3. Firefox/Safari print not in TODO.** The report and D-045 say print was checked in headless Chrome only,
but no TODO line carries it. Fix: add to TODO.md §4: `- [ ] W03 → Q: print the page from Firefox and Safari
(QR background with print-color-adjust, lazy evidence photos in opened timelines) and from Chrome's real print
dialog.`

**P3-4. Printed QR depends on a print-time fetch.** `batch.html.j2:146`, `page.css:44,54`. `print-color-adjust:
exact` makes Chrome, Safari and Firefox (97+) print this background even with "Background graphics" off, so the
default-setting worry does not apply. The remaining risk is timing: the image is first requested when print
layout starts, and a slow link can give a blank square in a real print dialog. The printed page link
(`batch.html.j2:148`) is enough for a reader to reach the page, and the QR is already on the pack. Accept;
covered once P3-3 is in TODO.

**P3-5. `beforeprint` opens every timeline and never closes them.** `templates/page.js:13-15`. After printing,
the screen view keeps all timelines open (with their lazy photos now loading). Fix if wanted: remember the
closed ones and close them again in an `afterprint` handler (3 lines). Cosmetic; also with JS off the printed
timelines stay closed (no CSS can open `<details>` in all browsers yet).

**P3-6. `og:image` is the QR code.** `batch.html.j2:48`. A shared link preview shows a QR, not the produce.
Not a privacy issue (the QR encodes only the public URL). A product photo would need a new non-personal image
field; leave as is, note for product.

**P3-7. Tracking-file merge conflicts with main.** `git merge-tree 0ed87b8 HEAD`: textual conflicts in

## Ponytail review (`/ponytail-review` on the branch diff)

a print layout (black on white, QR and link, one photo per event), a small inline map with coarse village dots,
and a separate "page not available" page for unpublished, withdrawn or unknown codes. It also sorts same-day
events by crop stage.

No must-fix or should-fix items. Nice to have: P3-1 (`|lang` filter), P3-5 (`afterprint`). Lean: nothing to
delete; the diff reuses `_pair`/`t()`, the existing privacy lint and the existing CLI. Load assumed: one render
per publish in a Celery task; the outline is projected once at import.

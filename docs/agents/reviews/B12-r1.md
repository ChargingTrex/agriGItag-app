`EVENT_RULES` and `PLOT_RULES` do not run here: the seed calls no `check_event` or `check_plot`, and in the e2e
`send_task` is a recorder.

## Findings

### P2-1 `make seed` fails on a fresh stack: nothing migrates the compose DB (`Makefile:38`)
- **What:** README "Five-minute start" says `make up` then `make seed`. The api image's CMD is `uvicorn` only.
  `infra/docker-compose.yml` has no migrate step, and `make up` runs none. So the first `make seed` hits
  `relation "fpos" does not exist`. The worker report says "needs a migrated stack (`make up`)", but `make up`
  does not migrate.
- **Fix (one line):** `$(COMPOSE) exec api sh -c "alembic upgrade head && python -m agritrace.seed.demo"`.
  `alembic.ini` and `alembic/` are in the image, and `alembic/env.py` reads `DATABASE_URL` from the settings, which
  compose sets. Upgrading head is a no-op when the DB is already current, so the target stays idempotent.

### P2-2 "FPO code exists" is not "seeded": silent no-op, order-dependent e2e (`apps/api/agritrace/seed/demo.py:343-345`)
- **What:** `tests/integration/test_config_imports.py:78-80` (the `ids` fixture) inserts a bare
  `Fpo(code="VIRUDHAI_SCFC_VINOBA_BHAVA_FPO")` if it is missing. Suppose a session runs that module before
  `tests/e2e`, for example `uv run pytest tests/integration/test_config_imports.py tests/e2e`, a `-k` selection, or
  any order plugin. Then `seed()` returns False without writing anything. The e2e `api` fixture finds that FPO
  with no field officer, no QC officer and no lots, and `test_reference_batch...` crashes (`KeyError: Role.FIELD_OFFICER`,
  or the flag Counter is `{}`). `make test` and CI pass today only because `tests/e2e` sorts before `tests/integration`.
  The same silent no-op hits `make seed` on any DB where an admin already created this FPO. The guard also
  accepts a half-written seed. `create_batch` → `_refuse` **commits** before it raises `gate_not_met`
  (`lots_batches/service.py::_refuse`), so a future gate change that refuses the reference lots leaves the FPO
  and all history committed with no batch. Every re-run then reports "already present". That contradicts
  D-048 §3 ("committed in one transaction").
- **Fix (about 3 lines):** use the batch as the marker:
  `if await session.get(Batch, BATCH_ID) is not None: return False`. Then get-or-create the FPO:
  `fpo = await session.scalar(select(Fpo).where(Fpo.code == FPO_CODE)) or Fpo(...)`, adding it only when new. In
  the e2e fixture, add `assert lots, "seed did not run"` so a skipped seed fails with a clear message. In D-048 §3,
  reword the idempotency sentence (marker = `BATCH_ID`; a refused `create_batch` commits; recovery is to drop the
  FPO's rows).

### P3-1 Event versions get no audit rows, but the docstring and ADR say audit rows are written (`demo.py:339`, `docs/adr/D-048.md` §1)
`EventVersion` is not `Audited` (`events/models.py:62`). The API writes an explicit `audit_log` row per version
(`events/service.py::_add_version`). The seed's 30+ versions have none. Fix: say "audit rows for audited models
(events, not event_versions)" in both places. Adding rows is not needed for demo history.

### P3-2 Seeded codes have shapes the API never produces (`demo.py:445`, `:470`)
Farmer `code=f"F-{n:03d}"` against the API's `F` + 6 hex (`registry/service.py::_new_farmer_code`). Plot `"P-01"`.
This is harmless, but list it with the invented values in the B12 TODO line, or use the API format.

### P3-3 `_legacy_grading` re-reads the FPO it was given (`demo.py:605-606`)
`seed()` already holds `fpo`. Pass it in and drop the `session.get` and the `assert`. Lean: −2 lines.

### P3-4 The unit test re-implements `_lot_context` (`tests/unit/test_seed_demo.py:59-80`)
`_lot_context` is copied by hand (used = received, harvested None, yield outcome None). It can drift from
`rules_flags/service.py::_lot_context`. That is acceptable, because the e2e checks the real path. Add one line to the
docstring saying the e2e is the authority, so nobody "fixes" the copy instead of the service.

### P3-5 The sync push answer is read before its status is checked (`tests/e2e/test_reference_batch.py:261-262`)
On a 4xx, `r.json()["results"]` raises `KeyError` instead of showing the error body. Add
`assert r.status_code == 200, r.text` first.

### P3-6 "Both clients compile" was not checked with `flutter analyze` or `tsc`
`make clients` regenerated both clients, and the Dart `build_runner` compiled the models. The output is
byte-identical (tree clean), because B12 does not change OpenAPI, so compile status is the same as on main. The
Verifier should run `cd apps/portal && npx tsc --noEmit` and `cd apps/mobile/packages/agritrace_api && dart analyze` after the merge with main.
B16 changed the spec there.

## Port fidelity (grade_calculator.dart vs grade_engine.py, read side by side)

| Check | Result |
|---|---|
| Latest reading per parameter, ordered by `(measured_at, id)`, null time first | **Same.** `DateTime.parse` keeps the offset and `compareTo` compares instants. A UUID compared as lower-case text gives the same order as `uuid.UUID` for the canonical form the server sends. On a full tie the first reading wins, as with Python `max`. Probes P1a–d match. |
| Missing required parameter with non-null limits → `incomplete` | **Same.** The branches run in the same order: role, then `limits is None`, then a missing reading. |
| Best grade per parameter, else `fail_grade` | **Same.** `limits[g]?.holds(...) ?? false` is Python's `g in p.limits and …`. |
| Cap by source | **Same.** The cap only ever lowers a grade, and the fail grade stays fail. P2c gives `Standard` with `capped=True` and `limit=null` on both sides. |
| Batch grade = worst | **Same.** `worst=-1` start, `exception` → `max(worst,0)` |
| `lab_certified` and per-parameter lab flags | **Same.** It needs the rule, a parameter in the profile, the right source and a NABL number that is not blank after `strip`/`trim`. P1d (NABL `" TC-1 "`) and P5c (lab reading at the wrong stage) match. |
| `limits: null` → `profile_incomplete` | **Same.** |
| Plausibility (unknown parameter alone, then unit, range, source) | **Same order and codes.** The messages differ only in how numbers are printed (`10.0` against `10`), and they are for logs only. |
| Trail rule (baseline = highest value at the latest earlier stage, `>` baseline + tolerance, overridable) | **Same.** P7a (exactly +0.5) gives no violation, and P7c (10.61 after 10.1) gives an overridable violation on both sides. |
| Lot gate | **Same.** An empty list gives `False` and 11.0 gives `True` (inclusive). |

| `Decimal` wherever Python uses `Decimal` | **Yes.** Values, limits, plausible ranges, gate bounds, trail tolerance and the yield rule are all `Decimal`. `double` appears only in GI geometry, where Python/PostGIS also use floats. No comparison mixes the two types. |
| JSON number → Decimal via its text | **Yes.** `toDecimal(v) = Decimal.parse(v.toString())`, which equals Pydantic's `Decimal(str(x))`. P6 (`1e-7`, exponent text) and P6b (`"10.000000000000001"`, past double precision) match. |

## Findings

### P2

**P2-1. An input of category `other` derives "Organic"** (`lib/core/rules/practice_tags.dart:8-16`).
`chemicalCategories` holds only the two chemical categories, and every other category counts as organic. The
server's `InputCategory` enum also has `other` (`core/enums.py`, backend-design §2 `inputs_master`). The header
comment says "every other category is organic or biological", which is not true for `other`.

Example: a lot whose only input is a sticker or spreader filed as `other` previews **Organic**. A farmer who honestly
declared Inorganic then gets a `practice_tag_contradiction`. The TODO says B08 should port these Dart semantics, so
the server would make the same mistake.

Fix: derive `organic` only when every category is in `{organic_fertilizer, bio_fertilizer, bio_pesticide}`. Leave
`other` out of the derivation; it neither proves organic nor makes a lot inorganic. Add one test.

**P2-2. Five file headers name callers that do not exist** (CLAUDE.md §5.1).
- `gi_check.dart:5` names `test/rules/gi_check_test.dart`.
- `event_order.dart:5` names `event_order_test.dart`.
- `moisture_limit.dart:6` names `moisture_limit_test.dart`.
- `practice_tags.dart:6` names `practice_tags_test.dart`.
- `yield_check.dart:5` names `yield_check_test.dart`.

These tests are all in `test/rules/preview_rules_test.dart`. Fix: change the five caller lines.

### P3

**P3-1. The report's evidence command does not reproduce.** The report runs `grep -c` on `--reporter expanded`
output and gets "63". On my run it gives **61**, because the expanded reporter drops lines for tests that finish
quickly. The two missing cases were "chilli 10.5 is Standard" and "chilli 11.4 is Below grade". Run alone with
`--plain-name`, both pass. The JSON reporter confirms 63 of 63. Count with `--reporter json` in future reports.

**P3-2. `Reading.fromJson` accepts timestamps without an offset** (`grade_calculator.dart:49`). `DateTime.parse`
reads them as device-local time, while Python `AwareDatetime` rejects them. Nothing wrong happens today, because
the phone builds its own readings. M11 should always give readings an offset or UTC, or the preview's "latest"
reading can differ from the one the server accepts.

**P3-3. The GI distance uses the mean Earth radius** (`gi_check.dart:24,32-33`). The `shortcut:` comment names this
limit, and TODO already records it. The measured error was ≤ 0.25 m inside the buffer and 0.5 % at 30 km. No
action is needed. If the near-edge preview ever disagrees in the field, the cheap upgrade is the WGS84 meridional
and prime-vertical radii at the pin's latitude (two constants).

**P3-4. The tests do not cover the Madurai point** that the server tests use (`tests/unit/test_geo.py`,
`integration/test_registry.py`). My probe classifies it `outside`. One more line in `preview_rules_test.dart` would
keep both sides' GI probes the same. Lean note: the `FeatureCollection` branch in `GiRegion.fromJson`
(`reference.dart:164-168`) exists only so tests can load the seed GeoJSON, because B07 sends
`{geometry, tolerance_buffer_m}`. It is 3 lines, so I am not asking for a cut.

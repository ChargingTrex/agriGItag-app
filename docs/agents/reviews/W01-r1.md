## 3. Findings

### P1: must fix before merge

**P1-1. `render()` does not re-check a `PublicBatchRecord` instance. A field changed after validation goes straight to the public page.**
- *What the code does:* `render()` calls `PublicBatchRecord.model_validate(record)` (`render.py:179`). For a model instance, Pydantic's default `revalidate_instances="never"` returns the instance as it is. So `_reject_personal_data` and every field validator are skipped. `_CONFIG` (`schema.py:33`) does not set `validate_assignment` or `frozen`, so assignment after construction is not checked either.
- *What goes wrong:* The schema header says B10 builds a `PublicBatchRecord`, and `render` accepts one. The probe built a valid record, set `rec.lots[0].review_note = "Farmer phone 9876543210"`, and called `render(rec)`. The phone number appeared in `index.html`. Setting `rec.lots[1].farmer_name` on an opted-out lot also published the name. The D-017 comment at `schema.py:28-31` promises "privacy is enforced where the page is built, not trusted to every caller". For instance input that promise is false. This breaks CLAUDE.md §6.
- *How to fix:* add `revalidate_instances="always"` to `_CONFIG`. I checked this: with it, the same mutated record is rejected with `privacy: phone number at record.lots[0].review_note`. Add one test: build the record, mutate it, call `render`, expect `ValidationError`.
- *If skipped:* B10 or the portal preview fills a record in steps, as builders usually do. One later bug or code path that sets a free-text field or a consent-dependent name then publishes personal data to a page printed on packaging, with no gate. W02's lint runs in CI on fixtures, not on every production publish.

**P1-2. `boundary_map_url` accepts any string: a `javascript:` link on the public page, and a way past every privacy pattern.**
- *What the code does:* `boundary_map_url: str | None` (`schema.py:363`) has no `pattern`. The template writes it into `<a href="{{ r.boundary_map_url }}">` (`batch.html.j2:64`). Autoescaping does not neutralise a `javascript:` scheme. Also, `_privacy_violation` skips every text pattern for any string that starts with `http(s)://` (`schema.py:100`).
- *What goes wrong:* The probe accepted `javascript:alert(document.cookie)`, which makes a script link on a public, unauthenticated page. It also accepted `https://maps.example/static?path=9.536271,78.201934|…` and `https://…/polygon/farm-123.geojson`, which put exact farm coordinates or a boundary polygon on the page. This is the only URL field the builder supplies without a constraint. Photo URLs have an `evidence/` pattern, and `map_link` is computed.
- *How to fix:* `boundary_map_url: str | None = Field(None, pattern=r"^https://[^\s]+$", …)`. Better still, pin it to the static GI asset host or path that B07/B13 will use, for example `…/gi/<n>/…`. Add a parametrised test for `javascript:` and for a coordinate-bearing URL. Also consider running `_TEXT_PATTERNS["precise coordinates"]` and `"boundary polygon"` on URLs too. They do not false-positive on hash digits.
- *If skipped:* a bad reference-data import or a compromised admin field can inject script or publish exact plot geometry. The W02 lint looks at text patterns, and those are exactly what URL-shaped values skip.

### P2: should fix (fix in round 2, or record as a TODO with an owner)

**P2-1. The phone and survey-number patterns miss common Indian formats.**
- *What the code does:* the phone regex at `schema.py:38` is anchored with `\b` and allows only `+91`. The survey regex at `schema.py:40` matches only `survey no|number`, `patta` and `chitta`.
- *What goes wrong:* the probe accepted these:
  - `09876543210`, the trunk-0 form, which is very common;
  - `phone9876543210`;
  - a number glued to Tamil text: Tamil letters count as `\w`, so `\b` never matches;
  - `987 654 3210`;
  - `S.F. No. 123/4A`, the standard Tamil Nadu form;
  - `Sy. No. 45`.

  The W01 validator is the only check at publish time. W02's lint runs over fixtures in CI.
- *How to fix:* replace `\b` with `(?<!\d)` and `(?!\d)`, and allow an optional `0` or `91` prefix. A simpler option: strip separators from a copy of the string and search for `(?<!\d)(?:91|0)?[6-9]\d{9}(?!\d)`. Use the same digit lookarounds for Aadhaar. Extend the survey regex to `(?i)\b(?:s\.?\s*f\.?|sy\.?|survey)\s*no\b|\bpatta\b|\bchitta\b`. Add these cases to the parametrised test.
- *If skipped:* a field officer's review note such as "spoke to farmer on 09876543210" or "S.F. No. 45/2" gets published.

**P2-2. FR51: the "Lab-certified" badge can show without any lab reading.**
- *What the code does:* `Grade._lab_name_only_when_certified` (`schema.py:251`) checks only that `lab_name` implies `lab_certified`.
- *What goes wrong:* a record with `lab_certified=True` and only instrument readings was accepted, and the page shows ★ Lab-certified. FR51 says the badge appears only when an accredited lab result is attached.
- *How to fix:* when `lab_certified` is true, also require `any(r.source == "lab" for r in self.readings)`, plus one test.
- *If skipped:* a builder bug produces a false quality claim on retail packaging.

**P2-3. Spec gap: no "procured quantity", and the batch quantity is ambiguous.**
- PRD §12.1 lists Crop → *Procured quantity* (320 kg) as a separate field from *Batch quantity* (20 kg), and marks it covered. The schema has only `total_quantity`, labelled "Total quantity".
- The fixture sets it to 320 kg, the super-lot total, so the lot quantities of 100 + 200 + 20 kg add up to it.
- For the B12 reference batch, B10 will send a 20 kg batch with 100/200/20 kg lots and shares of 31.25/62.5/6.25. The page would then show three lots adding to 320 kg under a "Total quantity" of 20 kg, with nothing to explain the gap.
- *How to fix:* add `procured_quantity: Quantity` with its own label, or rename and describe `total_quantity` precisely and add `batch_quantity`. The Architect-Gate should confirm the choice at G1.
- *If skipped:* B10 hits the mismatch at wave 6, and the schema changes after the portal preview and fixtures depend on it.

**P2-4. Future-caller contract: the `Photo` fields have no producer for `jpeg_url` and for the sizes.**
- The `Photo` docstring says "three server-made variants". Plan §13 B6 makes only two, both WebP: thumbnail and medium.
- Nothing produces `jpeg_url`, and nothing produces `width` and `height` unless B06 stores them in `evidence_photos.variants`.
- *How to fix:* in the `Photo` field descriptions and the README "How B10 calls it" section, state that `jpeg_url` is the original evidence JPEG (about 350 KB after B1). Add a TODO for B06 to record the variant sizes, or to emit a JPEG thumbnail if a 350 KB fallback per photo is too heavy for non-WebP browsers.
- *If skipped:* B10 discovers the gap and invents values, or the page loses its width/height and layout shifts.

**P2-5. TODO.md was not updated.** The worker could not touch it (it is outside the declared paths). The Orchestrator should add:
- native-speaker review of `ta.json`;
- W03 print CSS must open `<details>`;
- an ADR for 3 dp pin precision (see P3-8);
- B10 must map `pydantic.ValidationError` from `render()` to a registered `AppError` code such as `public_page_privacy_violation`, so that publishing returns a coded 422 and not a 500;
- the P2-4 item for B06.

**P2-6. The interrogate command in the review brief is wrong.**
- `--ignore-init-method=false` exits 2: the option is a flag and takes no value.
- The Verifier should run `uv run interrogate -vv --fail-under 100 agritrace_page`. Init methods are not ignored by default, and that run passes at 100 %.
- The Orchestrator should correct the command wherever it is copied, so the W01 Verifier does not record a false FAIL.

### P3: nits and cuts

1. Photo URLs skip every text pattern. A phone number used as an object key is accepted. Keys are system-made, so the risk is low. Consider checking the path with hex runs removed.
2. `_EVIDENCE_URL` allows `http://`, which gives mixed content on an HTTPS page. It also matches `evidence/` anywhere in the path, including after `?`. Use `^https://` and anchor the bucket segment.
3. Text with exact coordinates but no comma pair (`lat 9.536271 lon 78.201934`) is not caught. W02's coordinate-precision regex can own this. Note it in W02's acceptance.
4. `rel="noopener"` on the map link has no effect without `target="_blank"` (`batch.html.j2:95`). Drop it.
5. `render.py` imports `markupsafe` directly, but `pyproject.toml` declares it only through jinja2. Declare `markupsafe>=3`, or import `Markup` from jinja2's dependency on purpose and say so in the ledger.
6. The LIBRARIES row for `hatchling` says "latest". Give a floor version, as the other rows do.
7. FR72 asks for "review method and date". `review_note` is English-only free text on a bilingual page. A structured `review_method` (enum) and `review_date` would render in both languages and in "14 Feb" form. This can go to W03/B10.
8. The DECISION comments at `schema.py:158` (3 dp pin) and `schema.py:282` (Farmer N on opt-out) cite D-017. D-017 is about YAML field visibility. These are separate privacy and consent decisions, and 3 dp is still an open question (TODO §2). The Orchestrator should open D-021, or the comments should cite TODO §2 until it exists.
9. `RenderResult.html` and `.data_json` have no per-field description. Add one line each in the class docstring.
10. Many test functions take the `record` fixture but have no `Args:`. Interrogate passes because it checks only that a docstring exists. CLAUDE.md §5 says every function. Low value for tests, so this is a note only.
11. `__main__.py` header names W01 but no FR or flow. Add "FR15 local build" or similar.
12. The CHANGELOG line ends "awaiting review". The Orchestrator rewrites it to the `reviewer PASS rN, verifier PASS` format on merge.
13. `data.json` cannot be fed back as input: it carries computed fields and the schema uses `extra="forbid"`. If the portal preview ever posts a stored `data.json` back, it will fail. Document this in the README, which already says it once, or exclude computed fields on input.

## 6. What to cut (Ponytail)

- **`_PRIVATE_KEY` key-name regex** (`schema.py:45`, `:83-84`). Every model sets `extra="forbid"`, so any key that is not a declared field is already rejected. No declared field name matches the regex. The regex only changes the wording of the error. About 4 lines.
- **The coordinate-array branch** (`schema.py:88-92`). No field accepts a list of numbers, so Pydantic's type check already rejects one. Same reasoning: the branch only changes the error text. Update `test_rejects_polygon_and_other_personal_data` to expect the type error.
- **The `lang_order` option**: the parameter, the unknown-language `ValueError`, the `local` computation and `test_english_first_when_asked`. Nobody asked for a reorderable language pair. Tamil-first is the rule, and W03 owns labels. Keep `("ta", "en")` as a module constant. Medium priority: the option is small and harmless, but it is "an option nobody asked for".
- **`rel="noopener"`** without `target` (P3-4).
- Keep the rest:
  - `measure`/`check` enforce the E1 budget acceptance.
  - `place()` dedupe and `indian_number` are small and tested.
  - The share and best-before cross-checks guard facts the page states as true.

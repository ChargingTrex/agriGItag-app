### P2

**P2-1 A tenant can widen a field's visibility, and `public_fields` ignores tenant narrowing**
(`core/fieldconfig.py:157-185, 309-324`)

- **What happens:**
  - `_check_tenant` accepts `fields.farmer.phone.visibility: public` (probe above). After that,
    `fields_for`, `bundle_part` and `GET /v1/config/fields` report the phone number as `public` to every
    client of that FPO.
  - `public_fields(entity)` takes no `fpo_code`. A tenant that sets a field to `internal`, or disables
    it, does not change what the page builder may show. Example: an FPO that wants farmer names off the
    public page gets nothing.
  - Nothing publishes from `fields_for` today. The page builder (B10) is told to use `public_fields`, so
    nothing leaks now, which is why this is not a P1. But a partner payload (no `partner_fields` helper
    exists) or a portal preview that reads `visibility` from `/config/fields` would leak the phone
    number. That breaks CLAUDE.md §6 and the D-017 "visibility rules enforce privacy centrally".
- **Fix:**
  - In `_check_tenant`, refuse `override.visibility` that is more open than the base visibility
    (`rank = {"internal": 0, "partner": 1, "public": 2}`; about 2 lines plus the message).
  - Then `public_fields(entity, fpo_code)` can return
    `[f.name for f in fields_for(entity, fpo_code) if f.visibility == "public"]`.
  - Add one table case to `test_invalid_yaml_is_refused_with_the_file_and_key`.
- **If skipped:** CLAUDE.md §6 depends on every future reader remembering to ignore tenant
  visibility, and tenant opt-outs do nothing on the public page.

**P2-2 The ID-document consent gate and bucket choice have no test** (`registry/service.py create_id_document`)

- **What happens:** The only unit test reaches the endpoint with an unknown farmer, so it gets
  `not_found` before the consent check. No test checks that:
  - another farmer's consent is refused;
  - a revoked consent is refused;
  - a consent of the wrong type is refused;
  - the presign targets `S3_BUCKET_IDDOCS`.

  The integration file does not cover it either, and the Verifier's LocalStack check only proves that
  the upload works. This is a security branch (CLAUDE.md §4: security logic leaves one test).
- **Fix:** Add one unit test with a stubbed session/`_farmer_in_scope` and a monkeypatched
  `storage.presign_put`. Assert three refusals (`validation_error`, field `consent_record_id`) and one
  success with `bucket == settings.s3_bucket_iddocs` and a key prefix of `{fpo}/{farmer}/`.
- **If skipped:** a later edit could drop a consent condition or the `bucket=` argument (which would
  send Aadhaar images into `evidence`), and no test would fail.

   blank (about 2 lines plus one test case).

## Ponytail review (skill `ponytail:ponytail-review`, trimmed)

What this change does: it adds YAML files that say which fields each FPO captures and which features it has
on. The API refuses to start if they are wrong, serves them to the apps, and enforces them when farmers and
plots are created. It also adds CSV imports for farmers, villages and inputs, with a per-row report, and
two routes that exist only when a flag is on (ID documents, producer groups). Load assumed: pilot, one to a
few FPOs, imports run by an admin a few times a season.

**Should fix**

1. **A tenant file can make a private field look public** (`core/fieldconfig.py:184`). The loader accepts
   `phone: {visibility: public}`, and `/config/fields` then calls the phone public. Refuse widening in
   `_check_tenant`. Then the page helper can honour the tenant's narrowing. If skipped, the privacy rule
   depends on every future reader remembering a special case. (= P2-1)
2. **The consent check on ID documents has no test** (`registry/service.py create_id_document`). Wrong
   farmer, revoked or wrong-type consent, and the bucket choice are never exercised. Add one unit test.
   If skipped, a later edit can send Aadhaar images into the wrong bucket unnoticed. (= P2-2)
3. **Event field names in the YAML do not match B06's payloads.** Intake `quantity` vs `received`, and a
   required `pack_date` and `bags` that B06 does not have. Fix the YAML at merge. If skipped, those events
   fail on every phone once enforcement is wired. (= P2-3)

**Nice to have**

4. **A trailing comma in the CSV kills the whole file** (`imports.py:105`). Ignore blank extra cells. (= P3-1)
5. **Delete `required_fields` and `BUNDLE_PART`**, which nothing reads. (= P3-2)
6. **The village template uses tenant overrides, but the import does not.** Pass `None` for villages. (= P3-6)

Verdict: fix 1 and 2 first (small); 3 at merge.
Lean: -16 lines possible.
Not checked: integration tests, `alembic check`, LocalStack presign, 5,000-row timing (Docker down).

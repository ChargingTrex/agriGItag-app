### P2

**P2-1: The API process starts without `JWT_SECRET`, and with an invalid prod config. The report and
README say it does not.** `main.py:195` (`app = create_app()`), `core/config.py:66`, `infra/README.md`
("the API does not start without it").
- *What it does:* `Settings()` is built lazily, on the first `get_settings()` call, which happens inside a
  health probe. uvicorn reaches `Application startup complete`.
  - `HEAD /v1/healthz` answers 200.
  - `GET /v1/healthz` answers 503 with `error: ValidationError` for db, redis and s3 (probe above).
  - The same happens with `ENV=prod` plus a set `OTP_DEV_CODE`, or with a secret under 32 bytes.
  - `test_secrets_fail_closed` only checks that `Settings()` raises, so its docstring ("no JWT secret
    means no start") is not backed by the test.
- *What goes wrong:* this is not an auth bypass, because no code default exists and anything reading the
  secret raises. But:
  - (a) A misconfigured prod API passes the phones' HEAD reachability probe. Phones then push into
    requests that fail with 500, instead of seeing "offline".
  - (b) The GET healthz makes a config error look like an outage of all three dependencies.
  - (c) The docs promise a guarantee that B02 will rely on.
- *Fix:* validate at boot. Add a FastAPI `lifespan` that calls `get_settings()` before serving.
  - The lifespan does not run for `export_openapi` or the ASGITransport unit tests, so neither needs a
    placeholder.
  - Alternatively, call `get_settings()` in `create_app()` and give `export_openapi` the same `setdefault`
    placeholder as `gen-error-codes.py`.
  - Add a test that enters the lifespan without `JWT_SECRET` and expects `ValidationError` (for example
    `with TestClient(app):`).
- *If skipped:* the README's claim stays false, and a prod deploy that forgot the secret looks reachable
  to every phone. It must land before B02 merges. It can be a two-line B00 follow-up or the first change
  in B02.

### P3

- **P3-1: An empty `OTP_DEV_CODE` is accepted and stays `""`, not `None`.** `.env.example` says
  "unset or empty in prod", and `Settings(env="prod", …, otp_dev_code="")` is accepted with
  `otp_dev_code == ''`. If B02 writes `if s.otp_dev_code is not None and code == s.otp_dev_code`, an
  empty submitted code matches. Normalise `""` to `None` with a `field_validator`, or put it in B02's
  brief: "treat a falsy `otp_dev_code` as off".
- **P3-2: Settings validation errors are logged with their input values.** Pydantic includes a
  truncated `input_value` dict (env, `database_url`, `jwt_secret`, `otp_dev_code`) in the message. P2-1
  makes `_check` log it at WARNING on every GET healthz, which means every 5 s from the compose
  healthcheck and on every load-balancer probe. In the live probe the secret's middle was cut off by
  truncation, but a short rejected secret or the DSN password at either end of the dict can appear.
  Fix: add `hide_input_in_errors=True` to `SettingsConfigDict`. A one-line fix that goes with P2-1.
- **P3-3: The 405 on `/v1/healthz` sends `Allow: GET`, although HEAD is served too.** Starlette takes
  the methods of the first partially matching route. RFC 9110 wants every supported method. This is
  cosmetic for a health route. Put it in TODO, or fix it with a single `methods=["GET"]` route plus an
  explicit HEAD branch if B02+ routes hit it.
- **P3-4: Ledger and changelog nits.**
  - The hatchling row's purpose column still says it "Builds the `agritrace_page` wheel" only. Add
    "and the `agritrace` API package".
  - The CHANGELOG B00 line has no `WP-` prefix. The Orchestrator rewrites it at merge anyway.

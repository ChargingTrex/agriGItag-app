# M04 review, round 1: capture kit (CameraCapture, PhotoCompressor, ExifRewriter, PhotoQualityCheck, GpsFix, Clocks, VoiceNoteRecorder)

**Verdict: FAIL** because of **1 P1**. `PhotoCompressor` writes the evidence photo and its thumbnail **next to the
camera file**. The camera plugin puts that file in the OS-purgeable cache: `getCacheDir()` on Android and
`FileManager.temporaryDirectory` on iOS. The header tells M07 to store that path in the Media table. A photo that
waits days for signal can be deleted by the OS before upload, and Android does this when storage runs low,
which is exactly the "Phone is full" case. That is an evidence-loss path. The fix is about 5 lines plus one
test (P1-1).
Everything else is good. The custom EXIF writer is justified (I confirmed the package:image bug in its source) and
it produces valid TIFF: an independent reader (Pillow 12.1.1) parses every tag. The ladder, the GPS rule, the clocks
and the 30 s cap are correct and tested. All commands are green, apart from one pre-existing M01 host-timing flake
(P3-5).
There are also **1 P2** and **7 P3** findings.

## ponytail-review (skill invoked; trimmed)

**What this change does:** It adds the phone's capture kit. It opens the back camera, shrinks the photo to 1600 px
and about 300 KB in a background isolate, rewrites EXIF to keep only time, GPS and orientation, checks brightness
and blur, waits for a ≤ 20 m GPS fix for up to 60 s, and records a voice note of up to 30 s. Load: one farmer, one
photo at a time, on a 2 GB phone.

**Must fix**

1. **Evidence photo is saved in a folder the phone may empty** (`photo_compressor.dart:70-71, 114-118`)
   - **What this is:** The compressor writes `<camera file>_1600.jpg` and `_thumb.jpg` in the same folder as the
     camera file.
   - **Problem:** The camera plugin writes into the app cache (Android `getCacheDir()`,
     `ImageCaptureProxyApi.java:90`) or into tmp (iOS `FileManager.temporaryDirectory`, `DefaultCamera.swift:783`).
     The OS deletes those folders when storage is low (Android) or when the app is not running (iOS). An entry
     that waits offline for days loses its photo before upload.
   - **Fix:** Take the output folder as a required argument (`required Directory outDir`). M07 passes app support
     storage. Write both files there, and add one test that they land in `outDir`.
   - **If we skip it:** Photos go missing on exactly the low-storage phones the pilot targets, and the entry
     uploads with no proof.

**Should fix**

2. **A failed stop leaves the voice note waiting forever** (`voice_note_recorder.dart:88-107`)
   - **What this is:** `stop()` sets `_stopping`, calls the plugin, hashes the file and completes `result`.
   - **Problem:** If `_rec.stop()` throws (for example a PlatformException after an audio interruption) or the
     file read throws, `result` never completes, and every later `stop()` returns the same stuck future.
   - **Fix:** Wrap the body in `try`/`catch` and call `done.completeError(e, st)`. Add one test where the fake
     throws on stop.
   - **If we skip it:** M07's problem-report screen spins forever and the farmer's note is lost with no message.

**Nice to have**

3. **OffsetTimeOriginal is dropped when the camera writes the time without an offset** (`exif_rewriter.dart:45-48`).
   Fill 9011 from `capturedAt` on its own when it is missing. One line.
4. **AAC branch untested.** One test with the fake returning `isEncoderSupported == false` should expect `.m4a` and `aacLc`.
5. **VoiceNoteRecorder never disposes the AudioRecorder it creates.** Add `Future<void> dispose() => _rec.dispose();`.

Verdict: fix 1 and 2 first. Lean: nothing to delete. The custom TIFF writer is the one large piece, and the
package bug justifies it.
Not checked: real devices, PSS, and whether CameraX writes OffsetTimeOriginal.

## Findings

### P1

- **P1-1 Evidence and thumbnail land in OS-purgeable storage** (`lib/core/capture/photo_compressor.dart:70-71`,
  `:114-118`, header `:6-7`)
  - **Problem:**
    - Outputs go "next to [source]". [source] is the camera plugin's file in `getCacheDir()` on Android
      (camera_android_camerax 0.7.2 `ImageCaptureProxyApi.java:90`) or in `temporaryDirectory/camera` on iOS
      (camera_avfoundation 0.10.3 `DefaultCamera.swift:783`).
    - The file header tells M07 to store the result in the Media table, so `Media.localPath` and `thumbPath` would
      point into the cache.
    - mobile-design §3: entries wait up to 7+ days offline, and the full-size file is only deleted on confirm. The
      thumbnail is the only copy kept after that.
    - Android clears the cache under storage pressure (UserFlows "Phone is full") and iOS clears tmp. That is an
      evidence-loss path (CLAUDE.md §6: evidence photos written once).
  - **Fix (smallest):**
    - Add a required `outDir` argument to `compress` and pass it into the isolate job.
    - Write `<outDir>/<stem>_1600.jpg` and `<outDir>/<stem>_thumb.jpg`.
    - Say in the docstring that the caller must pass non-purgeable app storage.
    - Add one test that asserts both paths are under `outDir`.
    - Update the header's caller line.
  - M07 then picks the directory (e.g. `getApplicationSupportDirectory()/media`). Adding `path_provider` belongs in
    M07; it is already transitive.

### P2

- **P2-1 `VoiceNoteRecorder.stop()` error path never completes `result`** (`voice_note_recorder.dart:88-107`)
  - **Problem:** If `_rec.stop()` or `readAsBytesSync()` throws, `_stopping` stays true and `_result` never
    completes. The docstring says "[result] completes either way". The 30 s timer path also swallows the throw.
  - **Fix:** `try { … } catch (e, st) { done.completeError(e, st); }` around the plugin stop and the hash, plus one
    test with the fake's `stop` throwing.
  - This is "error handling that prevents data loss" in Ponytail's never-cut list.

### P3

- **P3-1 Offset can go missing** (`exif_rewriter.dart:45-48`)
  - **Problem:** `capturedAt` fills DateTimeOriginal **and** OffsetTimeOriginal only when the source has no 9003. A
    camera that writes 9003 without 9011 gives a local time with no zone, which weakens the server's FR61
    time check.
  - **Fix:** Fill 9011 on its own: `exif.putIfAbsent(0x9011, …)` when `capturedAt != null`.
- **P3-2 Segment order** (`exif_rewriter.dart:60-70`)
  - **Problem:** APP1 is spliced right after SOI, before the encoder's JFIF APP0 (order E1, E0). Pillow 12.1.1 and
    ImageIO read it, and ExifInterface scans markers. Strict JFIF wants APP0 first; strict Exif wants APP1
    first, so either order breaks one of the two specs.
  - **Fix:** Optional: drop the APP0 when splicing. Otherwise leave it and note it.
- **P3-3 Header names a missing test** (`exif_rewriter.dart:5`)
  - **Problem:** The caller line lists `test/capture/exif_rewriter_test.dart`, which does not exist; the EXIF tests
    live in `photo_compressor_test.dart`.
  - **Fix:** Correct the header.
- **P3-4 Voice coverage gaps**
  - **Problem:** The AAC-LC/M4A branch has no test. `VoiceNoteRecorder` has no `dispose()` for the `AudioRecorder`
    it creates (record 6.2.1 `record.dart:157`).
  - **Fix:** One test (fake `isEncoderSupported` → false, so `.m4a` and `aacLc`) and a one-line `dispose`.
- **P3-5 Local `-x golden` runs flake on M01's `perf` test**
  - **Problem:** 2 of 3 runs failed on '500 entries + 500 media save in under 2 s (host)'. It passes alone and in the
    full `flutter test` run. It is already skipped on CI. The worker saw the same "+55 −1".
  - **Fix:** Verifier and reviewers should run `flutter test -x golden -x perf` (or `--concurrency=1` for perf). No
    code change is needed in M04.
- **P3-6 D-002 ADR text** (Orchestrator)
  - **Problem:** D-002.md is about Flutter, platforms and APK size, and does not mention the 2 GB/PSS memory reason
    the preset comment relies on.
  - **Fix:** Add one line to D-002 ("capture preset `veryHigh`, see camera_capture.dart") so the greppable link
    reads naturally. The ruling is already recorded in TODO.md.
- **P3-7 Merge main before merging** (Orchestrator/worker)
  - **Problem:** Conflicts in CHANGELOG.md, pubspec.yaml (M05's just_audio/url_launcher sit next to M04's
    image/record) and LIBRARIES.md (both append).
  - **Fix:** Re-resolve the lock with `flutter pub get`, then rerun analyze and the full suite. Main has 198
    tests, so expect about 214.

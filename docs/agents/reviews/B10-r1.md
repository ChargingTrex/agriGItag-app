## Findings

### P2-1: `plot.declared_area` and the grade-reading fields are `partner` in YAML but always published (needs Architect-Gate ruling)

- `apps/api/config/fields/plot.yaml:16` marks `declared_area` as `visibility: partner`.
- `apps/api/config/fields/quality_reading.yaml:8-11` marks `stage`, `parameter_code`, `measurement` and `source` as `partner`.
- `builder.py:460` always sends `farm_area`, and `builder.py:494-503` always sends the readings, because the W01 schema requires them. D-034 records this, and TODO.md has a line for it.

Severity:
- **Not a P1.** The source documents put both on the page. "What the public page shows: farmer name (unless the FPO opts out), village, farm size, …" (System Architecture §Privacy). Grade readings are FR51 / PRD §12.1. Neither is a CLAUDE.md §6 category.
- **Still a P2.** Today the YAML, the single config source (D-017), says these values never reach the public. A tenant also cannot narrow them. And farm size plus village plus lot kg next to an opted-out "Farmer N" can make a small-village farmer identifiable.

Exact fix: Architect-Gate picks one option and records it in D-034.
- **(a), recommended, matches the source docs.** Set `declared_area` and `quality_reading.{parameter_code,measurement,source}` to `visibility: public` in `config/fields/`. Make the fieldconfig loader refuse a tenant override that narrows them, because the page cannot honour it. Or document them as `core` public.
- **(b)** Make `farm_area` and `readings` optional in the W01 schema, and have the builder send them only when `public_fields` lists them.

Either way the YAML and the page stop disagreeing.

### P2-2: An older build can overwrite a newer page (check-then-write race in `build_page`)

`service.py:308-311` reads the batch without a lock and checks `build.build_no < batch.current_build_no` once, at the start. After that it does `load`, `render` and the S3 writes (`:337`), still unlocked.

The case:
1. Build N (publish) starts.
2. The admin finds an error (for example a revoked name consent, or a wrong FSSAI number) and calls rebuild.
3. Build N+1 runs on another prefork worker process and finishes first.
4. Build N then writes its objects last.

The latest S3 objects now hold N's stale data (the name visible again), while `/builds` shows build N+1 `built`. Nothing repairs it until the next rebuild.

Exact fix, one argument: `batch = await session.get(Batch, build.batch_id, with_for_update=True)` at `service.py:308`. The lock is held until the commit at `:341`. `rebuild` already takes the same lock (`_batch_in_scope(..., lock=True)`), so builds and rebuilds of one batch run one after another. A queued older build then sees the bumped `current_build_no` and becomes `superseded`. The lock also makes duplicate D-009 deliveries harmless. Add one unit or integration test: run build 1's task after build 2 is created, and assert `superseded` and that S3 still holds generation 2.

### P3

1. **P3-1 CDN invalidation misses the bucket paths.** `service.py:278` invalidates only `/b/<code>*`. But data.json and the photos are linked as `{PUBLIC_BASE_URL}/batches/<code>/…`, and index.html can be opened at that path too. A CloudFront min-TTL above 60 s would serve a stale data.json. Fix: `"Paths": {"Quantity": 2, "Items": [f"/b/{code}*", f"/batches/{code}/*"]}`.
2. **P3-2 qr.png is `immutable` but its name is not a hash.** `service.py:255`: the content depends on `PUBLIC_BASE_URL` as well as the code, so a domain change leaves a year-old QR in caches. E3 says "immutable on hashed assets". Fix: `PAGE_CACHE` (or `public, max-age=86400`) for qr.png.
3. **P3-3 A failed S3 or CloudFront call leaves the build `queued` forever.** `service.py:337-342`, `tasks.py:17`: there is no autoretry, so "stays queued for a retry" never happens and `/builds` shows no error. Fix: `@app.task(name=…, autoretry_for=(ClientError,), retry_backoff=True, max_retries=5)`, and correct the docstrings.
4. **P3-4 Public photo copies are never withdrawn.** If a photo is later corrected away or rejected, its content-addressed copy stays readable at the same public URL. Add it to the void/withdraw TODO (TODO.md line 253): delete the copies that the new snapshot no longer references.
5. **P3-5 Shared fixture via import plus an F811 ignore.** `tests/integration/test_publishing.py:26-32`, `pyproject.toml:78`. This works, but it couples two test modules. Move `migrated`, `world`, `World`, `_batch` and `_moisture` to `tests/integration/conftest.py` (or a `tests/integration/helpers.py` for the plain helpers), then drop the per-file ignore.
6. **P3-6 The integration revoked-consent test covers only the all-null case.** `test_publishing.py:220-237`: both lots end up `None`, so the test would also pass if names were never shown. Give lot 1's farmer an unrevoked consent and assert `[name, None]` plus `"Farmer 2"`. The unit test covers the mixed case, so this only strengthens stack evidence.
7. **P3-7 No stack test of the photo copy.** No integration test puts a verified photo with variants on an event. So `copy_object` from `evidence` (key split, `ContentType image/webp`, `CacheControl` immutable, object present) is never exercised against LocalStack. Add one photo in `test_publish_writes_objects_with_matching_generation` and `head_object` the two copies.
8. **P3-8 TODO line missing for client regeneration.** The report says "Dart/TS clients not regenerated (Orchestrator `make clients`)", but TODO.md has no B10 line. P04 needs rebuild, builds, qr.png, labels.pdf and the proxy. Add `- [ ] B10 → B12/P04: run make clients (rebuild, builds, qr.png, labels.pdf, lot qr, public proxy)`.
9. **P3-9 Docstring `Raises:` gaps (CLAUDE.md §5.2).** `builder.photo_copies` (`:252`) can raise `KeyError` when `variants` lacks `thumb_url` or `medium_url`. `builder.assemble` (`:519`) and `_lot` (`:426`) pass through `KeyError` from `fieldconfig.public_fields` (unknown entity) and the `AssertionError` from the pin check. Document them.
10. **P3-10 Lean.** `build_out` (`service.py:129-150`) copies ten fields by hand. Fix: `BuildOut.model_validate(build, from_attributes=True).model_copy(update={"error": build.snapshot.get("error") if build.status == "failed" else None})`, about −9 lines.

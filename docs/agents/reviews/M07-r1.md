## Findings

### P1 (blocks merge)

**P1-1. The CI ledger check fails on `path_provider`** (`docs/LIBRARIES.md:127`).
`libraries-check.py` treats the whole Library cell, split on commas, as package names. So the cell
`path_provider (now declared directly; was transitive via drift_flutter)` becomes the key
`path-provider (now declared directly; was transitive via drift-flutter)`. The CI job `.github/workflows/ci.yml:68`
then exits 1.
**Fix:** make the Library cell just `path_provider` and move the note "now declared directly; was transitive via
drift_flutter" into the "What for" or "Why this one" cell. Then re-run
`uv run --no-project --with pyyaml python infra/scripts/libraries-check.py` and check that it exits 0. The worker
report says this gate passed, but it was never run.

### P2

**P2-1. The tap count starts at F04, not at the farmer home, and the home path is not asserted**
(`test/features/farmer_flows_test.dart:82-98`, `test/features/screens_test.dart:18-49`, report §Tests).
Counted from `/home`, these are the real numbers:

| Path from home | Taps (each counted tap is listed) | Meets "≤ 3 + 1"? |
|---|---|---|
| Next-task card → event | card (1), [extra choice, optional], shutter (2), tick (3) | yes: 3 + 1 |
| "Log" → grid → event | Log (1), card (2), [extra], shutter (3), tick (4) | no: 4 + 1 |
| Farmer with 2+ active lots | add 1 for the "Field n" pick | no: 4 + 1 from the card |
| First out-of-order event | add 1 for Yes/No, once per gap | asked once (by design) |
| Weak GPS | add 1 for "Save anyway" after 60 s | exception path |

Stepper +/− taps (5 taps for 6 bags) are value changes, not steps. UserFlows names "+ / −" as the extra choice
itself, so not counting them is fair. UserFlows defines the three taps as "choose the event, take the photo,
confirm". The task card meets that from home. The grid path only meets it if the "Log" tap counts as navigation, and
the report does not say so.
**Fix:**
1. In the home task-card test, assert `h.taps == 4` (card, Next, shutter, tick) right after `/home/saved`.
2. Add the table above to the report, so the Verifier and Q01 count the same way.
3. Optional: when there is exactly one active lot, also skip the lot step on the grid path. It already does that.
   Nothing more to change in code.

**P2-2. Fertiliser/pesticide cannot be logged when the input master is empty** (`lib/features/event_log/extra_choice.dart:87`, `:189`).
When `input_id` is enabled, the screen shows only `_Products`. If the inputs bundle is empty, `_Products` shows
nothing and there is no "Next" button. This happens before the first pull, or when the FPO has not imported its input
list yet, which is likely early in the pilot. The farmer is stuck on that screen and can only go back or call. The
controller already handles `input == null`: it sends `{bags, "bag"}`, and `input_id` is not required by default.
**Fix:** in `_ProductsState.build`, when `snap.data!.isEmpty`, return the same `next` button (pass it in, or pass
`onPicked` and build a `FarmerButton`). Add one screens_test case: empty inputs bundle → Next → photo → saved with
`{'quantity': {'value': n, 'unit': 'bag'}}`.

**P2-3. The "asked once" memory is a made-up flag in the server-mirror `Flags` table** (`lib/features/event_log/event_log_controller.dart:81-82`, `:270-319`).
- `Flags` is documented as "Flags raised by server rules … Server flag id". It is written by M02's pull.
- The local row uses type `order_gap`. The comment says this is the "server rule code `order_gap`", but the server
  code is `event_out_of_order` (main `rules_flags/rules/event_order.py`). The server's details are
  `{event_type, occurred_on, missing}`, with no `lot_id`.
- So a pulled server flag never counts as "already asked". If M02's pull replaces the farmer's flags, the local rows
  disappear and the question comes back, which breaks "asks once". The farmer's Yes/No (`farmer_says_done`) never
  reaches the server.

**Fix (smallest):**
1. Correct the comment: local marker only, not a server code.
2. Make the hand-off to M02 concrete in TODO.md: the pull must keep rows whose `flagId` it did not send, or the
   "asked" marker moves to a local-only store (e.g. a `SyncState` key `order_asked:<lotId>` holding the gap list).
3. Record in TODO.md that the Yes/No answer is local only.

No new code is needed in M07 if M02 accepts the hand-off. Otherwise use the `SyncState` key (about 10 lines).

**P2-4. Input quantities will never be in kilograms against the real server** (`event_log_controller.dart:251-259`, `:406-412`).
On main, B07's `input_json` serves `{id, name_en, name_local, manufacturer, category, unit}` with no `pack_size`. So
`packSize` is always null and every input entry is `{bags, "bag"}`. UserFlows asks for "Kilograms (bags × bag size)".
M07 handles this correctly, has a `shortcut:` mark, and lists it in TODO. The gap is in B07, so it does not block M07.
**Fix (Orchestrator):** open a B07 follow-up to add `pack_size` (as a decimal string) to `input_json`, and an M03
follow-up to parse it in `InputItem`. Then delete the raw-bundle read in `inputs()`.

### P3

1. **Old photo files are kept when the farmer goes Back from Confirm and shoots again**
   (`event_log_controller.dart:357-362`). `setPhoto` overwrites `d.photo` without deleting the previous compressed
   file and thumbnail. Nothing purges unreferenced files in `<app support>/media`, and each one is about 300 KB on a
   2 GB phone. Fix: in `setPhoto`, first `deleteQuietly(state.photo?.path)` and `deleteQuietly(state.photo?.thumbPath)`
   when it is a different path.
2. **The camera stays open under the Confirm screen** (`event_flow_screen.dart:134`, `camera_step.dart:72-76`).
   `context.push(...confirm)` keeps `CameraStep` mounted, so the preview and the GPS stream keep running while the
   720 px decode runs. Fix: call `_camera.dispose()` (or pause the preview) before `widget.onAccepted()`, and reopen
   it in `didChangeDependencies` or on return. Measure on the Go AVD (Q01) first.
3. **System Back on the F09 sheet records "No"** (`event_flow_screen.dart:84-120`). `isDismissible: false` only
   blocks taps on the barrier. Android Back still pops the sheet with `null`, and `answer ?? false` stores
   `farmer_says_done: false`. Fix: wrap the sheet body in `PopScope(canPop: false)`.
4. **Ticking while recording drops the voice note and calls `ref` after dispose**
   (`voice_note_button.dart:64-67`, `confirm_screen.dart:59`). If the farmer taps the tick during recording, the
   entry saves without the note. The recorder's `result` later calls `ref.read(...)` on a disposed widget, which
   Riverpod 3 reports as a StateError, and the file is never deleted. Fix: disable the tick while recording (expose
   `_recording` through the draft), or `await` stop in `dispose`.
5. **The entry's GPS time is not the shutter's** (`event_log_controller.dart:465`). `gpsTime` is
   `d.fix?.gpsTime`, the most accurate fix seen, which may be older than the photo. `d.clocks.gpsTime`, the shutter
   clock, is stored but not used. Arch §Offline-first means capture-time clocks. Fix:
   `gpsTime: Value(d.clocks?.gpsTime ?? fix?.gpsTime)`.
6. **Undocumented private members** (CLAUDE.md §5.2 "every function, public and private"). These have no `///`:
   `EventLogNotifier._saving` / `_db` / `_now` (`event_log_controller.dart:186,192,194`), `_EventFlowScreenState` and
   its `_step` / `_lots` (`event_flow_screen.dart:42-44`), the `_Step` values, `_SavedScreenState._undoing`, and the
   `_VoiceNoteButtonState` fields. The `ExtraChoice.build` doc says it "Returns a list of widgets", but it returns a
   `Column`. Fix: one line each.
7. **The problem kinds are listed twice** (`extra_choice.dart:121-126` against `farm_event.dart:105`). Fix: zip
   `kProblemTypes` with an icon map, or drop the const. Lean: −1 list.
8. **Hard-coded values (50 kg bag, 3 varieties, 7-day drying reminder):** accepted for now. Each has a `shortcut:`
   with the limit and when to upgrade, plus a TODO row. Main's B07 crop bundle has no bag weight, variety list or
   drying span, so there is nowhere to move them yet. These are values, not requiredness, so D-017 is not broken.
   Re-check when B07/M12 add them.
9. **Voice clips:** only 8 of the new prompt ids have a clip (all placeholders). The others, such as `eventHarvest`,
   `bagsPrompt` and `nurseryPrompt`, play nothing; the text shows and VoicePlayer counts the miss. Every screen does
   have a Tamil-first `VoicePromptBar`. This is listed in TODO (recordings).

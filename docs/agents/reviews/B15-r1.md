## Security review (SEC lens)

**(a) Per-entry session ownership. Holds.** `core/auth.py:279 assist_session_farmer` filters on
`id == assist_session_id AND officer_user_id == caller.user_id`, with no `ended_at` filter (D-032 block at :295).
`events/service.py:855 _entry_caller` raises `AssistSessionInvalidError` on None, so the entry is rejected and
never runs unassisted. The entry's farmer is checked in three places. Consent: `identity/service.py
_check_writer` compares `on_behalf_of_farmer_id` whenever `assist_session_id` is set. Lot events:
`events/service.py:295 _check_subject`. Plots: the new `registry/service.py:977`, which runs before the resend
lookup, so a replay of a plot for another farmer is also refused. Each raises `forbidden`. An officer with two
FPO memberships who uses a session from FPO 1 under an FPO 2 token is still stopped: every handler scopes the
farmer, lot or plot to `user.fpo_id`. A farmer token can own no session (sessions are field-officer-only), so
it gets `assist_session_invalid`.

**(b) `assist_session` kind. Holds.** `identity/service.py:886` checks for a field officer before anything is
read. `start_assist` (unchanged) runs `_farmer_in_fpo`, which gives `not_found` for another FPO's farmer, and
gives `conflict` for an id owned by another officer or farmer. Pending farmers are allowed, which onboarding
needs.

**(c) `farmer` kind. Holds, with P2-2.**
- Role: `registry/service.py create_farmer_from_sync` allows FIELD_OFFICER and FPO_ADMIN only.
- Stored state: `pending` farmer, plus the `users`/`memberships` rows `create_farmer` already writes.
- Same `client_id` in the same FPO → `duplicate`, with the stored id as `server_id`.
- Same id in another FPO → `client_id_conflict`, on both REST and push. This leaks only the existence of a
  random UUIDv7. That is negligible.
- `farmer_phone_taken` is unchanged. Its details carry no number.
- **Resend with a different body:** the stored farmer wins. I accept this as the D-031 compromise. It is
  written in the DECISION block at `registry/service.py:741` and in TODO. Plots compare pin and size because
  those are locked evidence. A farmer is `pending` and goes through admin review and `PATCH`, so a silently
  ignored edit is recoverable. No change asked.
- **Audit:** `Farmer` and `Membership` are `Audited`. The `farmer` kind clears assist on both the caller and
  the audit context, so the farmer, user and membership rows carry actor, device and request id, with null
  `on_behalf_of`/`assist_session` (line 8 asserts this). Consent, plot and event rows get the entry's S and F.
  `assist_sessions` rows are not `Audited` (P3-6, pre-existing B02).

**(d) `Token.old_value` restamp. Correct, no leak.** `ContextVar.reset(token)` restores the value from before
the `set` that made the token, even after a second `set`, as long as it runs in the same context. `push` awaits
handlers directly in the request task (no `create_task`), so set and reset happen in one context. A task
spawned inside a handler would only copy the stamped value. `reset_audit_context(token)` sits in `finally`
(`events/service.py:946-948`), so the request context is back before the next entry and before
`_store_metrics`, also when an entry is rejected. `_entry_caller` runs before stamping, and a rejected session
never stamps. The audit listener reads the context in `after_flush` within the same task. The unit test
asserts the restore. A public getter in `core/audit.py` would be cleaner, but that file is outside the
declared paths (P3-7).

**(e) `POST /v1/farmers` 201 on a repeat. Acceptable, no change.** Acceptance output 2 allows "201 both times,
documented". It is documented in `FarmerIn.client_id`'s `description=` (in OpenAPI) and in conventions.md
§Sync. It matches the house pattern: `POST /v1/assist/start` and plot resends also answer 201 with the stored
row, and conventions §Idempotency says "a no-op that returns the stored result". Under D-020 the change is
additive: an optional request field, and the status code is unchanged.

**(f) Logs.** No log call is added anywhere in the diff. New error details carry only client-sent ids.

### P2

**P2-1. `_push_assist_session` has no `Side effects:` section** (`apps/api/agritrace/modules/events/service.py:803-826`).
- **What this is:** the handler for the `assist_session` kind.
- **Problem:** it inserts and commits through `start_assist`, but the docstring has no `Side effects:`. CLAUDE.md
  §5.2 makes that a reject. Interrogate does not catch it.
- **Fix:** add
  `Side effects:\n    Inserts an assist_sessions row and commits (through start_assist); nothing when the id is stored.`

**P2-2. A concurrent first send of the same farmer fails the whole push with 500** (`apps/api/agritrace/modules/events/service.py:794-797`; TODO.md B15 line 4).
- **What this is:** D-031 exists for "online `POST /v1/farmers` times out, then sync sends the same F". The
  phone may sync while the slow online request is still running.
- **Problem:** both requests pass `session.get(Farmer, F) is None` and insert `users(phone)` and `farmers(F)`.
  The loser gets an `IntegrityError` (`users.phone` unique or the `farmers` primary key). `push` catches it as
  `DBAPIError`, `append_only_error` returns None, and the error is re-raised. The whole push answers 500 and the
  entries after it are not processed. The TODO and the report say "the loser is rejected", which is wrong.
  There is no data loss: the phone's retry gets `duplicate`.
- **Fix:** follow the house pattern from `record_consent` and `write_version`: retry once after a rollback, so
  the winner is now visible.
  ```python
  data = {**entry.data, "client_id": str(entry.client_id)}
  try:
      farmer, created = await registry_service.create_farmer_from_sync(session, user, data)
      await session.commit()
  except IntegrityError:  # a concurrent first send of F won; re-run to get duplicate / conflict / phone_taken
      await session.rollback()
      farmer, created = await registry_service.create_farmer_from_sync(session, user, data)
  ```
  Then correct the TODO line. A unit test can monkeypatch `create_farmer_from_sync` to raise `IntegrityError`
  once.

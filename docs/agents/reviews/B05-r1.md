### P2
- **F1 — `lab_certified` is narrower than the binding spec.** §4 says "`lab_certified` when any reading
  source=lab with NABL number", and the profile key is `any_parameter_source`. The engine applies the rule
  only to readings that set a parameter grade, and only at `grading_stage` (`_lab_certified(rules, used)`).
  Pilot consequence: a NABL lab certificate for capsaicinoid (the Special label declaration) or a lab
  moisture reading at intake does **not** earn the FR51 badge (probes P10 and P10b). Either reading is
  defensible: "the grade is lab-backed" versus "an accredited result is attached". But it changes
  public-page output and has no DECISION. **Ask:** the Architect-Gate rules on it. Then either align the
  code (`used` → all readings of the batch) or keep it and amend §4 and the `GradeOut.lab_certified`
  description. The fixture case should pin whichever is chosen, because M03 ports this function.
- **F2 — the grade is not deterministic when `measured_at` ties.** `_latest` keeps the later *input* on equal
  times, and `compute_grade_for_batch` selects readings with no `ORDER BY`. Two grading readings with the
  same instant (for example a re-test entered at minute resolution in the portal) therefore grade by heap
  order: Standard or Special for the same data (P8b, P8c). The phone preview (D-006) can disagree with the
  server in the same way. **Fix** (about 3 lines): tie-break on `(measured_at, id)` in `_latest` (UUIDv7
  ids follow capture order), and add one fixture case with equal times in both orders.
- **F3 — no test for tenant scoping.** CLAUDE.md §4 asks for a test on new security logic. §6 makes FPO
  scoping an invariant. The integration suite has no case where a reading on another FPO's lot or batch
  gives 404, nor one where a farmer posts on another farmer's lot. **Fix:** about 15 lines in
  `test_quality.py`: seed a second FPO's lot and assert 404 on POST /quality-readings and on GET
  /lots/{id}/readings.
- **F4 — the portal CI job will break at merge. This is outside the worker's paths.** `docs/api/error-codes.md`
  goes from 12 to 22 codes and `packages/openapi/openapi.json` gains the quality paths. The portal's
  `npm run gen:check` (ci.yml:110) regenerates `apps/portal/src/api/generated/{schema.d.ts,
  error-messages.ts}` and fails on any diff. At base `279da1d` both tables list the same 12 codes, so B05
  introduces the drift. **Ask:** the Orchestrator runs `npm run gen:api` in `apps/portal` as part of the B05
  merge, and adds this step to the merge checklist for every backend WP that adds routes or error codes.

### P3
- **F5 — visual cap fixture (Orchestrator ruling).** The case "chilli visual 9.8 is capped at Standard"
  proves the cap only on moisture, which the API rejects at entry. Add one case where the cap applies to a
  parameter whose `sources_allowed` includes `visual` (probe P9 is a ready template). Keep the moisture
  case, relabelled as a pure engine case. Also, the TODO.md line "confirm the intended policy with
  compliance" is now answered by the ruling; the Orchestrator should close it. For the Verifier: the
  acceptance line "visual 9.8 → Standard" is evidenced at the engine level
  (`test_compute[chilli visual 9.8 is capped at Standard]`). Through the API, visual moisture correctly
  gives 422 `source_not_allowed`.
- **F6 — partial `limits` maps.** The semantics are safe (a grade missing from the map is unreachable) but
  easy for a compliance author to get wrong: `{Standard: ≤11}` alone silently caps every batch at
  Standard. Suggestion for the Architect-Gate: when `limits` is not null, `_cross_check` requires a key for
  every grade, with `{}` meaning unconstrained.
- **F7 — §4 profile data has gaps against FR50.** `unripe_marked_fruits`, `broken_fruits`, `insect_damaged`,
  `total_ash` and `capsaicinoid` (all `%`) have no `plausible` range, so −5 % broken fruits is stored. The
  worker copied §4 verbatim, which is correct. **Ask (Architect-Gate):** add `plausible {0, 100}` to every
  `%` parameter in §4 and the JSON before these limits are loaded.
- **F8 — a whitespace NABL number earns the badge.** `lab_nabl_no="  "` gives `lab_certified=true` (P10c).
  Strip whitespace and set `min_length=1` on `QualityReadingIn.lab_nabl_no`.
- **F9 — `compute()` does not check units.** Entry checks units, but if a later profile version changes a
  unit, readings stored under the old unit are graded against the new limits without conversion. Treat a
  unit mismatch as `missing` in `compute()`, or note it as a `# shortcut:`.
- **F10 — calibration and stage policy (documented, not tested).**
  - Calibration is judged on the client's `measured_at`, so backdating defeats expiry. There is no check
    that `measured_at` is not in the future or far from `device_time`/`server_received_at`. A flag would
    do; rejecting would break offline-first.
  - The instrument kind is not matched to the parameter: a `scale` is accepted for moisture.
  - The stage is not checked against `capture_stages`, the subject (a lot or a batch) or the role. A farmer
    can post an `intake` reading on their own lot and so raise the trail baseline. The worker listed this.
- **F11 — `yield_outcome` with a float.** It raises `TypeError` on a float `kg` or acres (P11b). The type
  hints say `Decimal`; B08 must pass `Decimal`. Either add it to `Raises:` or coerce with `Decimal(str(x))`.
- **F12 — `send_task` runs in the request path.** When Valkey is down, kombu's default publish retry policy
  can hold the request for seconds before the `except` runs. The existing `# shortcut:` covers a lost
  enqueue but not this latency. Pass `retry=False` or add a note.
- **F13 — LIBRARIES.md "Used in" cells.** Quality now uses fastapi, pydantic, sqlalchemy, geoalchemy2
  (`WKTElement`) and celery (`send_task`), and their "Used in" cells do not list it. The worker deferred
  this to avoid conflicts. The Orchestrator updates the cells at merge.

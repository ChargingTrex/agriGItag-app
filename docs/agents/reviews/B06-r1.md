## Findings

### P2

**P2-1 Concurrent retry of the same entry answers `stale_version` instead of `duplicate`** (`service.py` `write_version` / `_add_version`)
Case: on 2G the phone loses the connection while the server is still working through a 50-entry push, and retries after 2 s (A6). Request B reaches entry k while request A still holds the event row lock for it. B's `_existing()` ran before A committed, so B passes, blocks on `FOR UPDATE`, then reads `max = n` and raises `StaleVersionError`. `write_version` only catches `IntegrityError`/`_LostRace`, so the stored entry is reported `rejected stale_version` (and its photo URLs are not returned); M02 parks it in `needs_attention`. Same for version 1 if A commits between B's pre-read and B's `session.get(Event)`. Not an overwrite, but it breaks A3 ("a retry returns the original result").
Fix (≈4 lines): in `write_version`, catch `StaleVersionError` too — rollback, `found = await _existing(...)`, return it if present, else re-raise. Add one unit/integration test (call `_existing` path after a forced stale).

**P2-2 `plot_id` is not tied to the lot** (`service.py` `_check_subject`)
Case: a farmer sends a harvest on their own lot with `plot_id` = a neighbour's plot in the same FPO. It is accepted (only "plot in FPO" is checked), stored on `events.plot_id`, and FR69 / B08 location checks then compare the GPS fix to the plot the farmer chose. Trust-boundary validation gap.
Fix (1 line): for lot events require `v.plot_id in (None, lot.plot_id)` (else `validation_error`), or ignore the body and use `lot.plot_id`.

**P2-3 Voice notes cannot be pushed** (`schemas.py` `PhotoIn.content_type`)
M04 TODO (main, after this branch's base): voice notes arrive as `audio/ogg` (Android 10+) or `audio/mp4` (iOS, Android 8–9). The media schema accepts only `image/jpeg`, and `object_key` hard-codes `.jpg`; `verify_photo` would run EXIF/Pillow on audio. Fix: widen the Literal to the three types, derive the extension from the type, and in `verify` skip EXIF/variants for `audio/*` (sha256 only → `verified`). Or record a scoped decision that voice notes are out of the push for the pilot and tell M02/M04.

**P2-4 Task runner duplicates `worker.run_db_task`** (`tasks.py` `_run`, ~25 lines)
Main (B04 merge, D-009 amendment) has `agritrace.worker.run_db_task(work, *args)` with the same NullPool + `asyncio.run` body; the amendment says tasks use it. On rebase delete `_run` and call `run_db_task(evidence.verify, uuid.UUID(photo_id))`; move the D-009 DECISION comment reference accordingly. Not visible from the branch base, so not the worker's fault.

**P2-5 (recommendation for B10/portal) Original JPEG keeps exact EXIF GPS**
`variants.jpeg_url` points at the original evidence object, which keeps the phone's GPS (M04 keeps it on purpose). CLAUDE.md §6 forbids exact locations on public pages. B10 must link only the WebP variants (no EXIF; confirmed `webp_variant` copies none) or a GPS-stripped copy, and the privacy canary should test it. Already in main TODO (79269bc); B06 needs no change now.

### P3

- **P3-1 REST undo trusts body clocks.** `UndoIn.clocks` lets an online client pick the "at" time, so the 24 h window is advisory (the worker names the risk). For the REST route the server could judge `now` vs v1 `server_received_at`; the sync path must stay on device time. Also an undo of an already `undone` event is accepted (adds another undo version) — harmless, could be 409.
- **P3-2 Any user of the FPO can confirm any photo of the FPO** (prefix check only). Effect is limited to a HEAD and a verify enqueue; tighten to `version.entered_by_user_id == user.user_id` when convenient.
- **P3-3 Variant URLs are unsigned URLs on a private bucket.** `evidence` has no public read (infra/README), so `thumb_url`/`medium_url` returned by `GET /v1/lots/{id}/events` cannot be fetched by the portal or phone as-is. B10 copies or presigns; the portal/timeline needs presigned GETs (or store keys). Hand-off note for B10/P0x.
- **P3-4 Broker outage slows the push.** `enqueue` runs `send_task` per entry; with Valkey down each call waits on connect/publish retries, serially for 50 entries, and can pass the phone's 30 s timeout (feeds P2-1). Same family as B05 F12 in TODO; a short `publish_retry_policy`/connect timeout on `send_task` would bound it.
- **P3-5 `verify` overwrites the client-declared `exif_taken_at`/`exif_gps`** with the server-read values, so a declared-vs-actual mismatch is not kept. Acceptable (server is the source of truth); note for B08 if it wants that signal.
- **P3-6 `_errors()` helper is copied in `router.py` and `sync_router.py`** (8 lines). Keep one (sync_router can own it and router import it, no cycle that way).
- **P3-7 Merge hygiene.** `openapi.json` conflicts with main (regenerate after rebase); the two TODO lines the worker added duplicate the Orchestrator's 79269bc lines — keep one copy; after rebase re-run `gen-error-codes --check` (B04 may have added codes, so 39 can change).
- **P3-8 Test gaps (cheap).** No test that a farmer cannot write on another farmer's lot (`_check_subject` 404 path) or that body identity fields are refused (probe above shows they are; a 5-line unit test pins it).
- **P3-9 Envelope 413 vs 422 order.** A non-JSON body over 256 KB answers 422 (FastAPI parses first). Cosmetic once the ALB cap exists.

## Ponytail review (skill `ponytail:ponytail-review`, trimmed)

What this change does: adds the phone-to-server sync path. The phone pushes up to 50 offline entries; each is stored once (the phone's id is the key), with three clocks, an audit row, and presigned upload links for its photos; a worker then checks each photo's hash and EXIF and makes small WebP copies. Officers can correct and farmers can undo within 24 h, both as new versions.

Should fix:
1. **A retry racing the first send is reported as an error** (`service.py` `write_version`) — see P2-1. Fix: catch `StaleVersionError`, re-read, return `duplicate`. If skipped: farmers see "needs attention" on entries that were saved.
2. **Plot not checked against the lot** (`service.py` `_check_subject`) — see P2-2. One-line check.
3. **Voice notes rejected** (`schemas.py` `PhotoIn`) — see P2-3.
4. **reuse:** `tasks._run` = `agritrace/worker/__init__.py:run_db_task` on main — delete ~25 lines.
5. **merge:** `_errors()` near-copy in router.py and sync_router.py — delete 8 lines.

Nice to have: bound `send_task` time when the broker is down (P3-4).

Verdict: fix 1–3 first (round 2), 4–5 at rebase.
Lean: -33 lines possible.
Not checked: anything needing Postgres/LocalStack (deferred to the Verifier).

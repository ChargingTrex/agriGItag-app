## 2. Findings

### P1 (blocks the merge)

**P1-1 `privacy-lint.py` misses phone numbers in common Indian formats, and hyphenated Aadhaar numbers.**
- *What the code does:* `phone` is `(?<!\w)(?:\+?91[\s-]?)?[6-9]\d{9}(?!\w)`. It needs ten consecutive digits. `aadhaar` is `\d{4}\s?\d{4}\s?\d{4}`, which allows spaces but not hyphens.
- *What goes wrong:* `98765 43210`, `+91 98765 43210`, `98765-43210`, `(+91) 98765 43210`, `09876543210` and `2345-6789-0123` all pass with exit 0. Above, a1 is the requested fixture and the rest are from the probe. The 5+5 grouping is how Indian mobiles are usually written, so an officer typing a number into a free-text note would produce one. Phone numbers are the first item in CLAUDE.md §6, and BM-09 is "0 hits for phone". The control reports clean on the most likely leak.
- *How to fix:* Build the patterns from digits with optional separators. For example, phone: `(?<!\d)(?:(?:\+|00)?91[\s.-]?|0)?[6-9](?:[\s.-]?\d){9}(?!\d)`. Aadhaar: `(?<!\d)[2-9]\d{3}[\s.-]?\d{4}[\s.-]?\d{4}(?!\d)`. Use `(?<!\d)` instead of `(?<!\w)` so `tel:` and `ID:` prefixes still match. Add a fixture line for each format above to `dirty/index.html` and a test case for each. Then check that `clean/` still passes: it contains an FSSAI number of 14 digits, a hex hash and ISO timestamps. To stop `tel:+919876543210` reporting both rules, drop the `aadhaar` hit when it overlaps a `phone` hit.
- *If skipped:* W02/B10 pages and partner payloads can ship a farmer's phone number with BM-09 green and G4 signed. That is a privacy leak, which qa-rubric makes an automatic FAIL once found.

**P1-2 Precise coordinates slip through in pretty-printed JSON, in WKT, and in URL-encoded links.**
- *What the code does:* The scan runs line by line. `coordinate_precision` needs `lat|lng|lon` keys, or both numbers of a pair on one line separated by a literal comma. `polygon` needs a ring on one line or a `"type": "Polygon"` line.
- *What goes wrong:* `json.dumps(..., indent=2)` puts every array element on its own line. A GeoJSON Point with 7 decimal places, or a bare coordinate ring, passes with exit 0. Python's standard pretty-printer, which W01's JSON output or a partner stub may well use, defeats the rule. The same happens to `POINT(78.1335214 9.5598061)`, the PostGIS `ST_AsText` output, which is space-separated. It also happens to `q=9.5598061%2C78.1335214`, which is what `urlencode` produces for a map link, and to `{"x": …, "y": …}`. The tool's own docstring promises coordinates with more than 3 dp are caught.
- *How to fix:* Run the coordinate and polygon rules on the whole text with whitespace collapsed, not line by line. Report the line from `text.count("\n", 0, m.start()) + 1`. For `.json` files, the simplest robust fix is to `json.load` the file and walk it. Flag any float with more than 3 decimal places under a key matching `lat|lng|lon|latitude|longitude|coordinates|x|y|geom|boundary`, and any list of two or more numeric pairs. Add `POINT|LINESTRING|MULTIPOINT\s*\(` with a precise number to the WKT rule. Decode `%2C` (`urllib.parse.unquote`) before matching. Add an indent-2 Point, a WKT POINT and a `%2C` link to `dirty/`.
- *If skipped:* An exact farm location can be published with privacy lint at zero. CLAUDE.md §6 forbids this, and TODO §2 calls for rounding to 3 dp.

### P2 (fix in this round or file in TODO with an owner)

**P2-1 `benchmarks/collect.py` lets an older passing run hide a newer failing one.** `load_results` keys results by `id`, and the file whose name sorts last wins. The README's own naming, `<BM-id>-<WP-or-gate>.json`, makes `BM-07-Q04.json` beat `BM-07-G5.json`. The probe above shows a failing G5 run (450 ms) reported as PASS. *Fix:* keep the result with the latest `measured_at`, and exit 1 when that field is missing. Alternatively, judge every file and fail if any FAIL. Add one test with two files for the same id. *If skipped:* Q05 can sign G5 with a benchmark that is currently failing.

**P2-2 privacy-lint skips every file that is not `.html`, `.htm` or `.json`.** `SUFFIXES` is fixed. A folder holding a clean `index.html` plus `app.js` with a phone number and `area.geojson` with a Polygon reports "0 hit(s) in 1 file(s) scanned". The exit-2 guard only fires when no file matches at all. *Fix:* scan every file that decodes as UTF-8 (skip binaries by suffix list or a NUL-byte test), or at least add `.js .css .xml .txt .csv .svg .geojson .ndjson .webmanifest`. Print the skipped file count. *If skipped:* a partner export or sitemap in another format leaks unseen.

No.` / `S.No.` survey abbreviation. *Fix:* add the Tamil terms and `\bS\.?\s?F\.?\s?No\b|\bS\.\s?No\.?\s?\d`, plus a Tamil line in `dirty/`. Ask W01 for the exact Tamil strings it uses.

Q00 now ships `infra/scripts/privacy-lint.py` with the same purpose. Amend W02's acceptance so W02 extends it, or imports `scan_line`, instead of writing a second one. If W02 has already written one, the next round deletes one of the two.

**P2-5 Gate runs can pass while acceptance tests are still placeholders.** The README's gate command is `robot --exclude not-ready qa/robot/api`. If a WP merges without converting its placeholders, the gate run contains only the healthz smoke tests and is green. *Fix:* add a gate rule to `qa/README.md` (and ask the Orchestrator to mirror it in `qa-rubric.md`). `robot --dryrun --include not-ready --include WP-<each gate WP> qa/robot` must select 0 tests, otherwise the gate fails. Change both READMEs' evidence tables to `docs/agents/qa/<WP>/robot/` and drop the `git add -f` advice. *If skipped:* Verifiers file evidence in two places, and gate reports link to paths that are ignored.

**P2-7 The QA layer's own Python is not gated in CI.** `doc-coverage.py` runs interrogate only on `apps/api` and `apps/public-page`. Ruff runs only from pre-commit, which is local and optional. `infra/scripts/` and `qa/` therefore pass CI even if their docs or lint regress. *Fix:* in the `docs` job, add `uvx ruff check infra/scripts qa` and `uvx interrogate --fail-under 100 infra/scripts qa/robot/lib qa/tests`. Alternatively, add those paths to `PYTHON_APPS`-style targets in doc-coverage.py.

**P2-8 `parse_flutter_results` can report a crashed run as green.** It counts only `testDone` events. A run that dies mid-way (emulator crash, OOM on the 2 GB AVD) leaves started tests with no `testDone`, and an empty log gives `{passed: 0, failed: 0}`. A Q01 cell asserting `failed == 0` then passes. *Fix:* count tests started but not done as failed. Read the final `{"type":"done","success":…}` event, return `success`, and set it to False when the event is missing. Add a truncated-log fixture.

**P2-9 CI and Robot defaults still point at MinIO, which D-008 has since dropped.** The Orchestrator amended D-008 after the worker's commit: LocalStack (`localstack/localstack`, port 4566) replaces MinIO, because the `minio/minio` images were removed. - `S3_ENDPOINT_URL: http://localhost:9000` and the `minioadmin` keys in ci.yml.
- `${PUBLIC_BASE}` defaults to `http://localhost:9000/public-pages` in common.resource.
- The test name "Page Is Served From MinIO With The Backend Down" in page.robot.

*Fix:* run LocalStack as a normal service container (no custom command needed): `localstack/localstack:<pinned tag>`, `ports: ["4566:4566"]`, env `SERVICES=s3`, health check `curl -sf localhost:4566/_localstack/health`.

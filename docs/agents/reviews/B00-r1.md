## What is right (checked, no action)

- **Presign.** It signs against `S3_PUBLIC_ENDPOINT`, while the API and worker use the client on
  `S3_ENDPOINT`. `Content-Type` and `x-amz-checksum-sha256` are signed headers, so on AWS a missing header
  or a changed one fails the signature, and a body mismatch fails the checksum. Expiry is 900 s. No
  `x-amz-sdk-checksum-algorithm`/CRC32 noise leaks into the query.
- **ids.** UUIDv7 comes from `uuid6` (Python 3.12 has no `uuid.uuid7`) and is monotonic in-process; the
  test covers 1,000 values. The Crockford alphabet `0123456789ABCDEFGHJKMNPQRSTVWXYZ` has 32 symbols and
  excludes I, L, O and U. `batch_code` is 60 bits from `secrets`.
- **Error registry.** It registers itself through `__init_subclass__` and refuses duplicates at import.
  A module can add codes by subclassing `AppError` in its own file, with no edit to core.
  `gen-error-codes.py` walks every package, so module codes reach the doc. A raised but unregistered
  `*Error` fails the script.
- **Import-linter.** The contract encodes D-004 the strict way: only `*.models` and `*.service` edges
  are ignored, so router, schemas, tasks and any other submodule (`geo.py` included) are forbidden. Probes
  above. "core never imports modules" is a separate forbidden contract.
- **alembic/env.py.** It is async, pins `search_path` to `public`, uses all three GeoAlchemy2 hooks and
  disposes the engine.
- **Celery.** `autodiscover_tasks` over `modules/*`, `worker_process_init` clears the cached engine, and
  the D-009 comment states the per-task `asyncio.run` caveat (already in TODO.md).
- **Brotli** (gzip fallback) works.
- **Dockerfile.** uv is pinned at 0.12.1, `--frozen --no-dev`, the dependency layer is built before the
  code is copied, it runs as non-root uid 10001, and `.dockerignore` drops `.env` and tests.
- **Compose.** LocalStack is pinned at `4.14.0`, Valkey has a `valkey-cli ping` healthcheck, every host
  port can be overridden, and api/worker wait for `s3-init: service_completed_successfully`.
  `s3-init.sh` enables object lock **at bucket creation** (`--object-lock-enabled-for-bucket`), turns on
  versioning, sets default GOVERNANCE retention of 1 day, skips buckets that already exist, and its `put-*`
  calls are idempotent.
- **`.env.example`** lists all 14 `Settings` fields.
- **Makefile** has every target in CLAUDE.md §8 (up, down, test, openapi, clients, seed), plus logs,
  test-unit, lint, progress and error-codes.
- **conventions.md** matches plan §13: C1 brotli, C4 cursor pages and `?fields=`, A4 256 KB / 50 entries
  (documented as B06's enforcement), and D-020 `/v1` with additive-only changes and oasdiff.

### P2 (fix before or with the named WP; not blocking B00)

**P2-1: Insecure defaults: the dev OTP and the dev JWT secret are code defaults, and the prod guard only
catches the literal dev secret.** `core/config.py:22,43-45,58`.
- *What it does:* `env` defaults to `dev`, `otp_dev_code` defaults to `"123456"` and `jwt_secret` defaults
  to `dev-only-change-me`. The validator rejects only `ENV=prod` combined with that exact secret or with a
  non-empty OTP code.
- *What goes wrong:* a production deploy that forgets `ENV=prod` starts silently with OTP `123456` accepted
  for every phone (once B02 reads it) and a public signing key, which means account takeover.
  `Settings(env="prod", jwt_secret="")` and `jwt_secret="a"` are both accepted (probe above).
- *Fix:* have no dangerous defaults. Make `jwt_secret` required (no default) and default `otp_dev_code` to
  `None`. Compose `x-app-env`, `.env.example` and `conftest.py` already set both values explicitly, so
  developers notice nothing. In prod, also require `len(jwt_secret) >= 32`. Extend `test_prod_refuses_dev_secrets`.
- *If skipped:* the auth bypass is dormant until B02 and live after it. It must not reach B02's merge.

**P2-2: `/v1/healthz` returns raw exception text to anonymous callers.** `main.py:69`.
- *What it does:* returns `f"error: {str(e)}"`. The worker's own round-2 run leaked
  `role "agritrace" does not exist`. Other asyncpg, redis and botocore messages carry host names, IPs and
  bucket names.
- *What goes wrong:* this is information disclosure on a public, unauthenticated route that every phone hits.
- *Fix:* return `f"error: {type(e).__name__}"` (and `TimeoutError` for timeouts) and `log.warning` the
  full text. Update the `Health` field descriptions and the unit-test expectation
  (`"error: ConnectionError"`).
- *If skipped:* SEC review will raise it, and internal topology is exposed in prod.

**P2-3: The HEAD reachability probe runs the full deep check.** `main.py:146-154`.
- *What it does:* HEAD and GET share `healthz`, so every phone's pre-sync probe (plan §13 A1, 3 s timeout)
  opens a DB connection, a **new** Redis connection pool (`Redis.from_url` per call) and an S3 HEAD, each
  with a 3 s timeout.
- *What goes wrong:* (a) if S3 is slow or down, the probe takes about 3 s or returns 503, so phones treat
  themselves as offline and stop pushing entries, which do not need S3 at all. (b) Each phone probe costs
  three backend round-trips on an unauthenticated route, which amplifies load.
- *Fix:* let HEAD answer 200 with no probes ("the API is reachable"), and keep the deep check on GET for
  compose and the load balancer. One small handler. Keep the separate HEAD route so operation ids stay
  unique.
- *If skipped:* an S3 incident becomes a sync outage for every phone, and M02 will build its reachability
  logic on the wrong semantics.

**P2-4: The boto3 client keeps botocore's 60 s read timeout and legacy retries (5 attempts).** `core/storage.py:41`.
- *What it does:* sets `connect_timeout=3` only (probe: `read_timeout: 60`, `retries: legacy`).
- *What goes wrong:* `_ping_s3` runs in `asyncio.to_thread`. `wait_for` abandons it after 3 s, but the
  thread stays blocked for up to 60 s × retries. Under P2-3's probe traffic, a hanging S3 fills the
  default executor, and every other `to_thread` call (B06 presign/head) queues behind it.
- *Fix:* `Config(..., connect_timeout=3, read_timeout=10, retries={"max_attempts": 2, "mode": "standard"})`.
- *If skipped:* an S3 hang stalls the API's thread pool.

**P2-5: The D-004 independence contract lists the 11 modules by name, so a new module escapes it.** `pyproject.toml:107-119`.
- *What it does:* `modules = [identity, …, reporting]`.
- *What goes wrong:* a module added later (B13's masters/config/imports work is the likely first) is
  outside the contract. The probe shows `masters.service -> registry.schemas` is not reported, and nothing
  fails to warn anyone.
- *Fix:* `modules = ["agritrace.modules.*"]`. Verified on import-linter 2.15: it catches both the new
  module and the existing ones.
- *If skipped:* D-004 erodes without anyone noticing.

**P2-6: The local S3 never checks presigned signatures, so the tests cannot prove that the checksum and
Content-Type are bound.** `infra/docker-compose.yml:61-64`, `tests/conftest.py:46`, `tests/integration/test_storage.py`.
- *What it does:* LocalStack skips presigned-URL signature validation by default
  (`S3_SKIP_SIGNATURE_VALIDATION=1`). `test_storage` only sends the right headers with wrong bytes, which
  the checksum check catches without any signature check.
- *What goes wrong:* a client that **omits** `x-amz-checksum-sha256`, or sends another Content-Type, is
  accepted locally but rejected on AWS. B06/M02 could ship a phone uploader that only works locally, and
  the D-011 integrity guarantee goes untested.
- *Fix:* set `S3_SKIP_SIGNATURE_VALIDATION: "0"` on the compose `s3` service and
  `.with_env("S3_SKIP_SIGNATURE_VALIDATION", "0")` on the LocalStackContainer (keys stay `test`/`test`).
  Add two assertions to `test_storage`: a PUT without the checksum header and a PUT with
  `Content-Type: image/png` both give 403.
- *If skipped:* the presign contract is verified only in production.

### P3 (follow-ups; Orchestrator may route to TODO.md)

- **P3-1: The envelope handlers lose headers and mislabel unregistered statuses.** `core/errors.py:199-211`.
  - `_http_error` drops `exc.headers`, so 405 has no `Allow` (RFC 9110 requires it) and 401 has no
    `WWW-Authenticate`.
  - A status without a registered code (400, 413, 415) becomes `internal_error` / "Something went wrong on
    the server." with that status (413 probe above).
  - `AppError` cannot set headers at all, yet `rate_limited`'s fix line promises `Retry-After`.
  - Fix:
    1. Pass `headers=getattr(exc, "headers", None)` through `_envelope`.
    2. Give `AppError.__init__` an optional `headers`.
    3. Have B06 register `payload_too_large` (413) for the A4 256 KB limit, and B02 use `headers` for
       `Retry-After`.
  - If skipped: B02 and B06 each patch core separately, and the mobile retry policy (A6) gets no
    `Retry-After`.
- **P3-2: `gen-error-codes.py` has no check mode.** `--check` is silently ignored and the doc is rewritten.
  CI can only catch drift with `git diff --exit-code docs/api/error-codes.md`. Either add `--check`
  (compare instead of write, exit 1 on difference) or document the git-diff step in the CI job.
- **P3-3: `lot_code`/`superlot_code` have 32 random bits and nothing tells callers about collisions.**
  `core/ids.py:26-50`. The birthday bound is about 1 % at 10k lots. The format is fixed by plan §7.1, so add
  `# shortcut: 32-bit random code; callers insert under a UNIQUE constraint and retry on conflict` and say
  the same in the docstrings. B01 adds the unique index and B09 the retry.
- **P3-4: `presign_put` does not check its input.** It accepts any even-length hex (the probe shows a
  1-byte "digest" signed), and the size is not bound. Check `len(sha256) == 64` (ValueError, as
  documented). B06's request schema must also cap the declared size, and `photos/confirm` must check
  `ContentLength`, because a presigned PUT cannot limit size and the bytes land in an object-locked bucket.
- **P3-5: S3 credentials are always passed explicitly** (`"test"` defaults, `core/storage.py:38-39`). This
  contradicts `.env.example` ("an IAM role in production"): an explicit key overrides the instance role.
  Make `s3_access_key`/`s3_secret_key` `str | None = None` and pass them only when set (compose and
  `.env.example` already set `test`). Before the first prod deploy.
- **P3-6: Router discovery does not enforce module tags.** The probe shows the tag only because the probe
  router set it. Write the rule in conventions.md: each module's router sets `tags=["<module>"]` matching

  them.
- **P3-7: Compose hygiene.**

## LocalStack recommendation (for the Orchestrator)

Keep `localstack/localstack:4.14.0` pinned for dev and CI now, record the pin and its revisit trigger in
D-008, and do not move to `latest` with an auth token. A token makes every developer and CI runner depend
on a LocalStack account, and the free tier's terms need checking for a commercial product.

The frozen pin is the best fit for what we need today:
- It is a dedicated AWS emulator.
- boto3 presigned PUTs with `x-amz-checksum-sha256` work against it (with P2-6's
  `S3_SKIP_SIGNATURE_VALIDATION=0` it also validates the signature).
- It supports versioning and object lock.
- testcontainers ships a module for it.
- Missing security fixes matter little for a dev-only container that is not exposed.

Its real costs are the image size (about 1 GB, which matters on this disk-starved machine) and that it
will slowly diverge from AWS. If the Verifier's `test_storage` run shows that 4.14.0 does not enforce the
checksum or object lock, or if image size becomes the blocker, switch to **SeaweedFS** (Apache-2.0, Go,
small image, long-maintained). Its S3 gateway documents versioning, object lock (enabled at bucket
creation), retention and legal hold, and it validates flexible checksums. I found no documentation
confirming SHA-256 checksum enforcement on presigned PUTs, so the same `test_storage` assertions must
pass first. **RustFS** (Apache-2.0) is the weaker fallback: it reached 1.0 GA only in September 2026, and
an object-lock enforcement CVE (CVE-2026-73288) was fixed as late as rc.1.

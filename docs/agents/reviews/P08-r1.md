## What this change does

It adds `/uploads` with Farmers / Villages / Inputs tabs. Each tab fetches B13's template
(`GET /v1/imports/{kind}/template.csv`, `parseAs: 'text'`), offers it as a `data:` download, and lists its columns
with the en label and "Required" from `/v1/config/fields`. A native file input reads the picked file once
(SHA-256 with SubtleCrypto, parse with an in-house reader), posts it with `dry_run=true`, and shows every row (100
per page) with the server's rejected rows tinted red, labelled "Rejected <code> in <column>: <message>", and the
bad column outlined. Confirm re-reads the file, refuses if the hash changed, and posts the same bytes with
`dry_run=false`. The commit report replaces the preview counts; after a farmers import a Members link appears.
MSW handlers mock field config, templates and imports.

## Correctness

**CSV reader (D-044 → D-047).** Differential run of a verbatim copy of `parseCsv` against Python 3 `csv.DictReader`
with the server's post-processing. Same row numbers and cells for: LF; CRLF; BOM (TextDecoder strips it like
`utf-8-sig`); quoted commas; quoted LF and quoted CRLF line breaks (number = end line, like `line_num`); doubled
quotes; a quote inside an unquoted cell (`ab"c`); text after a closing quote (`"ab"c`); a space before a quote;
blank lines in the middle and at the end; trailing newline or none; unterminated quote at EOF; `"",""` and `""""`;
`,` rows. Differences, all refused by the server so the preview never shows them: bare-CR line endings and a bare
CR inside an unquoted cell (Python raises `csv.Error`), blank lines before the header (server: "no header").

The in-repo test (`imports.test.tsx:198`) pins quoted line breaks, blank lines, escaped quotes, CRLF and a trailing
blank column. It does not pin BOM or LF-only, but the page tests use CRLF and LF files and TextDecoder handles the BOM.

Is a 30-line reader the smallest honest choice? Yes. B13's report carries only `{row, code, field}`; the red-row
preview the acceptance line asks for needs the cells, and returning them from the server would echo raw phones
(the ADR's reason). papaparse reports record indices, not physical end lines, so it would need the same counting.

**Hash check.** Confirm calls `readCsvFile(picked)` again, compares the hex SHA-256, and throws `FileChangedError`
before any request (`MasterDataPage.tsx:171-176`; test `:137`). The bytes sent are the bytes hashed (`new Blob([bytes])`).
`ImportPanel` is keyed by kind, so a check made on one tab cannot be confirmed on another. The hash is a UX guarantee,
not a security control: the server re-validates the commit from scratch under the caller's own FPO scope, and the
commit report (not the dry-run one) is what is shown afterwards. Mutations do not retry (TanStack default; the
client's retry policy covers queries only), so a timed-out commit is not re-sent.

**Paging.** 100 rows per page, pagination only above 100 rows (test `:185`, page 2 starts at row 102).
Rejected rows on later pages have no pointer (skipped, TODO.md:250). See P3-4.

**Members link.** Shown only for farmers after a commit; test clicks it and finds the imported farmer.

## Findings

### P2-1 Villages tab shown to every admin; the skip reason is wrong
- **Where:** `apps/portal/src/features/imports/MasterDataPage.tsx:122` (tab list); `TODO.md:249`; `apps/portal/src/mocks/handlers.ts:105` ("not a role in the token"), `:543`.
- **What happens:** An FPO admin opens Villages, fills a file, uploads it, and only then reads "Your role does not allow this action." TODO.md:249 says the flag is not in the session, but `SessionOut.roles` includes `super_admin` (`identity/service.py:325`).
- **Fix:** In `MasterDataPage` take `const { session } = useAuth();` and render
  `(Object.keys(KINDS) as Kind[]).filter((k) => k !== 'villages' || session?.roles.includes('super_admin'))`.
  In the mock, `roles: [...mockState.roles, ...(mockState.superAdmin ? ['super_admin'] : [])]` (SessionOut.roles is `string[]`), and fix the comment at `:105`.
  Change test `:146` to "hides the Villages tab unless the caller is a super-admin" (`queryByRole('tab', { name: 'Villages' })` is null); keep `:153` for the super-admin path.
  Delete TODO.md:249. Keep the `forbidden` message path: the server stays the judge (a revoked flag before token refresh).
- **If skipped:** Every FPO admin sees a tab they can never use and finds out only after preparing a file.

### P3-2 New file picked while a commit is in flight
`MasterDataPage.tsx:237-250`: the file input stays enabled during `commit.isPending`. Picking another file calls
`commit.reset()`, which detaches the UI from the running import; the old file is still committed on the server but its
report is never shown, and the screen now previews the new file. Fix: `disabled={commit.isPending}` on the `<input>`.

### P3-3 Bare-CR CSV gives a 500 (B13 follow-up, outside P08 paths)
Python's `csv` raises `csv.Error` on CR-only line endings (Excel for Mac "CSV (Macintosh)" still writes them);
`imports.parse_csv` does not catch it, so `_unhandled` returns `internal_error` and the portal shows the generic
message. Add a TODO line for B13: catch `csv.Error` in `parse_csv` and raise `ValidationFailedError(details={"file": "save as CSV UTF-8 (comma delimited)"})`
(or read with `io.StringIO(text, newline=None)`, which also accepts CR). The portal already prints the `details.file` hint.

### P3-4 Rejected rows are hard to find in a long file
Skipped and logged (TODO.md:250). Cheapest step that removes most of the pain, if the Orchestrator wants it in r2:
append the rejected row numbers to the status line (`report.rejected.map((r) => r.row).join(', ')`, capped at ~20).
Not required for acceptance.

### P3-5 Non-admin roles see the page and get `forbidden` on upload
`navigation.ts:26` and the route are open to every signed-in role; farmers/inputs imports need `fpo_admin`. Same
pattern as P2-1: if the session lacks `fpo_admin`, show an info Alert instead of the file input. Add a TODO line if
deferred (P07 e2e signs in as admin only).

### P3-6 Template acceptance test is mock against mock
`imports.test.tsx:80` compares the MSW template with the `MOCK_FIELDS` it is built from. State in the test header
that the YAML parity is B13's server test and the live check is the Verifier's, so nobody reads it as proof.

### P3-7 "Import 1 rows" / "1 rows imported."
`MasterDataPage.tsx:278,282` (and the status line). Use `row${n === 1 ? '' : 's'}`; update the two test strings.

### P3-8 Mock `/v1/me` hard-codes `is_super_admin: false`
`handlers.ts:828`: return `mockState.superAdmin` so the mock tells one story (pairs with P2-1).

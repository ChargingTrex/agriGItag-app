# M12 review, round 1: Notifications + deep links

Reviewer: MOB Reviewer, privacy lens (Opus), 2026-10-31. Branch `worktree-agent-aa8b2d0f10b9d2730` at 6dd159f, diffed
against `git merge-base main HEAD` = 7681f7f. 25 files, +1091 / -10. I did not change any code or tests.

## Verdict: **FAIL** (1 P1, 1 P2, 9 P3)

The design is small and sound:

- One local notification per open task, built only from l10n strings and a plot index.
- The payload is `/log/<event>?lot=<id>` and nothing else.
- Runs are serialized, and each run starts with `cancelAll`.
- Only the farmer role gets reminders, so sign-out cancels everything.
- The push work is a seam with no Firebase.
- Every gate is green on a full run (672 tests).

Two things block the PASS:

- **P1:** the ledger records `desugar_jdk_libs` as Apache-2.0. Its real licence is GPL-2.0 with the Classpath
  Exception. D-018 rejects GPL for linked libraries, and this library is linked into the APK. The code needs no change.
  The ledger row needs fixing, and the Architect-Gate must rule on the licence.
- **P2:** on Android 8–12 (most of the pilot's phones), a farmer who answers **No** to "Allow reminders?" still gets
  every reminder.

Both fixes are small. Round 2 should take under an hour, plus the Architect-Gate's ruling.

## Findings

### P1

**P1-1: `desugar_jdk_libs` is GPL-2.0 with the Classpath Exception, not Apache-2.0. D-018 has no rule that accepts
it.** `docs/LIBRARIES.md:138`, `apps/mobile/android/app/build.gradle.kts:53-56`.

- **The facts:** the Maven POM of `com.android.tools:desugar_jdk_libs:2.1.4`, fetched from dl.google.com during this
  review, says:
  `<name>GNU General Public License, version 2, with the Classpath Exception</name>`.
  The library is a subset of OpenJDK. With `isCoreLibraryDesugaringEnabled = true`, AGP dexes it into the APK (as L8
  output), so it ships to every phone.
- **The rule:** the LIBRARIES.md header and D-018 accept MIT, BSD, Apache-2.0 and ISC, plus an MPL-2.0 amendment. They
  reject GPL, AGPL and LGPL for linked libraries. psycopg was refused for being LGPL.
- **The ledger:** the flutter_local_notifications row says "desugar_jdk_libs:2.1.4, Apache-2.0". That is wrong.
  `libraries-check.py` passes only because it does not read Gradle dependencies.
- **No way around it:** flutter_local_notifications 10+ needs desugaring even without scheduling (its README, and its
  AAR metadata turns AGP's check on). `minSdk 26` does not avoid it.
- **Fix (no code change):**
  1. Give `desugar_jdk_libs` its own row in `docs/LIBRARIES.md`:
     - Version: `2.1.4`
     - Licence: `GPL-2.0-only WITH Classpath-exception-2.0`
     - Used in: `apps/mobile/android/app/build.gradle.kts`
     - What for: java.time backport that flutter_local_notifications needs
     - Why this one: required by the plugin
     - Alternative rejected: no reminders plugin, or own platform channels
  2. Remove "Apache-2.0" from line 138.
  3. Ask the Architect-Gate for a D-018 amendment, for example: "GPL-2.0 with the Classpath Exception is accepted for
     unmodified JDK/Android runtime libraries that the build toolchain links. The exception allows linking independent
     modules on any terms." This mirrors the MPL amendment. Record it in DECISIONS.md and add a TODO line until it is
     signed.
  4. If the Architect-Gate refuses, the only options are dropping flutter_local_notifications or writing the
     AlarmManager and UNUserNotificationCenter channels by hand (D-046 alternative 3).
- **If skipped:** a licence the project's own policy rejects ships in the APK, and the ledger hides it from any
  licence audit.

### P2

**P2-1: On Android 8–12, "No" to "Allow reminders?" changes nothing. The reminders still ring.**
`apps/mobile/lib/features/notifications/reminders.dart:146-149`, `startReminders` :229. The test
`test/notifications/reminders_test.dart:352-362` asserts this behaviour ("scheduled anyway; the phone decides whether it
shows").

- **What happens:**
  1. On No, `askReminderPermission` stores `reminders_permission_asked = no` and skips the platform request.
  2. `run()` keeps scheduling, because `remindersOnProvider` is still true.
  3. Below Android 13 no permission is needed, so every reminder appears.
  4. On Android 13+ and iOS the reminders stay silent, but Settings still shows **Reminders: on**.
- **The case:** a farmer on an Android 11 phone (the Go profile in PLAN §13) says No and gets "Time to log: Drying"
  seven days later anyway.
- **Root cause:** the rationale and the Settings switch are two separate states. The rationale's answer is never applied
  to the switch.
- **Fix (about 6 lines plus a test change):**
  - On No, also store the switch off: `await db.syncStateDao.set(remindersKey, 'off')`. Then `invalidate` the switch
    provider, either by passing the container or `ref` in, or by having `run()` read the key directly. The next run then
    cancels everything, and Settings shows the truth.
  - In `RemindersOn.set(true)`, when `permissionAskedKey` is `no`, make the same two platform requests as the Yes path.
    A farmer who turns reminders back on then gets the Android 13+ / iOS prompt.
  - Change the "No is remembered" test to expect `scheduled` empty and the switch `off`.
- **If skipped:** the app ignores the farmer's explicit "No" on most pilot phones. The phone and the Settings screen
  disagree on every OS.

### P3

**P3-1: Shared phone: farmer B gets farmer A's reminders after a user switch.** `reminders.dart:103` reads
`tasksDao.watchOpen()`, which returns every open task on the phone, with no owner filter.

- **What works:** sign-out *does* cancel everything. The role becomes null, `run()` passes `on: false`, and `cancelAll`
  runs.
- **The gap:** the next farmer's sign-in schedules every open task left on the phone. That includes A's local drying
  task, because M07 writes it and the D-029 reset keeps it. A tap preselects A's lot for B, and the server rejects the
  entry on scope.
- **Root cause:** this is TODO §4 "M02/M06 (M08-r1 P2-2, H-2)" at `TODO.md:149`. The same rows already reach the home
  task card through `nextTaskProvider`. The phone has no local "signed-in farmer id": the pull does not write
  `Farmers`, and `Session` holds only `userId`. So M12 cannot filter correctly by itself.
- **Privacy:** no phone number, name or ID document reaches the lock screen, only "Time to log: Drying / Field 2".
- **Fix:**
  - Add "M12 reminders (`watchOpen`)" to the TODO line at :149.
  - Add one compromise bullet to D-046 ("tasks are not filtered by owner until the session carries the farmer id").
  - When that TODO lands, filter `watchOpen` by the farmer id.

**P3-2: Any Tasks change, or simply opening the app, wipes reminders already shown in the tray.** `reminders.dart:89`.

- **Cause:** `cancelAll()` also removes notifications already presented. Its own doc says "scheduled and those that
  have already been presented".
- **The case:** the harvest reminder rings at 08:00 and the farmer has not tapped it. They open the app from the
  launcher, or log another event. The first run removes the shown reminder. Its due time has passed, so it is never
  scheduled again.
- **Fix:** `on ? plugin.cancelAllPendingNotifications() : plugin.cancelAll()`. Sign-out and the switch still clear the
  tray, which shared phones need.

**P3-3: One failed `zonedSchedule` drops every later reminder until the next change.** `reminders.dart:107,113`.

- **Cause:** the plugin throws `ArgumentError` when `scheduledDate` is before `clock.now()` (`helpers.dart:15`). `now`
  is read once before the loop, so a task due within that window throws after `cancelAll` has already run. The queue's
  `catchError` logs the error, and the tasks after it are never scheduled.
- **Fix:** skip with a margin: `!at.isAfter(now.add(const Duration(minutes: 1)))`.

**P3-4: The cold-start test is a warm start with launch details, and it does not assert that home is underneath.**
`reminders_test.dart:384-398`.

- **Cause:** `startApp` pumps the whole app before calling `startReminders`. In `bootstrap.dart:81` it runs straight
  after `runApp`, maybe before the Router is mounted.
- **Why it matters:** `openReminder` relies on `go('/home')` being applied synchronously before
  `push(payload)` reads `routerDelegate.currentConfiguration` (go_router 17.5.0, `router.dart:448-454`). Before the first
  frame, the push base may be empty, which leaves `/log/harvest` alone with nothing to go Back to.
- **Fix:**
  - Add `expect(h.container.read(routerProvider).canPop(), isTrue)` to the cold-start test.
  - Mark "tap from a killed app, then Back returns home" as a Q01 device check (already in the TODO device line; add
    "Back returns home").
- **Session race:** none. `bootstrap` awaits `restore()` before `runApp`, so the role is known when the redirect runs.

**P3-5: The OS permission can be denied (Yes, then Deny, or revoked later) while Settings still shows on.**

- **Fix:** add a TODO line now. Later, Settings can read
  `AndroidFlutterLocalNotificationsPlugin.areNotificationsEnabled()`, show "Reminders are blocked by the phone", and
  open the OS settings. This is not needed for the pilot once P2-1 is fixed.

**P3-6: Settings shows the "Reminders" switch to officers and QC, where it does nothing.**
`settings_screen.dart:122-134`.

- **Cause:** the role gate is at :229 of reminders.dart, so for other roles the switch has no effect.
- **Fix:** wrap the tile and its gap in `if (ref.watch(sessionProvider).role == Role.farmer)`. Settings already serves
  every role.

**P3-7: The sign-out cancellation has no test.** The shared-phone safety depends on it.

- **Fix:** one app test: a task is scheduled, sign-out (or setting the session role to null) runs, and `scheduled` is
  empty.

**P3-8: The privacy scan seeds only a Latin-script name and village.** `reminders_test.dart:118-150,248`.

- **Coverage:** the scan already covers both locales and the lot label ("Field n" / "வயல் n"). The text cannot contain
  a name, because it is built from l10n strings and a plot index.
- **Fix:** add `name_local: 'முருகன்'` to the farmer JSON, and add `'முருகன்'` to the secrets list, so a future body
  built from `name_local` fails the test.

**P3-9: The local drying reminder rings at the time of day the drying start was saved, which can be 22:00.**
`event_log_controller.dart:545` writes `now + 7 days`, so the 07:00 rule (date-only tasks) never applies to it.

- **Fix (optional, product call):** M07 stores the due *day* (local midnight) for the drying task, and M12's 07:00 rule
  then covers it. Otherwise accept and note it in D-046.

### Accepted (no finding)

- **Rationale and switch per phone, not per user** (D-046 compromise). This is fine on shared phones once P2-1 ties
  them together.
- **No debounce on a Tasks burst.** N emissions give N sequential runs, and each run does cancel-then-schedule with ids
  0..n-1. Runs are serialized by the `queue` chain, so nothing double-fires. A few dozen plugin calls is fine for a
  farmer's handful of tasks.
- **07:00 in the device's zone.** `dueDate.toLocal()` turns midnight into 07:00 local. The instant goes to the plugin
  in a fixed `UTC` location, and both Android's `ZoneId.of("UTC")` and iOS's `TimeZone("UTC")` accept it. A future
  server date-only task parsed as UTC midnight would land at 05:30 IST and not get the 07:00 rule. Today nothing writes
  server tasks (TODO lines exist). Whoever implements that pull must parse `due_on` as a local date.
- **The push seam is 25 lines with `shortcut:` comments**, as PLAN §7.2 M12 names FCM/APNs. It reads
  `features.push_notifications` from the top level of the `fields` part. That matches `fieldconfig.bundle_part`, which
  returns `{version, entities, features}`. Absent or non-bool means off. A non-JSON stored bundle throws
  `FormatException` into the crash hooks, unawaited, and does not break start-up.
- **Assist scope (M10):** the role gate means an officer's phone never schedules reminders, even for the drying tasks
  it writes while assisting. On main, `/log` is farmer-only (`allowedPrefixes`), so a stray reminder tap on an officer
  phone redirects to `/officer`. It can never enter `/assist/:farmerId`. A farmer phone never assists.
- **M08 Wi-Fi switch test narrowing** (`m08_screens_test.dart:228-229`) is legitimate. `find.byType(SwitchListTile)`
  now matches two tiles. Selecting by the tile's text keeps every assertion unchanged.
- **Android setup:** this matches the 22.3.3 README for `build.gradle.kts`:
  - `RECEIVE_BOOT_COMPLETED`
  - `ScheduledNotificationReceiver`
  - `ScheduledNotificationBootReceiver` with BOOT / MY_PACKAGE_REPLACED / QUICKBOOT
  - `isCoreLibraryDesugaringEnabled` and `desugar_jdk_libs:2.1.4`

  AGP 8.11.1, plugin minSdk 24, app 26. The plugin merges `POST_NOTIFICATIONS`. The inexact mode means no
  `SCHEDULE_EXACT_ALARM`.
- **iOS:** the `UNUserNotificationCenter.current().delegate = self as? UNUserNotificationCenterDelegate` line matches
  the README (iOS 13+ min, so no `#available`). Not compiled here. Q01 should also check a tap while the workmanager
  headless engine is alive, because it registers the plugin a second time through `GeneratedPluginRegistrant`.
- **Size (note for M13 / BM-04):** flutter_local_notifications' Android code is small. The desugared L8 dex is shrunk
  by R8. `timezone` loads no tz database (only `timezone.dart` is imported, not `data/latest*.dart`). I estimate
  ≤ 0.5 MB on the arm64 APK. Not measured: no `flutter build apk --analyze-size` run here.
- **Calendar source:** the M12 row says "from calendar bundle". The `calendar` part is empty and has no ids (B07), and
  the worker filed TODO lines. Reminders follow automatically once the part is mirrored into Tasks. Accepted.

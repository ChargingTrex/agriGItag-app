## 3. Judgement on the brief's questions

- **The linter change stays inside the coordinate rule.** The diff touches only `SEP`, two new fragments and the `coordinate_precision` alternatives. Phone, Aadhaar, survey and polygon logic is untouched.
  - The 90-probe and old-fixture comparisons above show no lost or changed hit.
  - The new `SEP` (bare `\s+`) and the no-`\b` key rule add three fail-closed false positives (P3-2). None of them appears on the built page or in the 90 probes.
- **canaries.json covers all six cases.** It has phone, Aadhaar, survey (`S.F. No.`), 6-dp lat and lon as separate entries, and the temp path, each with a plant path and the expected outcome.
  - The lat/lon canaries do work that no regex can do. My template copy printing `9.536271` alone gets 0 hits without canaries and 1 with them.
- **Coarsening the pin instead of rejecting it is acceptable.** `GeoPoint._coarsen` rounds the pin to 3 dp at the trust boundary (D-017 marker, W01), so `map_link` and `data.json` only ever see 3 dp.
  - Rejecting the pin would make every B10 publish fail, because the builder sends the real pin and the page needs a map link (plan §7.1, "map link 3 dp").
  - The pytest case checks that the canary is in neither `index.html` nor `data.json`.
- **The html-validate config is sensible.** It extends `standard` + `a11y`, with only `no-inline-style` turned off. The page is deliberately inline (D-007). Rejecting `recommended` is justified: it reports the valid lower-case doctype as an error.
  - Side note: run on a file outside `apps/public-page`, html-validate finds no config and falls back to `recommended`, so it reports `doctype-style`. CI and Robot run it from inside the app, so this does not affect them.
- **The Lighthouse configs follow D-025.**
  - 3G is the built-in `mobileRegular3G` values (verified in lantern's `Constants.js`).
  - 4G uses `normal_4g` from `profiles.yaml` (60 ms, 10 000 kbit/s).
  - Both use `simulate` and 3 runs with `aggregationMethod: median`.
  - 3G asserts perf ≥ 0.9, bytes ≤ 500 000 and LCP ≤ 2000. 4G asserts LCP ≤ 2500 and bytes ≤ 102 400.
  - 4G has no perf assertion, which matches BM-16. The marker cites D-007 rather than D-025 (P3-1).
- **YAML instead of JSON is justified.** CLAUDE.md §5 requires a header comment, and JSON cannot hold one. lhci reads YAML natively, and `--config` is explicit in every caller.
- **The Robot tests are real.**
  - Expected values come from the fixture (the bilingual `<h1>`) or from the parsed page (units, date order, evidence URLs).
  - The injected-phone test checks rc 1, both rule names, and that the number is not echoed.

  - One caveat: the skip also fires when `npm ci` was not run, so a Verifier must not count a SKIP as BM-03 evidence (P3-8).

### P2 (fix before G1 or file in TODO with an owner)

**P2-1. Hemisphere letters without a degree sign, and semicolon pairs, slip past both layers.** (`infra/scripts/privacy-lint.py` `SEP`/`coordinate_precision`; `apps/public-page/agritrace_page/schema.py` `_TEXT_PATTERNS["precise coordinates"]`)
- **What this is:**
  - The schema refuses precise comma pairs in free text.
  - The linter is the backstop on the built files.
  - Probes L25, L27, L28 and L31 slip past both:
    - `9.559806 N, 78.133521 E`;
    - `N 9.559806 E 78.133521` (Garmin-style);
    - `9.559806;78.133521`;
    - the standard `<meta name="geo.position" content="9.559806;78.133521">`.
- **Problem:** A farmer or officer who pastes a GPS-app reading into a free-text field that is shown on the page (`review_note`, an event `comment`) gets it published.
  - The canaries cannot help, because they only know the fixture's own pin.
  - W03 adds `<meta>` tags, where `geo.position` is a plausible addition.
  - This is not P1 for three reasons: the pin itself is coarsened in the schema; the most common copy-paste forms (Google comma pair, degree, DMS, OSM, `geo:`) are all caught; and these forms were outside Q00-1 and P2-3.
- **Fix:** Two lines in the linter, tested on a copy (`/tmp/w02rev/pl_cand.py`):
  ```
  SEP = r"(?:\s*(?:,|%2C|;|&nbsp;)\s*|\s+|\+|%20)"
  rf"|(?-i:\b[NS])\s*{PRECISE}|{PRECISE}\s*(?-i:[NS]\b)"      # after the {DEG} alternative
  ```
  - Result: all four are caught, the 90-probe set does not change, the G probes do not change, and the clean fixture stays at 0.
  - The `(?-i:…)` keeps `0.1234 s` (seconds) from matching.
  - Add one `LEAKS` row per form. Optionally mirror `;` in the schema's comma-pair pattern.
- **If we skip it:** A hand-typed GPS reading in the less common format goes onto a public page. File it in TODO for W02 r2 or W03 (before the OG/meta work).

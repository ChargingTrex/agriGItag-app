### Distinct root causes (one line each, with the tests it hits)

1. **B12 (seed), GI hold that never clears.** `test_reference_batch_flags_gates_fixes_and_publish` fails at `assert out["gi_verified"] is True` (tests/e2e/test_reference_batch.py:339). A scratch diagnostic plugin printed `gi_block_reasons = [lot_on_hold ×3, detail None]` after publish ([logs/12](B00/logs/12-e2e-reference-batch-showlocals.log)). Cause: `agritrace/seed/demo.py:482` builds `Lot(...)` without `gi_eligible`, so the model default `False` applies (`lots_batches/models.py:41`) with `gi_hold_reason=None`. `rules_flags.service.apply_hold` restores eligibility only when it owns a non-null reason (line 233), so nothing ever sets the lots back to eligible. The live compose DB shows the same state after `make seed`: 3 lots `gi_eligible=f`, reason NULL, no hold flags. The API path (`lots_batches/service.py:554`) sets `gi_eligible=True` explicitly.
2. **B13, stale migration head.** `test_migration_0003_applies_and_alembic_check_is_clean` fails with `assert '0003_masters' in '0004_lots_append_only (head)\n'` (test_config_imports.py:196). The test hard-codes the head, and B09 then added `0004`.
3. **B14, stale audit expectation.** `test_reject_pending_and_refuse_active` fails at test_registry_b14.py:101: the `farmer.reject` audit row is `{reason_code, reason_text, devices_revoked: 0, membership_removed: False}`, but the test expects only `{reason_code, reason_text}`. B14 round 2 (`352b61c`) added the two fields without updating this assertion.
4. **B00 harness (B00-2), env leak.** `test_prod_refuses_missing_or_console_sms_provider[None]` and `[console]` fail because `OTP_DEV_CODE=123456`, set by `stack`, reaches the prod validator: `ENV=prod requires JWT_SECRET of at least 32 bytes and no OTP_DEV_CODE`. They pass alone and fail with `OTP_DEV_CODE` set ([logs/13](B00/logs/13-env-leak-repro.log)).
5. **B00 harness (B00-1), load.** Not hit in the full run, but it hit all 11 B00 tests in run 1: `BucketAlreadyOwnedByYou` at tests/conftest.py:73. Under load, rerun 1 also hit test timeouts: the health probe's 3 s DB timeout and httpx's default 5 s timeout in test_storage.py.

## State found, and how the line was proved

The seeded batch FGP8T4033HM7 was `created`, not published, and I did not write to it. Batch X was published
through the API in [B09 part 2](B09/logs/03-live-b09-part2.log). Its **build 1 failed** with
`public_record_invalid` (409 code), and `GET /batches/{id}/builds` shows the field paths. The cause is that the B06
QA farmer has no address, so village/block/district/state are empty, and the plots had no `farming_type`. This is
the designed behaviour: the failure is visible to the admin and nothing is published silently.

I filled those fields through the API (`PATCH /farmers/{id}` with a village-level address, `POST /plots/{id}/correct`
with `farming_type`) and called `POST /batches/{id}/rebuild`. Builds 2 and 3 then built.

Observation (P3, B09/B10): `publish` answers 202 and sets the batch `published` even when the page cannot be built
from its data. Offline-onboarded farmers have no village picker (TODO M09), so this will happen in the pilot until
the admin fills the address. A pre-check in the publish gate, or a clear builds badge in P04, would help.

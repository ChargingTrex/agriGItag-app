## Cross-package contract (from P00)

The portal skeleton (P00) already codes against this auth contract; adopt it or document the difference in docs/api/conventions.md and tell the Orchestrator:
- `POST /v1/auth/otp/request` {phone} → 204 (429 on repeat within 60 s)
- `POST /v1/auth/otp/verify` {phone, code, device_id} → {access_token, refresh_token, expires_in, pin_required: bool, roles[]}; for field_officer / qc_officer / fpo_admin `pin_required=true` and a short-lived pre-PIN token
- `POST /v1/auth/pin/verify` {pin} → full tokens; 5 wrong PINs → 409 locked 5 min
- `POST /v1/auth/refresh`, `POST /v1/auth/logout`, `GET /v1/me`
- Never a code default for `OTP_DEV_CODE`; empty/None means off (B00 r2 P3-1).
- Web token storage: portal keeps tokens in sessionStorage (shortcut); decide whether to issue an httpOnly refresh cookie for the web client and record it as an ADR.

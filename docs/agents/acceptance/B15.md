## Outputs

1. **D-030, batch reconciliation split** (FR11, FR60, Dataflow Stages 7–8, PRD §12.2). `BatchContext` gains `received_kg`
   (`batches.total_received_kg`) and `grading_loss_warn_pct`. `_check_batch` reads the second from
   `fieldconfig.features_for(<FPO code>)`. `_batch` raises `batch_quantity_unattributed` (warn) when received kg exists
   and the shares are missing or Σ `kg_contributed` differs from it by more than 5 %. It raises `grading_loss_high`
   (warn) when the output (packed, else graded) is more than `grading_loss_warn_pct` below received kg, or more than
   5 % above it. Nothing is raised when received kg is missing. `CODES` lists both. The `shortcut:` comment citing
   P2-4 is replaced by a `DECISION D-030` block. `features.yaml` gets `grading_loss_warn_pct: 15` with a reader comment.
2. **D-031, offline farmer sync** (Stage 0, D-005, UserFlows §Onboarding). `FarmerIn.client_id: UUID | None` with a
   `description=`. `create_farmer` uses it as `farmers.id` and checks it first: an existing id in the same FPO →
   return the stored farmer (no phone check, no second user or membership); another FPO → `client_id_conflict`.
   `POST /v1/farmers` answers 200 with the stored farmer on a repeat and 201 on create (or 201 both times, documented).
   Push kind `farmer`: `data` = `FarmerIn`, entry `client_id` = farmer id, field officer / FPO admin only (others
   `forbidden`), committed per entry, `accepted` / `duplicate` / `rejected`. `X-Assist-Session` is neither required
   nor applied for this kind.
3. **D-032, per-entry assist context** (CLAUDE.md §6, FR41 consent witness, FR69, UserFlows §Onboarding step 2).
   Push kind `assist_session`: `data` = `AssistStartIn` without `client_id`, entry `client_id` = session id, handled
   by `identity.service.start_assist` unchanged (field officer only). `SyncEntry.assist_session_id: UUID | None` with a
   `description=`. When set, `push` resolves it for the caller (ended sessions allowed), and for that entry only
   replaces `on_behalf_of_farmer_id` / `assist_session_id` on the caller and in the audit context, restoring them
   afterwards. Unknown or another officer's session → that entry `rejected` `assist_session_invalid`. When absent,
   the header behaves as today. `create_plot` refuses (`forbidden`) a plot whose `farmer_id` differs from the caller's
   `on_behalf_of_farmer_id` in assist mode, the same as consent and events. The `farmer` kind ignores the field.

## Outputs

1. **D-040, QC intake by push** (Stage 7, FR9, FR43, User Flows §Selling, D-005, D-033).
   - `IntakeIn.processor_id: UUID | None` (description: "absent → the FPO's only own processor").
   - `create_intake` checks the role itself: QC officer or FPO admin, else `forbidden`; a correction
     (`supersedes_intake_id`) by anyone but an FPO admin → `forbidden`. Absent `processor_id`: the one processor with
     `fpo_id` = caller's FPO; zero or several → `field_required` naming `processor_id`. A first intake of an
     `open`/`drying` lot calls `mark_ready` first (same transaction); its `moisture_gate_failed` / `lot_status`
     refusal stands. All checks run before any row changes.
   - `create_intake_from_sync(session, user, data: dict)`: validates `IntakeIn` (422 `validation_error` with
     details, as `create_plot_from_sync`) and calls `create_intake`.
   - Push kind `lot_intake`: `data` = `IntakeIn` without `client_id`, entry `client_id` = intake id; the handler
     calls `create_intake_from_sync` and commits; `accepted` / `duplicate` / `rejected`; `server_id` = intake id.
   - `POST /v1/intakes` dependency: `require_role(Role.QC_OFFICER, Role.FPO_ADMIN)`; docstrings say "QC officer or
     FPO admin".
   - `IntakePayload` (event type `intake`) is documented as a timeline note that does not receive the lot
     ("use push kind `lot_intake` or `POST /v1/intakes`"). No behaviour change for that event type.
   - `DECISION D-040` at the handler and at the processor default.
2. **D-041, GI-only holds in non-GI batches** (FR29, FR68, FR70, Dataflow §4).
   - `GI_ONLY_HOLD_CODES = frozenset({"plot_outside_gi_region", "yield_over_ceiling"})` beside `hold_reasons`.
   - `hold_reasons(flags, gi_label_requested)` skips holds with those codes when `gi_label_requested` is false;
     `approve_grading`, `final_packing` and `publish` pass `batch.gi_label_requested`.
   - `_approval` records in `blocked_reasons` every active flag that did not block (warns, infos and, in a
     non-GI batch, the GI-only holds).
   - `_gi_check` is unchanged (a non-GI batch already skips it). `DECISION D-041` at `GI_ONLY_HOLD_CODES`.
3. **D-042, assist scope per kind** (CLAUDE.md §6, D-032).
   - `_entry_caller`: kinds `farmer`, `flag_resolution`, `assist_session`, `lot_intake` drop the assist context
     with no session lookup (extends the existing `farmer` line).
   - `quality.service.create_reading`: with `on_behalf_of_farmer_id` set, a lot reading whose lot belongs to
     another farmer, or any batch reading → `forbidden`.
   - `events._check_subject`: a batch event with `on_behalf_of_farmer_id` set → `forbidden`.
   - `SyncEntry.assist_session_id` description lists the four ignoring kinds. `DECISION D-042` in `_entry_caller`.
